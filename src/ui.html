추출 · 색 정리

비슷한 색은 추출 시 자동으로 대표 1색에 정리됩니다(드래프트 단계 — 바인딩 영향 없음). 역할(Semantic)을 정하세요. Global은 hue 패밀리(color/blue/500).

토큰 생성 (Global + Semantic)

색 외 토큰(간격·크기·폰트·효과)을 변수로 만듭니다. 색은 위 ‘색 정리’에서 다룹니다. 체크한 것만 생성되고, n×는 그 값을 쓰는 레이어 수입니다.

시맨틱 매핑 (역할 → 토큰)

다크 테마 생성

라이트 모드 색을 명도만 뒤집어 다크 모드를 채웁니다. 색상·채도는 그대로라 브랜드색이 유지돼요. Semantic이 Global을 가리키고 있는 것만 대상이고, 값을 직접 넣은 건 건너뜁니다. 다크용 원시색은 dark/…로 따로 만들어집니다. (Paid)

컴포넌트 / 베리언트

후보 스캔 → 골라 등록. 선택한 부모는 컨테이너(등록 제외). 고신뢰 구조(button·chip·table·card·list·field·nav·progress·figure·heading)인 보이는 FRAME/GROUP만 후보 — 이름과 무관, 숨김은 제외. heading은 섹션 머리줄(가로·낮은 높이·타이틀+선택 액션/메타)이며 페이지 header 랜드마크와 다름. 같은 레이어 이름이 2개+이면: 구조가 같고 텍스트/아이콘만 다르면 속성(단품+TEXT/스왑), heading의 액션(buttonGroup) 유무만 달라도 속성, 구조·크기·색이 다르면 세트. 이름이 다르면 각각 단독. 속성은 이름 어휘(Type·State·Size) 우선 + 기하 보완. 메인은 Components 페이지, 원위치엔 인스턴스.
베리언트 분류는 이미 만들어 둔 기존 컴포넌트를 같은 이름끼리 다시 묶을 때만(프레임은 「컴포넌트 등록」). 등록 시 TEXT·스왑·이름? BOOLEAN 속성이 자동 노출됩니다(접힘=다른 슬롯만, 단독·세트=전체 API).

닮은 프레임 컴포넌트화

구조가 같고 내용만 다른 프레임 여러 개를 골라 스캔하면, 하나를 마스터로 컴포넌트화하고 나머지는 인스턴스로 바꿉니다. 프레임마다 다른 텍스트·아이콘은 컴포넌트 속성으로 열리고, 이미지는 인스턴스에서 개별 교체됩니다. 마스터는 내용이 가장 잘 채워진 프레임을 추천합니다(빈 텍스트가 많으면 감점). 스캔은 무료, 실제 교체만 Paid.
