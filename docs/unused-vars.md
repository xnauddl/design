# 안 쓰는 변수 찾기 — 파일 전체 (2026-11-11)

> 대상: 변수 탭 ⋯ 메뉴의 새 항목 "안 쓰는 변수 찾기…"와 그 팝업. 화면 규칙은 `docs/ia-v4.md`(트리 §2.7 · 카드 · 띠 §2.8 · 변수 탭 §4.6 · 삭제 §4.9 · 유료 §6 · 다시 읽기 §7)를 따른다.
> 왜: 자동 만들기를 여러 번 돌리면 쓰이지 않는 변수가 남는다(예: 예전 실행의 `-2` · `-a8` 이름, 지운 레이어의 값). 지금은 변수마다 상세 팝업을 열어 "쓰인 곳"을 하나씩 봐야 한다. ROADMAP §9 "파일 전체 미사용 변수 찾기".
> 순서: 이 명세 → 코드 대조 검토 결함 0 → 화면 시안 → 구현(CLAUDE.md).

## 0. 결정 요약

| 항목 | 결정 |
|---|---|
| 들어가는 곳 | 변수 탭 [⋯] 메뉴 "안 쓰는 변수 찾기…"(구분선 아래, "텍스트 스타일 이름 다시 짓기…" 위) |
| 무료 · 유료 | 무료 — 기존 변수를 다루는 일(ROADMAP §9 원칙). ia-v4 §6 표 변수 탭 무료 칸에 더한다 |
| 범위 | 이 파일의 **로컬 변수 전부**(플러그인 · 사용자 컬렉션). 원격(라이브러리) 변수는 목록에 넣지 않는다 |
| "쓰임" | §2 — 레이어(숨김 · 인스턴스 안쪽 포함) · 스타일 · 프로토타입 · 컴포넌트 속성 정의가 붙인 변수, 그리고 쓰이는 변수가 **어느 모드에서든** 가리키는 변수를 따라간 것 전부 |
| 결과 | 팝업 하나 — ia-v4 §2.7 트리(컬렉션 머리 + 변수 줄, 스위치), [선택한 {k}개 지우기] |
| 지우기 | 사용자가 켠 것만, 지우기 직전 다시 확인(§4), 한 번의 ⌘Z로 모두 되돌림. 처음엔 모든 스위치 끔 |
| 알 수 없는 것 | 다른 파일이 이 파일을 라이브러리로 쓰는지는 피그마가 알려 주지 않는다 — 거기서 쓰는 변수도 "안 쓰임"으로 나올 수 있다. 팝업에 늘 주의 띠(주황) "다른 파일에서 쓰는 변수는 확인하지 못해요"(2026-11-11 사용자 결정 — 짧게) |

## 1. 흐름 · 상태

팝업 상태는 다섯 가지다.

| 상태 | 본문 | 아래 고정 줄 |
|---|---|---|
| ① 불러오는 중 | 진행 띠(§2.8 — 파랑 띠 + 도는 고리) "페이지를 불러오는 중…" | [취소] |
| ② 읽는 중 | 진행 띠 "파일을 읽는 중… {done} / {total} 페이지" | [취소] |
| ③ 결과 | 주의 띠 · 요약 줄 · 트리(§3) | [닫기] [선택한 {k}개 지우기] |
| ③' 결과 0개 | "안 쓰는 변수가 없어요" + 요약 줄 | [닫기] |
| ④ 확인하는 중 | 트리 위에 진행 띠 "지우기 전에 확인하는 중… {done} / {total} 페이지", 트리 · 스위치 · 모두 켜기/끄기 잠금(`aria-disabled`) | [취소] |
| ⑤ 오류 | 오류 띠(§2.8 — 빨강 띠 + ⚠) "파일을 읽지 못했어요" + `explainError` 한 줄 | [닫기] [다시 시도] |

- 요약 줄(회색): "페이지 {p}개 · 레이어 {l}개를 읽었어요"(메시지의 `pages` · `layers`).
- **들어가기:** ⋯ › "안 쓰는 변수 찾기…" → 팝업이 열리고 ①부터 시작한다. 로컬 변수가 0개면 메뉴 항목을 잠근다(`disabled`, 메모 "로컬 변수가 없어요"). 다른 쓰기 작업 중이면 잠근다(메모 = `writeLockReason`, ia-v4 ⋯ 메뉴의 "텍스트 스타일 이름 다시 짓기…"와 같은 방식).
- **닫힘 = 취소(①②④):** [취소] · Esc · 팝업 바깥 누름 · 최소화(ia-v3 §4.9 "팝업은 닫고 작업은 계속"의 예외 — 이것은 결과를 볼 팝업이 없으면 쓸모없는 읽기이므로 멈춘다) 모두 읽기 · 확인을 멈추고 팝업을 닫는다. ④의 다시 확인 중에 닫으면 지우지 않는다(다시 확인이 끝나 지우기가 시작된 뒤의 닫힘은 지우기를 멈추지 않는다 — §4-2).
- **결과(③)에서 [선택한 {k}개 지우기]:** 확인 팝업을 따로 띄우지 않는다(이 팝업이 확인 단계 — 목록 · 경고 · 직접 고름. ia-v4 §4.9 "확인 팝업(늘)"의 예외로 §4.9에 한 줄 적는다). ④로 가서 다시 확인 → 지우기 → 팝업을 닫고 §7 "플러그인 작업 직후" 다시 읽기 → 공통 상태 줄(§4 문구).
- **오류:** 읽기(`ERROR{op:'SCAN_UNUSED_VARS'}`) 중이면 ⑤ — [다시 시도] = 다시 읽기. 지우기 요청(`ERROR{op:'DELETE_VARIABLES'}` — 다시 확인 · 지우기 어느 단계든 하나의 길)이면 세 경우로 나눈다(최소화하면 팝업도 닫히므로 ⓒ를 ⓑ보다 먼저 본다): ⓐ 팝업이 열려 있으면 ⑤만(공통 상태 줄은 쓰지 않음 — 팝업 뒤라 보이지 않는다) — [다시 시도] = 같은 `DELETE_VARIABLES`를 다시(다시 확인부터). ⓑ 팝업이 닫힌 뒤(지우기 시작 뒤 닫음)면 공통 상태 줄에 이 기능의 실패 문구 "안 쓰는 변수를 지우지 못했어요"(`unused.deleteFail`, 툴팁 = `explainError` 사유). ⓒ 최소화 중이면 쓰기 작업 규칙(⚠ 표시 → 펼칠 때 "안 쓰는 변수 지우기 실패 · [보기]", 도착: 변수 탭 — 팝업은 다시 열지 않음).

## 2. "쓰임" 판정

**쓰는 곳(뿌리)** — 아래에서 찾은 **모든 변수 별칭**(값이 `{type: 'VARIABLE_ALIAS', id}`인 객체, 배열 · 객체 안 깊이까지)과 `variableId` 필드의 id가 직접 쓰임이다. 자리를 하나씩 고르지 않고 이 속성 값 전체를 깊이 우선으로 훑는다 — 그래야 그라디언트 색 단계(`gradientStops[].boundVariables.color`), 효과의 숫자(반경 · 퍼짐 · 오프셋), 격자마다의 연결, 글자 구간 배열, `componentProperties`의 {이름: 별칭} 객체를 빠뜨리지 않는다.
1. **레이어:** 모든 페이지의 모든 레이어 — **숨긴 레이어 · 숨긴 칠하기 · 숨긴 효과 · 인스턴스 안쪽 포함**(지우면 다시 보일 때 그 레이어가 바뀌므로). 훑는 속성: `boundVariables`, `fills`, `strokes`, `effects`, `layoutGrids`, `reactions`(아래 3), 인스턴스 `componentProperties`. 지금 사용 조회(`bind.ts` `walkVisibleDeep` · `boundVariableIds` — 보이는 것만, 칠하기 · 효과는 `color`만)와 **규칙이 다르다**: 새 순회 · 새 수집 함수(`collectUsedVariableIds`)를 쓰고 `walkVisibleDeep`는 쓰지 않는다. 그래서 상세 팝업(§4.8)의 "쓰인 곳 0곳"(보이는 레이어만 셈)인 변수가 이 목록에는 안 나올 수 있다 — 숨긴 레이어에 붙은 경우.
2. **스타일:** 로컬 칠하기 · 글자 · 효과 · 격자 스타일. 훑는 속성: `boundVariables`, 칠하기 스타일의 `paints`, 효과 스타일의 `effects`, 격자 스타일의 `layoutGrids`.
3. **프로토타입:** 레이어 `reactions`의 `actions[]`와 옛 `action` — 조건 동작(`CONDITIONAL`)의 `conditionalBlocks` 안 동작, 식(expression)의 인자까지 위의 깊이 훑기로 따라간다.
4. **컴포넌트 속성 정의:** 컴포넌트 세트(`COMPONENT_SET`)와 세트 밖 `COMPONENT`의 `componentPropertyDefinitions`를 훑는다(세트 안 베리언트에서 읽으면 피그마가 예외를 낸다 — 읽지 않는다). 정의에 변수 연결이 실제로 실리는지는 구현 때 확인한다(없으면 빈 수확으로 끝난다).

**따라가기** — 쓰이는 변수가 **어느 모드에서든** 다른 로컬 변수를 가리키면(별칭) 그 변수도 쓰인다. 계속 따라간다(한 변수는 한 번만 본다 — 순환 안전).

**안 쓰임** = 뿌리에서 닿지 않는 로컬 변수. 두 가지로 나눠 보인다.
- **아무 데도 안 씀**(`none`): 어떤 로컬 변수도(어느 모드에서도) 이것을 가리키지 않는다.
- **안 쓰는 변수만 가리킴**(`chain`): 이것을 가리키는 로컬 변수가 있지만 그 변수들도 모두 안 쓰인다. 예: 아무 데도 안 붙은 Semantic `color/text/subtlest`가 Global `color/gray/300`을 가리키면 둘 다 안 쓰이고, Global 쪽이 `chain`이다.

**보지 않는 것(한계):** 다른 파일의 라이브러리 사용, 코드 · 개발 모드의 변수 사용(코드 문법 등), 원격 변수(로컬 변수가 원격 변수를 가리키는 것은 따라가지 않는다 — 원격은 판정 대상이 아님).

## 3. 결과 팝업

```
┌ 안 쓰는 변수 18개 ───────────────────────────── ✕ ┐
│ ⚠ 다른 파일에서 쓰는 변수는 확인하지 못해요                     (주황 주의 띠)
│ 페이지 12개 · 레이어 8,240개를 읽었어요                                    │
│ 켠 변수만 지워요                              모두 켜기 · 모두 끄기       │
│ ▼ Semantic   6개                                              (○  )      │ ← 머리 띠(§2.7)
│     ● color/text/subtlest     #9CA3AF                          (○  )      │
│     # spacing/card/gap-2      24                               (○  )      │
│ ▼ Global   12개                                               (○  )      │
│     ● color/gray/300          #D1D5DB   안 쓰는 변수만 가리킴   (○  )      │
├───────────────────────────────────────────────────────┤
│ ⚠ 남기는 변수 2개가 '삭제된 변수'를 가리키게 돼요    (빨강 띠, 해당할 때만)  │
│                               [닫기]  [선택한 3개 지우기]                │
└───────────────────────────────────────────────────────┘
```

- 주의 띠: `.banner.caution`(§2.8 안내 띠와 같은 모양에 주황 `--warn-subtle` 배경 · `--warn` 글자 · ⚠ 아이콘 — 새 변형). 문구 `unused.libNote` = "다른 파일에서 쓰는 변수는 확인하지 못해요".
- 팝업은 `.modal`(카드). 안의 목록은 **ia-v4 §2.7 트리**(`treeList.ts` 그대로 — 카드 안 카드 없음): 목록 위 줄(왼쪽 "켠 변수만 지워요", 오른쪽 "모두 켜기 · 모두 끄기"), 컬렉션 머리 줄(회색 머리 띠 · 접기 ▼ `aria-expanded` · 이름 · "{n}개" · 머리 스위치 3가지 모습 `aria-checked="true" | "mixed" | "false"`), 변수 줄(아래 구분선 한 줄 · 오른쪽 스위치). 키보드 · 포커스도 §2.7(`treegrid`, 정지점 1개, ↑↓ · Home/End · ←→ 접기, Space = 스위치).
- 처음: 모든 스위치 끔(머리 스위치 "모두 끔"이어도 이 팝업은 모두 펼침 — §2.7 "처음 접기"의 예외, 고를 목록이 보여야 하므로).
- 변수 줄: 변수 칩(연결 · 만들기 트리의 `varChip` — 종류 표시 ● · # · T와 전체 이름) · 값(기본 모드 — 직접 값이면 값 알약 · 색 견본, 별칭이면 "→ {대상 끝 이름}" — 변수 탭 규칙 §4.6과 같음) · `chain`이면 회색 태그 "안 쓰는 변수만 가리킴"(툴팁 · 접근성 설명 "이것을 가리키는 변수 {m}개도 안 쓰여요 — 그 변수를 남기고 이것만 지우면 그 변수는 '삭제된 변수'를 가리켜요").
- 줄 순서: 컬렉션은 변수 탭 사이드바 순서, 그 안은 이름 순.
- **{m}(chain 태그)**: 이 변수를 **직접** 가리키는 서로 다른 로컬 변수 수(어느 모드든, 같은 변수는 한 번). **빨강 띠의 {m}**: 켠 변수를 직접 가리키는데 **켜지 않은** 서로 다른 로컬 변수 수. 둘 다 UI가 변수 표(`VAR_TABLE`의 모드별 별칭 대상)로 센다(ia-v4 §4.9 삭제 확인의 {m}과 같은 출처) — 메시지에 싣지 않는다.
- 아래 고정 줄: [닫기] · [선택한 {k}개 지우기](`--danger`). k = 0이면 `aria-disabled`(사유 "지울 변수를 켜 주세요"), 다른 쓰기 작업 중이면 `aria-disabled`(사유 = `writeLockReason`). 잠금 사유는 포커스에도 툴팁(`#uiTip`)으로 뜨고 `aria-describedby`로 읽힌다.
- 진행 띠는 `role="status"` · `aria-live="polite"`.
- **포커스:** 열면 [취소]. 결과가 오면 — 사용자가 그동안 포커스를 옮기지 않았으면(아직 [취소]) 결과 있음 → 트리(첫 줄), 0개 · 오류 → [닫기]. 옮겼으면 그대로 둔다(text-style-krds §5.2와 같다). 닫거나 취소 · 지우기로 팝업이 닫히면 변수 탭 [⋯] 단추로 돌아간다.
- 직접 만든 변수(`dsl.manual`, §4.9)도 목록에 든다 — 사용자가 켤 때만 지운다.
- 결과의 id가 지금 변수 표에 없으면(그 사이 지워짐) 그 줄은 그리지 않는다. UI는 결과를 받으면 변수 표를 한 번 다시 읽고(`GET_VAR_TABLE`, 조용히) 그린다. 제목 "안 쓰는 변수 {n}개" · 머리 "{n}개"는 **그린 줄 수**이고, 그린 줄이 0이면 ③'.
- **구현 메모(팝업 한 개로 상태 바꾸기):** `openModal`은 한 번만 부른다(다시 부르면 `closeModal` → 취소 · 포커스 되돌림이 먼저 돈다). 상태가 바뀌면 같은 팝업 안의 본문과 아래 줄(`.m-foot`) 단추를 바꿔 끼운다 — 바꾸기 전에 `document.activeElement`가 [취소]였는지 먼저 보고, 맞으면 위 포커스 규칙의 자리로 옮긴다. 빨강 띠는 아래 줄 위 자리(`footTop`)에 처음부터 숨겨 두고 보이기만 바꾼다. 취소는 팝업의 `onClose`에 걸되 **①②④(읽는 중 · 다시 확인 중)일 때만** `CANCEL{op:'unused'}`를 보낸다 — ③ [닫기] · ⑤에서는 보내지 않는다. ④에서는 UI가 지우기 시작 시점을 모르므로 늘 보내고, 코드가 지우기 시작 뒤의 취소를 무시한다(§4-2)(최소화 `setMini`는 `closeModal`을 바로 부르므로 `beforeClose`로는 놓친다). 트리 마운트에는 `.tree` 클래스를 준다.

## 4. 지우기 직전 다시 확인 · 지우기

1. **다시 확인(④):** 처음 읽기와 **똑같이 파일 전체를 다시 읽어**(§2 — 뿌리 · 따라가기, 비용도 같다) 지금의 안 쓰임 집합 U′를 구한다. 켠 변수 집합 S 중 U′에 없는 것(그 사이 쓰이기 시작했거나, 쓰이는 변수가 가리키게 됐거나, 이미 지워진 것)이 **건너뜀 집합 K = S − U′**(K ⊆ S, s = |K|)다.
   - U′의 정의상 쓰이는 변수는 U′의 변수를 가리키지 않으므로, S ∩ U′만 지우면 쓰이는 변수가 '삭제된 변수'를 가리키는 일은 없다. 남는 것은 **안 쓰이는 변수**가 지운 변수를 가리키는 경우뿐이고, 이것은 사용자가 빨강 띠(§3)를 보고 고른 것이다 — 단 읽은 뒤 새로 생긴 안 쓰이는 변수가 켠 변수를 가리키게 된 경우는 띠에 나오지 않았다(드묾, 한계).
   - 코드는 처음 결과를 기억할 필요가 없다(메시지에 처음 결과를 싣지 않는다).
2. **지우기:** S − K를 하나씩 `variable.remove()`. **지우기를 시작한 뒤에 온 취소는 무시한다**(다시 확인이 끝나는 순간이 취소를 보는 마지막 지점) — 팝업이 이미 닫혔어도 결과는 공통 상태 줄에 나온다. 실패하면 그 변수는 실패 수 f로 세고 다음으로 간다. 지운 수 d > 0이면 한 번 `commitUndo`(⌘Z 한 번에 모두 돌아옴), d = 0이면 부르지 않는다.
3. **결과 문구(공통 상태 줄):**
   - d > 0: "변수 {d}개를 지웠어요 · ⌘Z로 되돌리기" + (s > 0이면) " · 건너뜀 {s}"(툴팁 "읽은 뒤 쓰이기 시작했거나(쓰는 변수가 가리키는 경우 포함) 이미 지워졌어요") + (f > 0이면) " · 못 지움 {f}"(경고 모양).
   - d = 0: "지운 변수가 없어요" + 같은 꼬리.
   - 상태 줄은 쓰기 작업 결과와 같은 모양(성공 ✓ · 일부 실패 ⚠).

## 5. 메시지 · 작업 등록

- `SCAN_UNUSED_VARS{reqId}` → `PROGRESS{op: 'unused', done, total}`(불러오는 중은 `done: 0, total: 0` 한 번 — UI는 total 0을 "불러오는 중"으로 그린다, 그 뒤 페이지 단위) → `UNUSED_VARS{reqId, items: {id, kind: 'none' | 'chain'}[], pages, layers, cancelled?: true}` / `ERROR{op: 'SCAN_UNUSED_VARS', reqId}`.
- `DELETE_VARIABLES{reqId, ids}` → `PROGRESS{op: 'unused-delete', done, total}`(다시 확인, 같은 규칙) → `VARIABLES_DELETED{reqId, deleted, skipped, failed, cancelled?: true}` / `ERROR{op: 'DELETE_VARIABLES', reqId}`.
- `CANCEL{op?: 'unused'}`: op가 없으면 지금처럼 찾기만 멈춘다(`bindCancel`). `'unused'`면 따로 둔 플래그(`unusedCancel`) 하나만 켜고 `bindCancel`은 건드리지 않는다. `SCAN_UNUSED_VARS` · `DELETE_VARIABLES`를 **시작할 때 `unusedCancel = false`**(지금 찾기가 새 요청마다 `bindCancel`을 지우는 것과 같다 — 남은 플래그가 다음 요청을 멈추지 않게). 읽기 · 확인은 다음 양보 지점에서 멈추고 `cancelled: true`인 응답을 보낸다(UI는 이 응답으로 대기 상태를 푼다 — 응답이 늘 온다).
- `shared/messages.ts`: 새 메시지 4개, `PROGRESS.op`에 `'unused'` · `'unused-delete'`, `CANCEL`에 `op?`.
- **UI 작업 등록:** 읽기(`SCAN_UNUSED_VARS`)는 진행 테두리 · 최소화 고리 대상이 **아니다**(팝업이 진행을 보인다 — `OPS`에 넣지 않음, 닫히면 취소이므로 최소화 중 결과도 없다). 그래서 `opReceived`는 `PROGRESS{op:'unused'}`를 무시한다(전역 진행 `opProg`를 덮지 않게). 팝업은 이 진행을 자기 띠에 그린다. ia-v4 §2.6에 예외를 적었다. 지우기(`DELETE_VARIABLES`)는 쓰기 작업이다 — `OPS`에 `write: true`, 라벨 `op.deleteUnused`("안 쓰는 변수 지우기"), `VAR_WRITE_OPS`에 넣는다(다른 쓰기와 서로 잠금). 결과 판정(`opReceived`): `VARIABLES_DELETED{cancelled}` → 취소(표시 없음 — ia-v3 §4.9), `failed > 0` → 일부 실패(⚠), 그 밖 → 성공(✓). §7 "플러그인 작업 직후" 다시 읽기는 `deleted > 0`일 때만. 실패 · [보기] 도착은 변수 탭(ia-v4 §2.6).

## 6. 성능

- `figma.loadAllPagesAsync()`(①, 이 동안은 취소가 먹지 않는다 — 끝난 뒤 바로 멈춘다) 뒤 페이지마다 **직접 스택으로** 레이어를 돈다(`findAll`처럼 배열을 통째로 만들지 않음). 레이어 **2,000개마다** 양보(`setTimeout 0`)하고 취소 플래그를 본다. 진행은 페이지 단위로 보낸다.
- 레이어마다 변수 id만 집합에 모은다(후보 목록 없음).
- 노드 1만 개 기준 수 초, 큰 파일은 수십 초(추정) — 실측은 실기 확인 때 기록한다.
