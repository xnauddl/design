# 안 쓰는 변수 찾기 — 파일 전체 (2026-11-11 초안)

> 대상: 변수 탭 ⋯ 메뉴의 새 항목 "안 쓰는 변수 찾기…"와 그 팝업. 화면 구조 규칙은 `docs/ia-v4.md`(변수 탭 §4.6, 삭제 §4.9, 팝업 · 카드 규칙 §2.8)를 따른다.
> 왜: 자동 만들기를 여러 번 돌리면 쓰이지 않는 변수가 남는다(예: 예전 실행의 `-2` · `-a8` 이름, 지운 레이어의 값). 지금은 변수마다 상세 팝업을 열어 "쓰인 곳"을 하나씩 봐야 한다. ROADMAP §9 "파일 전체 미사용 변수 찾기 (IA v3 다음)".
> 순서: 이 명세 → 코드 대조 검토 결함 0 → 화면 시안 → 구현(CLAUDE.md).

## 0. 결정 요약

| 항목 | 결정 |
|---|---|
| 들어가는 곳 | 변수 탭 [⋯] 메뉴 "안 쓰는 변수 찾기…"(구분선 아래, "텍스트 스타일 이름 다시 짓기…" 위) |
| 무료 · 유료 | 무료 — 기존 변수를 다루는 일(ROADMAP §9 원칙: 기존 변수는 Free, 새로 만드는 일은 Paid) |
| 범위 | 이 파일의 **로컬 변수 전부**(플러그인 · 사용자 컬렉션). 라이브러리(원격) 변수는 보지 않는다 |
| "쓰임"의 뜻 | 아래 §2 — 레이어 · 스타일 · 프로토타입이 붙인 변수, 그리고 그 변수가 (모든 모드에서) 가리키는 변수를 따라간 것 전부 |
| 결과 | 팝업 하나 — 컬렉션별 목록, 줄마다 체크, [선택한 {k}개 지우기] |
| 지우기 | 사용자가 고른 것만, 한 번의 ⌘Z로 되돌림. 처음엔 아무것도 고르지 않은 상태 |
| 알 수 없는 것 | 다른 파일이 이 파일을 라이브러리로 쓰는지는 피그마가 알려 주지 않는다 — 팝업에 늘 경고 한 줄 |

## 1. 흐름

1. 변수 탭 [⋯] › "안 쓰는 변수 찾기…" → 팝업이 열리고 바로 읽기를 시작한다.
2. **읽는 중:** 팝업 본문에 진행 띠(§2.8 진행 상자 — 파랑 띠 + 도는 고리) "파일을 읽는 중… {done} / {total} 페이지" · [취소]. 진행은 페이지 단위로 보낸다.
3. **결과:**
   - 0개: "안 쓰는 변수가 없어요" · [닫기].
   - 1개 이상: 목록(§3) · 아래 고정 줄 [닫기] [선택한 {k}개 지우기].
4. [선택한 {k}개 지우기]: 확인 단계 없이 바로 지운다(팝업이 이미 확인 단계 — 목록 · 경고 · 직접 고름). 지운 뒤 팝업을 닫고, 변수 표를 다시 읽고, 공통 상태 줄에 "변수 {k}개를 지웠어요 · ⌘Z로 되돌리기".
5. [취소](읽는 중): 읽기를 멈추고 팝업을 닫는다. 아무것도 바뀌지 않는다.

## 2. "쓰임" 판정

**쓰는 곳(뿌리)** — 이 중 하나라도 그 변수를 붙이고 있으면 직접 쓰임이다.
1. **레이어:** 모든 페이지의 모든 레이어(숨긴 레이어 · 인스턴스 안쪽 포함 — 지우면 그 레이어가 바뀌므로). 붙는 자리는 `boundVariables`의 모든 필드(칠하기 · 선 · 효과 색, 글자 구간 배열의 모든 원소, 컴포넌트 속성 `componentProperties` 포함)다. 지금 `bind.ts` `boundVariableIds`는 `componentProperties` · `textRangeFills`를 건너뛰므로(보기 전용 사용 수의 규칙) 이 판정은 새 함수(`collectUsedVariableIds`)로 하되 같은 읽기 도우미를 쓴다.
2. **스타일:** 로컬 칠하기 · 글자 · 효과 · 격자 스타일의 `boundVariables`(칠하기 스타일은 각 칠하기의 색 연결).
3. **프로토타입:** 레이어 `reactions`의 동작 중 변수를 쓰는 것(변수 바꾸기 · 조건의 변수 id와 그 값의 별칭).
4. **컴포넌트 속성 정의:** 컴포넌트 · 세트의 속성 기본값에 붙은 변수.

**따라가기** — 쓰이는 변수가 어느 모드에서든 다른 로컬 변수를 가리키면(별칭) 그 변수도 쓰인다. 따라간 변수가 또 가리키면 계속 따라간다(순환은 한 번만 본다).

**안 쓰임** = 뿌리에서 닿지 않는 로컬 변수. 두 가지로 나눠 보인다.
- **아무 데도 안 씀**(`none`): 어떤 변수도 이것을 가리키지 않는다.
- **안 쓰는 변수만 가리킴**(`chain`): 이것을 가리키는 변수가 있지만, 그 변수들도 모두 안 쓰인다. 예: 아무 레이어에도 안 붙은 Semantic `color/text/subtlest`가 Global `color/gray/300`을 가리키면 둘 다 안 쓰이고, Global 쪽이 `chain`이다.
- 체크해서 지울 때 `chain` 변수만 지우고 그것을 가리키는 변수를 남기면 그 변수는 "삭제된 변수"를 가리키게 된다 — 줄의 툴팁 · 팝업 경고로 알린다(§3). 고르는 일은 막지 않는다.

**보지 않는 것(한계):**
- 다른 파일이 이 파일의 변수를 라이브러리로 쓰는지(피그마 API로 알 수 없음).
- 코드 · 개발 모드의 변수 사용(코드 문법 등).
- 원격(라이브러리) 변수 — 이 파일에서 지울 수 없으므로 목록에 넣지 않는다. 단 로컬 변수가 원격 변수를 가리키는 것은 따라가지 않는다(원격은 판정 대상이 아님).

## 3. 결과 팝업

```
┌ 안 쓰는 변수 18개 ───────────────────────── ✕ ┐
│ ⓘ 다른 파일이 이 파일을 라이브러리로 쓰면 거기서 쓰는 변수도 여기에 보일 수 있어요   (파랑 띠)
│ 모두 선택 · 모두 해제                                   │
│ ▼ Semantic  6개                               [□]   (회색 머리 띠)
│   □ ● color/text/subtlest      #9CA3AF                │
│   □ # spacing/card/gap-2        24                     │
│ ▼ Global  12개                                [□]   │
│   □ ● color/gray/300           #D1D5DB   안 쓰는 변수만 가리킴 │
│   …                                                    │
├────────────────────────────────────────────────────┤
│                         [닫기]  [선택한 3개 지우기]      │
└────────────────────────────────────────────────────┘
```

- 팝업은 `.modal`(카드). 목록은 §2.8 "카드 안에서 쓰는 모양" — 컬렉션 머리는 회색 머리 띠, 줄은 아래 구분선 한 줄(카드 안 카드 없음).
- 머리: 컬렉션 이름 · "{n}개" · 머리 체크(모두 · 일부 · 없음, 누르면 일부 · 없음 → 모두, 모두 → 없음). 처음엔 모두 펼침.
- 줄: 체크 · 변수 칩(종류 표시 ● · # · T와 이름 — 변수 탭 줄과 같은 칩) · 값(기본 모드, 별칭이면 "= {가리키는 이름}") · `chain`이면 회색 태그 "안 쓰는 변수만 가리킴"(툴팁 "이것을 가리키는 변수 {m}개도 안 쓰여요 — 그 변수를 남기고 이것만 지우면 그 변수는 '삭제된 변수'를 가리켜요").
- 줄 순서: 컬렉션은 변수 탭 사이드바 순서, 그 안은 이름 순.
- 아래 고정 줄: [닫기] · [선택한 {k}개 지우기](`--danger`, k = 0이면 `aria-disabled` — 사유 "지울 변수를 골라 주세요"). 고른 것 중 `chain`의 가리키는 변수를 남기는 경우가 있으면 버튼 위에 빨강 띠 "남기는 변수 {m}개가 '삭제된 변수'를 가리키게 돼요"(§2.8 오류 띠 모양).
- 처음 포커스: 읽는 중 [취소], 결과 0개 [닫기], 결과 있음 "모두 선택". Esc = [닫기]([취소]).
- 직접 만든 변수(`dsl.manual`, §4.9)도 목록에 든다 — 사용자가 고를 때만 지운다.

## 4. 지우기

- 고른 변수만 지운다(`variable.remove()`), 한 처리 · 한 번의 `commitUndo`(⌘Z 한 번에 모두 돌아옴 — §4.9 삭제와 같이 피그마 되돌리기).
- 지우기 직전에 다시 확인: 읽은 뒤 사용자가 레이어에 붙였거나 이미 지워진 변수는 건너뛰고 센다. 확인은 **고른 변수만** 대상으로 §2의 뿌리(레이어 · 스타일 · 프로토타입 · 컴포넌트 속성 정의)를 한 번 더 찾는다(페이지를 다시 돌므로 진행 띠 "확인하는 중… {done} / {total} 페이지"). 따라가기는 다시 보지 않는다 — 고른 변수를 가리키는 변수가 그 사이 쓰이기 시작한 경우는 놓친다(드묾, 한계). 결과 문구에 " · 건너뜀 {s}"(툴팁 "읽은 뒤 쓰이기 시작했거나 이미 지워졌어요").
- 지운 뒤: 변수 표 다시 읽기(`readScreen('work')`), 상태 줄 "변수 {k}개를 지웠어요 · ⌘Z로 되돌리기"(+ 건너뜀 꼬리).

## 5. 메시지

- `SCAN_UNUSED_VARS{reqId}` → 진행 `PROGRESS{op: 'unused', done, total}`(페이지 단위) → `UNUSED_VARS{reqId, items: {id, name, collectionId, kind: 'none' | 'chain', pointers?: number}[], pages, layers}` / `ERROR{op, reqId}`.
- `CANCEL{op: 'unused'}` — 다음 페이지 경계에서 멈추고 `UNUSED_VARS`를 보내지 않는다.
- `DELETE_VARIABLES{reqId, ids}` → (다시 확인 중 `PROGRESS{op: 'unused-delete'}`) → `VARIABLES_DELETED{reqId, deleted, skipped}` / `ERROR`.
- 값 · 칩 표시는 UI가 지금 변수 표(`VAR_TABLE`)에서 id로 찾아 그린다(메시지에 값을 싣지 않는다).

## 6. 성능

- `figma.loadAllPagesAsync()` 뒤 페이지마다 `findAll`(인스턴스 안쪽 포함)로 돈다. 페이지 사이에 양보(`setTimeout 0`)해 진행 · 취소가 먹게 한다.
- 노드 수에 비례 — 노드 1만 개 기준 수 초, 큰 파일은 수십 초(추정). 실측은 실기 확인 때 기록한다.
- 레이어마다 변수 id만 모으고(집합) 후보 목록을 만들지 않는다.
