# UI/UX 전면 리디자인 — 요청 요지와 결정

> 2026-11-25 사용자 요청 "Figma Plugin UI/UX 디자인 전면 개선 및 리디자인". 원문은 4장 "분석 결과 단계 — 하단 왼쪽: Back"에서 끊겼다(뒷부분은 받는 대로 더한다).
> 구현 시기: **범위 정리(S-1b–S-5)가 끝난 뒤**(SC-D25). 그 전까지 이 문서는 기록이다.

## 1. 목표 (요청 요지)

- 핵심 기능 · 데이터 처리 · Figma API 연동 · 작업 흐름은 그대로 두고 UI 디자인과 인터랙션 구조를 전면 개선한다.
- 임시 개발 도구가 아니라 디자이너가 매일 쓰는 전문 디자인 시스템 관리 도구처럼 보여야 한다.
- 범위: 정보 구조와 시각 위계 · 메뉴와 기능 배치 · 버튼 위치 · 크기 · 우선순위 · 일관된 디자인 시스템 · 여백 · 정렬 · 간격 · 작업 흐름 · 플러그인 창에 맞는 레이아웃.

## 2. 디자인 방향

- 콘셉트: Modern Professional · Minimal & Clean · Design Tool Interface · Information First · Consistent & Functional.
- 밝은 테마가 기본. 배경은 흰색 또는 아주 밝은 중립색, 글자는 어두운 중립색, 구분선 · 보조 영역은 낮은 대비.
- 강조색은 주 실행(Primary)에만. 카드 · 패널은 필요할 때만, 테두리 · 그림자는 줄인다.
- 둥글기 · 아이콘은 한 체계로. 상태는 색만으로 가르지 않고 글자 · 아이콘을 함께 쓴다.
- 특정 제품의 UI를 베끼지 않는다(원칙만 참고).

## 3. 레이아웃

- **Header:** 로고 또는 심볼 · 플러그인 이름 · 지금 작업 범위(선택 대상) · 설정 · 도움말. 높지 않게.
- **Navigation:** 기능을 목적별로 묶고 Active 상태를 보인다. 실제 있는 기능만 메뉴로 둔다(없는 기능을 더하지 않는다).
- **Main:** 제목 → 짧은 설명 → 대상 · 범위 → 분석 · 설정 → 결과 · 미리보기 → 실행. 화면 특성에 맞게(기계적으로 같게 하지 않는다).
- **Bottom Action:** 주요 실행 버튼은 아래에. 필요하면 고정 실행 줄(내용을 가리지 않게).

## 4. 버튼

- 종류 넷: Primary(화면에 하나) · Secondary(미리보기 · 새로 고침 · 모두 선택 · 설정) · Tertiary/Ghost(취소 · 닫기 · 초기화 · 상세) · Destructive(삭제 · 초기화 — 확인 단계).
- 자리: 주 실행은 아래 오른쪽, 취소 · 뒤로는 아래 왼쪽이고 덜 눈에 띄게. 여러 단계 작업의 이전 · 다음은 같은 자리. 같은 목적의 버튼은 모든 화면에서 자리 · 크기가 같다. 높이 · 간격 통일, 글자 길이로 너비가 크게 달라지지 않게, 아이콘 버튼에는 툴팁, 내용과 겹치거나 창 밖으로 나가지 않게.
- 단계별 예: 분석 단계 — 왼쪽 Cancel · 오른쪽 Analyze. 분석 결과 단계 — 왼쪽 Back …(원문 끊김)
