# UI/UX 전면 리디자인 — 요청 요지와 결정

> 2026-11-25 사용자 요청 "Figma Plugin UI/UX 디자인 전면 개선 및 리디자인". 원문은 4장 "분석 결과 단계 — 하단 왼쪽: Back"에서 끊겼다(뒷부분은 받는 대로 더한다).
> **2026-11-25 SC-D30: 리디자인은 다른 세션에서 한다.** 구조(작업별 탭 · Header · 하단 실행 줄)와 첫 화면 재설계(SC-D6 진행 줄 · SC-D10 상태 줄 없앰 · SC-D11 Global 직접 연결 수)도 그 세션이 이어받는다. 범위 정리 쪽 S-2는 숫자("같은 값" 함수)만 고친다. 아래 SC-D25 · SC-D29의 "언제"는 이 줄이 대신한다.
> 구현 시기: **범위 정리(S-1b–S-5)가 끝난 뒤**(SC-D25). 그 전까지 이 문서는 기록이다.

## 1. 목표 (요청 요지)

- 핵심 기능 · 데이터 처리 · Figma API 연동 · 작업 흐름은 그대로 두고 UI 디자인과 인터랙션 구조를 전면 개선한다.
- 임시 개발 도구가 아니라 디자이너가 매일 쓰는 전문 디자인 시스템 관리 도구처럼 보여야 한다.
- 범위: 정보 구조와 시각 위계 · 메뉴와 기능 배치 · 버튼 위치 · 크기 · 우선순위 · 일관된 디자인 시스템 · 여백 · 정렬 · 간격 · 작업 흐름 · 플러그인 창에 맞는 레이아웃.

## 2. 디자인 방향

- 콘셉트: Modern Professional · Minimal & Clean · Design Tool Interface · Information First · Consistent & Functional.
- 밝은 테마가 기본. 배경은 흰색 또는 아주 밝은 중립색, 글자는 어두운 중립색, 구분선 · 보조 영역은 낮은 대비.
- 강조색은 주 실행(Primary)에만. 카드 · 패널은 필요할 때만, 테두리 · 그림자는 줄인다.
- 둥글기 · 아이콘은 한 체계로. 상태는 색만으로 가르지 않고 글자 · 아이콘을 함께 쓴다.
- 특정 제품의 UI를 베끼지 않는다(원칙만 참고).

## 3. 레이아웃

- **Header:** 로고 또는 심볼 · 플러그인 이름 · 지금 작업 범위(선택 대상) · 설정 · 도움말. 높지 않게.
- **Navigation:** 기능을 목적별로 묶고 Active 상태를 보인다. 실제 있는 기능만 메뉴로 둔다(없는 기능을 더하지 않는다).
- **Main:** 제목 → 짧은 설명 → 대상 · 범위 → 분석 · 설정 → 결과 · 미리보기 → 실행. 화면 특성에 맞게(기계적으로 같게 하지 않는다).
- **Bottom Action:** 주요 실행 버튼은 아래에. 필요하면 고정 실행 줄(내용을 가리지 않게).

## 4. 버튼

- 종류 넷: Primary(화면에 하나) · Secondary(미리보기 · 새로 고침 · 모두 선택 · 설정) · Tertiary/Ghost(취소 · 닫기 · 초기화 · 상세) · Destructive(삭제 · 초기화 — 확인 단계).
- 자리: 주 실행은 아래 오른쪽, 취소 · 뒤로는 아래 왼쪽이고 덜 눈에 띄게. 여러 단계 작업의 이전 · 다음은 같은 자리. 같은 목적의 버튼은 모든 화면에서 자리 · 크기가 같다. 높이 · 간격 통일, 글자 길이로 너비가 크게 달라지지 않게, 아이콘 버튼에는 툴팁, 내용과 겹치거나 창 밖으로 나가지 않게.
- 단계별 예: 분석 단계 — 왼쪽 Cancel · 오른쪽 Analyze. 분석 결과 단계 — 왼쪽 Back …(원문 끊김)

## 6. 지금 UI를 잰 값 (2026-11-25, `src/ui.html`)

- 모서리 둥글기 8가지(2 · 3 · 4 · 5 · 6 · 8 · 13 · 999px) · 글자 크기 6가지(10 · 11 · 11.5 · 12 · 12.5 · 13px — 11px가 77곳) · 버튼 59개 · 밝은 테마만 · 한국어만.
- 창 560×510. Header 약 40px + 탭 줄 + 하단 실행 줄을 모두 두면 세로의 약 25%가 틀에 쓰인다 — 명세에서 높이를 잰다.
- `scripts/verify-bind-flow.mjs`의 검사 약 790개가 지금 구조 · 한국어 문구에 묶여 있다. 영어로 바꾸면 문구를 보는 검사를 모두 고쳐야 한다.

## 7. 디자인 시스템 선행 작업 결정 (2026-11-25 사용자 결정 DS-D1–DS-D4)

> 명세: `docs/design-system.md`.
> 요청 "선행 작업: Figma Plugin 전용 디자인 시스템 신규 구축". 전제 바로잡음: `src/ui.html`에 "디자인 시스템 v2" 토큰(CSS 변수 약 30개 · 363곳)이 이미 있다 — 이번 일은 그것을 정리 · 확장하는 것이다.

| 번호 | 결정 |
|---|---|
| DS-D1 | **기반 먼저, 단계별.** DS-1(지금, S-1b와 나란히): 토큰 원본 한 곳 + 직접 입력 값을 토큰으로 바꿈 + 직접 입력을 막는 검사(화면은 단계에 맞추는 만큼만 바뀜). DS-2: 공통 컴포넌트 · 레이아웃 — 리디자인의 새 구조(SC-D30으로 이 세션이 맡음)가 이것으로 만들어진다. DS-3(S-5c): 토큰 값만 바꿔 새 모양. SC-D25 · SC-D29의 "디자인 시스템은 S-5c"를 이렇게 나눈다. |
| DS-D2 | 컴포넌트는 요청 목록 **30종 전부** 구현(처음에 35종이라 적었으나 목록은 30종 — Avatar는 크기 목록에만 있다. 지금 0곳인 Split Button · Radio · Breadcrumb · Table · Toast도 만들어 모음 화면에서 확인). |
| DS-D3 | 간격은 **4px 격자(4 · 8 · 12 · 16 · 20 · 24 · 32 · 40) + 2px**(아이콘–글자 사이 · 칩 안쪽만). 6px 등은 4 또는 8로 맞춘다. |
| DS-D4 | **코드 먼저, Figma 라이브러리는 나중.** 토큰 원본은 JSON으로 두어 나중에 이 플러그인으로 Figma 변수를 만들 수 있게 한다. |

## 8. 디자인 방향 · 핵심 기준 (2026-11-25 사용자 요청 요지 · 결정 DS-D5–DS-D9)

**요청 요지(원문 "디자인 방향 및 핵심 디자인 시스템 기준"):**
- 콘셉트 Modern Minimalism — Modern · Minimal · Professional · Clean · Precise · Functional. 장식 · 과한 색 · 복잡한 카드 UI를 피하고 정보 구조 · 가독성 · 정렬 · 간격 · 사용성을 앞세운다.
- Primary `#111111` — Primary 버튼 · 고른 내비 · 고른 탭 · 주요 액션 · 강조 · 핵심 아이콘 · 중요한 글자. Neutral과 어울리게.
- Foundation: Primary #111111 · Neutral 800 #333333 · 700 #555555 · 500 #999999 · 300 #D9D9D9 · 200 #ECECEC · 100 #F5F5F5 · White #FFFFFF. Semantic: Success #16845B · Warning #B7791F · Error #D64545 · Information(필요에 맞게). 상태색은 상태를 알릴 때만. 모든 색은 토큰으로.
- UI: 바탕 White · 보조 영역 Neutral 100 · 테두리 Neutral 200–300 · 주 글자 Neutral 800 · 보조 글자 700–500 · Primary 버튼 #111111 + White 글자 · Secondary 버튼 White + Neutral 테두리 · Disabled는 분명하되 과하게 흐리지 않게 · Hover · Focus는 바탕 · 테두리 · 외곽선 변화로.
- 둥글기 6 · 8 · 10 중심 · 4px 간격 · 버튼 · 입력 · 카드의 높이 · 간격 통일 · 넉넉한 여백 · 카드 쪼개기 · 테두리 겹침 피하기.
- 글자 Sans-serif · 위계는 크기 · 굵기로 · 제목을 크게 하지 않음 · 아이콘 선 굵기 · 크기 통일 · 아이콘–글자 정렬 · 간격 통일.
- 품질: #111111 중심 모노크롬이되 단조롭거나 무겁지 않게(Neutral 명도 차 · 글자 · 여백 · 배치로). 모든 화면이 같은 디자인 시스템을 쓴다.

| 번호 | 결정 |
|---|---|
| DS-D5 | 위 방향을 디자인 시스템의 최종 값으로 한다(`docs/design-system.md` §3). |
| DS-D6 | **DS-1 안에서 두 단계** — ① 지금 값 그대로 토큰으로 옮기는 커밋 ② 토큰 원본의 값만 새 기준으로 바꾸는 커밋(같은 PR). |
| DS-D7 | 상태색(Success · Warning · Error)은 **지정 값 그대로** 글자에도 쓴다. 4.5:1 미달(Warning 3.6:1 · Error 4.4:1 등)은 열린 결함으로 적고 대비 검사 예외에 둔다. |
| DS-D8 | Information은 **모노크롬**(#111111 글자 + ⓘ 아이콘 + Neutral 100 바탕). |
| DS-D9 | 둥글기 **xs 4(16px 이하 작은 요소) · small 6 · medium 8 · large 10 · full.** |
