# 컴포넌트 · 타이포그래피 자동화 — 기술 설계 제안 (초안 1)

> 2026-11-24(같은 날 9장 컴포넌트 속성을 받아 §3.13 · R14–R17 · D11을 더함). 사용자 정의서(`brief.md`) 6장 끝의 요청 — "개발을 시작하기 전에 Figma Plugin API 제약을 확인하고 실제 구현 가능한 방식으로 기술 설계를 먼저 제안한다" — 에 대한 답이다.
> 이 문서는 **제안**이다. 사용자 결정이 아닌 것은 "제안" · "추정"으로 적었다. 결정이 나면 명세(ia 문서)로 옮긴다.
> API 확인 출처: 이 저장소에 설치된 공식 타입 정의 `@figma/plugin-typings` **1.129.0**(`node_modules/@figma/plugin-typings/plugin-api.d.ts` — 함수마다 공식 설명이 들어 있다). 2026-11-24 기준 최신은 **1.143.0**이다 — 구현 전에 올리고 아래 표를 다시 확인한다. 타입 정의에 없는 동작(인스턴스에서 무엇을 덮어쓸 수 있는지 등)은 "실기 확인 필요"로 적었다.

## 0. 요약

- **만들 수 있다.** 정의서의 핵심(같은 구조 묶기 → 컴포넌트 · Variant 세트 · 누락 조합 · 인스턴스 교체 · 글자 스타일 + 변수 연결)은 모두 공식 API로 된다.
- **그대로는 안 되는 것 넷:** ① 상태(Hover · Disabled)와 뜻 이름(Primary · Secondary)은 멈춘 화면에서 읽을 수 없다 — 이름은 제안하고 사용자가 고친다. ② "화면 결과가 100% 같다"는 보장할 수 없다 — 바꾼 뒤 비교해서 다르면 원본을 그대로 두는 방식으로 지킨다. ③ 구조만으로 묶으면 서로 다른 것이 한 묶음이 된다(아이콘 + 글자 한 줄 = 버튼 · 메뉴 · 탭 · 칩) — 구조 다음에 모양으로 한 번 더 나눠야 한다. ④ 인스턴스 안에서는 자식을 더하거나 빼거나 순서를 바꿀 수 없다 — 구조가 조금이라도 다르면 Variant로 가야 한다.
- **8장(타이포그래피)은 지금 플러그인에 절반 넘게 이미 있다.** 새로 만들지 말고 차이만 채우는 것을 제안한다(§3.11 차이표).
- **범위가 크다.** 한 번에 만들지 말고 5단계로 나눈다(§4). 첫 단계는 파일을 바꾸지 않는 "분석만"이다.

## 1. 정의서 검토 — 바로잡을 전제와 빈 곳

정의서를 그대로 구현하면 막히는 곳이다. §5 "정할 것"에 선택지로 다시 모았다.

| # | 정의서 | 문제 | 제안 |
|---|---|---|---|
| R1 | 1장 "Figma Plugin을 개발한다" · 4장 5단계 화면 | 새 플러그인처럼 쓰여 있다. 이 저장소는 이미 변수 연결 · 만들기 · 이름 정리를 하는 플러그인이고 창은 560 × 510이다 | 이 플러그인의 **새 컴포넌트 기능**으로 본다(추정 — 확인 필요). 5단계는 이 플러그인의 화면 틀(첫 화면 진행 줄 · 하위 화면)에 맞춰 다시 그린다 |
| R2 | 2-3 Variant 이름 예: Color=Primary, State=Hover, Style=Ghost | 멈춘 디자인에는 "Hover" · "Primary"라는 정보가 없다. 파란 버튼이 Primary인지는 사람만 안다 | 축 이름 · 값 이름은 **자동 제안 + 실행 전에 고치기**. 제안 근거: 레이어 이름 속 단어(hover · disabled · selected …) → 붙어 있는 변수 이름(`color/primary`) → 색 이름 · 크기 순서(S · M · L) |
| R3 | 3장 "레이어 이름 · 글자 · 색 · 크기 차이는 구조 차이가 아니다" | 맞지만, 구조만 보면 [아이콘 + 글자] 한 줄은 버튼 · 메뉴 항목 · 탭 · 칩이 모두 같은 구조다. 한 Component Set으로 합쳐지면 틀린 결과다. 옛 컴포넌트 기능이 결정 31개(C-D1–C-D31)를 쓰고도 흔들린 자리가 여기다 | **2단 묶기**: ① 구조 지문으로 묶고 ② 그 안에서 모양 값(높이 · 여백 · 채움 유무 · 모서리)으로 "같은 가족인지"를 따로 본다(§3.3). 애매하면 합치지 않고 사용자에게 묻는다(정의서 3장 마지막 줄과 같은 방향) |
| R4 | 2-2 "속성만 다르면 Instance" vs 2-3 "속성이 다르면 Variant" | 어떤 차이가 **덮어쓰기**(인스턴스마다 다른 값)이고 어떤 차이가 **Variant**인지 기준이 없다. 카드 20개의 사진이 다 다르다고 Variant 20개를 만들면 안 된다 | **내용 차이 = 덮어쓰기**(글자 · 사진 · 아이콘 그림), **모양 차이 = Variant 후보**. 모양 차이도 같은 값이 되풀이될 때만 Variant로(§3.3) |
| R5 | 3장 Type C "별개의 Component로 관리" | 한 번만 나오는 프레임까지 모두 컴포넌트로 만들면 화면의 모든 구역이 컴포넌트가 된다 | Type C는 **만들지 않고 목록에만** 보인다("따로 볼 프레임"). 사용자가 골라서 만들 수 있다 |
| R6 | 2-2 "대표 프레임 하나를 Main Component로" | 메인 컴포넌트가 화면 디자인 한가운데 남는다. 그 화면을 지우면 메인이 사라진다 | 메인은 **컴포넌트 모음 자리**(전용 페이지 또는 섹션)에 만들고, 원래 프레임은 대표 포함 모두 인스턴스로 |
| R7 | 2-4 "빈 Variant" | 속성이 3개 × 값 4개면 조합이 64개다. 대부분은 디자인 시스템에 없는 조합이다 | 누락 조합은 **목록으로 먼저 보이고 고른 것만** 만든다(7-3과 같은 방향). 한 세트에서 한 번에 만드는 수에 상한 |
| R8 | 2-5 "화면상 결과물은 변경 전과 동일해야 한다" | API가 보장하지 않는다. 옛 기능에서 실제로 사진 자르기 · 글 줄바꿈이 바뀐 적이 있다(QA 5 결함 2) | 바꾸기 전후를 **수치로 비교**하고, 다르면 그 프레임은 되돌려 원본을 둔다. "바꾼 것은 같다 · 못 바꾼 것은 그대로다"를 약속한다(§3.6) |
| R9 | 중첩 언급 없음 | 카드 안에 버튼이 있으면 무엇을 먼저 만드나. API는 컴포넌트 안의 노드를 컴포넌트로 만들 수 없다 | **안쪽 먼저**(아이콘 → 버튼 → 카드). §3.7 |
| R10 | 7장 Avatar "Type=Image / Initial / Default"를 한 세트로 | 세 유형은 구조가 다르다(사진 채움 / 글자 / 아이콘) — 3장 Type C와 부딪힌다 | 특수 형태는 구조 지문이 아니라 **유형별 열쇠**(겉모양 · 비율 · 크기)로 묶는다. Figma는 한 세트 안 Variant끼리 구조가 달라도 된다 |
| R11 | 7장 Logo | 로고는 구조로 알아볼 방법이 없다(그냥 벡터 묶음이다) | 이름에 "logo"가 있거나 사용자가 고른 것만. 자동 인식 대상에서 뺀다 |
| R12 | 8-5 "별도 Typography Collection" · kebab 이름 `font-size-heading-h1` · "숫자만으로 이름 짓지 않는다" | 지금 플러그인은 Global(원시값 `font-size/16`) → Semantic(쓰임 `font-size/body/large`) 두 계층이고, 텍스트 스타일 이름은 KRDS 규칙이다(2026-11-09 사용자 확정). 정의서대로면 이름 체계가 둘이 된다 | **지금 구조를 유지**하고(Global은 숫자 · Semantic이 뜻 이름) 정의서의 "뜻 이름"은 Semantic이 맡는다. 이름 규칙을 바꿀지는 사용자 결정(§5 D7) |
| R13 | 8장 전체 | 스캔 · 묶기 · 등록 · 변수 연결 · 정수만 · 기존 스타일 재사용은 이미 있다. 같은 날 "텍스트 스타일 이름 다시 짓기"는 삭제하기로 했다(SC-D15) | 8장은 **지금 기능과의 차이만** 만든다(§3.11) |

## 2. Figma Plugin API 제약

"확인됨" = 타입 정의의 공식 설명에 있음. "실기 확인 필요" = 타입 정의에 없어 Figma에서 직접 돌려 봐야 함.

### 2.1 컴포넌트 · 세트 · 인스턴스

| 하려는 일 | API | 제약 | 확인 |
|---|---|---|---|
| 있는 프레임을 컴포넌트로 | `figma.createComponentFromNode(node)` | 속성 · 자식을 그대로 지킨다. **컴포넌트 · 세트 · 인스턴스 안에 있는 노드는 안 된다**(오류 `Cannot create component from node`) → 안쪽부터 만들어야 한다 | 확인됨 |
| 빈 컴포넌트 | `figma.createComponent()` | 자식 없는 컴포넌트를 만들 수 있다 → "완전히 빈 Variant"는 API로는 된다(정의서 2-4의 걱정과 다름). 다만 그 인스턴스는 아무것도 안 보인다 | 확인됨 |
| Variant 세트 | `figma.combineAsVariants(components, parent)` | 컴포넌트만 받고 1개 이상이어야 한다. **빈 세트는 없다**(`createComponentSet` 없음). 노드를 옮기는 일이라 부모 바꾸기 제약을 받는다 | 확인됨 |
| Variant 속성 | 컴포넌트 이름 `"Color=Primary, Size=Medium"` | 세트 안 컴포넌트의 이름이 곧 속성이다. 같은 조합이 둘이면 Figma가 충돌로 표시 → 같은 조합은 하나만 남기고 나머지는 인스턴스로 | 이름 형식 확인됨 · 충돌 표시는 실기 확인 필요 |
| 인스턴스 만들기 | `component.createInstance()` | — | 확인됨 |
| 인스턴스 → 다른 컴포넌트 | `instance.swapComponent(c)` | 덮어쓰기를 Figma 규칙으로 지켜 준다(규칙은 Figma가 바꿀 수 있다고 적혀 있음) | 확인됨 |
| Variant 고르기 · 속성 값 | `instance.setProperties({...})` | 글자 · 참거짓 · 인스턴스 교체 속성은 이름 뒤 `#id`가 붙는다 | 확인됨 |
| 속성 더하기 | `addComponentProperty(name, type, default)` | 종류: `BOOLEAN` · `TEXT` · `INSTANCE_SWAP` · `VARIANT` · **`SLOT`**(새 기능 — 인스턴스에서 자식을 넣고 뺄 수 있는 자리) | 확인됨 |
| 인스턴스가 덮어쓴 것 읽기 | `instance.overrides` | 덮어쓴 필드 목록(직접 덮어쓴 것만) | 확인됨 |
| 인스턴스에서 덮어쓸 수 있는 것 | 속성 대입 | 변경 추적 목록에 글자 · 채움 · 선 · 효과 · 모서리 · 여백 · 간격 · 방향 · 정렬 · 보임 · 크기 · 스타일이 있다. **자식 더하기 · 빼기 · 순서 바꾸기는 안 된다**(SLOT 예외). 자유 배치 프레임의 자식 x · y를 인스턴스에서 바꿀 수 있는지는 불확실 | 일부 확인 · **실기 확인 필요** |
| 메인 읽기 | `instance.getMainComponentAsync()` | 이 플러그인은 `dynamic-page`라 동기 `mainComponent`는 쓰기 전용 | 확인됨 |
| 되돌리기 단위 | `figma.commitUndo()` | 부르지 않으면 플러그인이 한 일이 한 덩어리로 묶인다. 실행 앞뒤로 불러 "실행 1번 = ⌘Z 1번" | 확인됨 |
| 큰 파일 읽기 | `figma.skipInvisibleInstanceChildren = true` | 인스턴스 안 숨은 레이어를 건너뛰어 훨씬 빨라진다. 대신 그 레이어는 못 읽는다 | 확인됨 |
| 미리보기 그림 | `node.exportAsync({ format: 'PNG' })` | 노드마다 그림을 뽑아 화면에 보낸다. 느리므로 개수 · 크기 상한 필요 | 확인됨(지금 타입 정의에 있음) |
| 사진 채움 | `ImagePaint` `imageHash` · `scaleMode`(`FILL` · `FIT` · `CROP` · `TILE`) · `imageTransform` | 사진은 채움이므로 인스턴스에서 채움을 덮어써 바꾼다. `CROP`은 `imageTransform`까지 옮겨야 자른 자리가 같다 | 확인됨 |
| 마스크 | `isMask` | 마스크는 **뒤따르는 형제 전부**를 가린다 — 구조 지문에 넣어야 하고 순서가 바뀌면 깨진다 | 확인됨 |

### 2.2 글자 스타일 · 변수

| 하려는 일 | API | 제약 | 확인 |
|---|---|---|---|
| 스타일에 변수 붙이기 | `textStyle.setBoundVariable(field, variable)` | 붙일 수 있는 필드는 **8개**: `fontFamily` · `fontStyle` · `fontWeight` · `fontSize` · `lineHeight` · `letterSpacing` · `paragraphSpacing` · `paragraphIndent`. 정의서 8-4 표와 같다 | 확인됨 |
| **Font Size**(보충) | `setBoundVariable('fontSize', v)` | 된다. 지금 코드도 이미 이렇게 한다(`src/lib/variables.ts` 1366). 성공 검증 = 붙인 뒤 `style.boundVariables.fontSize.id`가 그 변수이고 `style.fontSize` 값이 그대로인지 확인 | 확인됨 |
| 붙일 수 없는 것 | — | Text Case · Text Decoration · Leading Trim · 정렬 · 글자 색은 글자 변수 필드가 아니다(색은 채움 변수로 따로) | 확인됨 |
| 줄 높이 · 자간 | FLOAT 변수 | 변수는 숫자 하나뿐이라 단위를 담지 못한다 → **px일 때만** 붙인다. `%` · `AUTO`는 붙이지 않는다(정의서 8-4와 같음) | 확인됨(지금 코드 규칙과 같음) |
| 굵기 · 스타일 | `fontWeight`(FLOAT) · `fontStyle`(STRING) | 둘 다 붙일 수 있다. 둘이 어긋날 때(굵기 700 + 스타일 "Regular") Figma가 무엇을 따르는지는 불확실 | **실기 확인 필요** |
| 구간별 스타일 | `text.getStyledTextSegments([...])` · `setRangeTextStyleIdAsync(start, end, id)` | 한 글상자 안 구간마다 읽고 구간마다 스타일을 붙일 수 있다. 글꼴을 먼저 불러야 한다(`loadFontAsync`) | 확인됨 |
| 구간별 변수 | `setRangeBoundVariable(start, end, field, v)` | 된다 | 확인됨 |

## 3. 기술 설계 제안

### 3.1 흐름 — 읽기와 바꾸기를 나눈다

```
읽기(파일을 바꾸지 않음)
  ① 범위의 프레임을 걷어 "그림 없는 사본"(순수 데이터)으로 옮긴다
  ② 구조 지문 · 모양 값 계산
  ③ 묶기: 구조 → 가족 → Type A · B · C
  ④ Variant 축 추론 · 이름 제안 · 누락 조합 계산
  ⑤ 계획(plan) = 만들 컴포넌트 · 세트 · 바꿀 프레임 목록
화면: 계획을 보이고 사용자가 끄고 켜고 이름을 고친다
바꾸기(계획대로만)
  ⑥ 안쪽 묶음부터: 메인 만들기 → 세트로 묶기 → 프레임을 인스턴스로 → 비교 검증 → 다르면 그 프레임만 되돌림
  ⑦ 결과 수 · 실패 · 확인 필요 목록
```

- ①–⑤는 Figma 객체가 아닌 **순수 데이터 + 순수 함수**로 만든다. 단위 테스트로 묶기 규칙을 고정할 수 있다(옛 기능에서 가장 흔들린 부분).
- ⑥은 계획에 적힌 노드 id만 만진다. 읽은 뒤 파일이 바뀌었으면(노드가 없어짐 · 지문이 달라짐) 그 묶음은 건너뛰고 알린다.

### 3.2 구조 지문과 모양 값

- **구조 지문**(같으면 "같은 구조"): 노드 종류 · 자식 순서 · 깊이 · 오토 레이아웃 유무와 방향 · 마스크 · 자르기(clip) · 안쪽 인스턴스의 메인 컴포넌트. **넣지 않는 것**: 레이어 이름 · 글자 내용 · 색 · 크기 · 여백 값 · 사진 · 숨김 여부(숨긴 자식은 구조에 넣되 "숨김"을 모양 값으로).
- **모양 값**(같은 구조 안에서 비교): 크기(폭 · 높이 · 크기 방식 Hug/Fill/Fixed) · 여백 · 간격 · 정렬 · 모서리 · 채움 · 선 · 효과 · 글자 속성 · 불투명도.
- **내용 값**(덮어쓰기로 갈 것): 글자 내용 · 사진(`imageHash` · 자르기) · 아이콘 그림.
- 아이콘처럼 벡터만 든 작은 프레임은 안을 펼치지 않고 **잎 하나**로 본다(그림이 달라도 구조가 같게). 지금 이름 정리가 쓰는 판정(`isIconFrame`)을 그대로 쓴다.

### 3.3 묶기 — Type A · B · C와 "덮어쓰기냐 Variant냐"

1. 구조 지문이 같은 프레임을 모은다(2개 이상).
2. **가족 나누기**(R3): 같은 구조 안에서도 다음이 크게 다르면 다른 가족이다 — 오토 레이아웃 방향 · 루트 채움이 있고 없음 · 크기 차이가 정해 둔 비율을 넘음 · 부모 맥락(목록 안 줄인지, 혼자 있는 버튼인지). 임계값은 실기 파일로 정한다. 확신이 낮으면 "확인 필요"로 표시하고 기본은 **합치지 않음**.
3. 가족 안에서 모양 값이 모두 같으면 **Type A** — 메인 1 + 인스턴스.
4. 모양 값이 다르면 **Type B 후보**. 다른 속성마다 본다:
   - 값 종류가 적고(제안: 축마다 2–6개) 같은 값이 여러 프레임에 되풀이됨 → **Variant 축**.
   - 프레임마다 값이 거의 다 다름(제안: 값 종류 ÷ 프레임 수 > 0.5) → **덮어쓰기**(인스턴스마다 다른 값으로 두고 축으로 만들지 않음).
   - 함께 움직이는 속성(높이 · 여백 · 글자 크기가 늘 같이 바뀜)은 축 하나(`Size`)로 합친다.
5. 구조가 같은 프레임이 없으면 **Type C** — 목록에만(R5).

### 3.4 Variant 축 · 값 이름 (R2)

| 축 | 무엇이 다를 때 | 값 이름 제안 순서 |
|---|---|---|
| Size | 높이 · 여백 · 글자 크기가 함께 | 작은 순서로 Small · Medium · Large(4개 이상이면 XS · S · M · L · XL), 아이콘은 숫자(16 · 20 · 24) |
| Color | 루트(또는 주된 자식) 채움 · 글자 색 | 붙은 변수 이름의 끝 마디(`color/primary` → Primary) → 없으면 색 이름(blue-600) |
| Style | 채움이 있고 없음 · 선이 있고 없음 | 채움만 = Filled · 선만 = Outlined · 둘 다 없음 = Ghost(이건 모양으로 판정할 수 있다) |
| Alignment | 주축 · 교차축 정렬 | Left · Center · Right |
| State | **자동으로 알 수 없음** | 레이어 이름에 hover · pressed · selected · disabled · active가 있을 때만. 없으면 이 축을 만들지 않는다 |
| Shape(특수) | 모서리가 반지름 = 절반 / 0 / 그 사이 | Circle · Square · Rounded |
| Ratio(특수) | 폭 ÷ 높이 | 1:1 · 4:3 · 16:9(가까운 표준 비율, 벗어나면 "w:h") |

모든 이름은 미리보기에서 사용자가 고칠 수 있고, 고친 이름은 다시 실행해도 유지한다(§3.9).

### 3.5 누락 Variant (R7)

- 계산: 축 값의 모든 조합 − 있는 조합.
- 만들기: **기준 Variant를 복제**해 그 조합 이름을 준다(정의서의 대안 방식). 빈 컴포넌트(`createComponent()`)도 되지만 인스턴스가 아무것도 안 보여 쓸모가 적다.
- "누락" 표시(컴포넌트 안 모습은 건드리지 않는다): ① 컴포넌트 설명(description)에 "⚠ 자동으로 만든 자리 — 디자인 필요" ② 플러그인 표시 데이터 ③ 세트 안에서 있는 Variant와 떨어진 줄에 놓기. 눈에 보이는 표시(점선 · 딱지)를 컴포넌트 안에 넣으면 인스턴스에도 보이므로 넣지 않는다.
- 기준 고르기: 빠진 조합과 축 값이 가장 많이 겹치는 Variant.
- 상한(제안): 한 세트에서 한 번에 24개까지, 그보다 많으면 고른 것만.

### 3.6 인스턴스로 바꾸기 — 화면을 지키는 절차 (R8)

프레임 하나를 바꾸는 순서:

1. **앞 모습 기록**: 자기와 모든 자손의 절대 위치 · 크기, 글상자 줄 수, 채움 · 선 · 효과, 글자 내용.
2. 인스턴스를 만들어 **같은 부모 · 같은 순서 자리**에 넣는다. 위치 · 회전 · 제약 · 오토 레이아웃 자식 속성(늘어남 · 정렬 · 절대 위치)을 옮긴다.
3. **덮어쓰기 옮기기**: 구조가 같으므로 두 나무를 같은 길로 걸으며 다른 값만 넣는다 — 글자(글꼴 먼저 불러옴) · 채움(사진 포함) · 선 · 효과 · 모서리 · 여백 · 간격 · 보임 · 크기.
4. **뒤 모습과 비교**: 위치 · 크기 차이 0.5px 이하, 줄 수 같음, 채움 같음.
5. 다르면 인스턴스를 지우고 **원본을 그대로 둔다** → "확인 필요" 목록에 이유와 함께. 같으면 원본을 지운다.

- 원본은 5번이 끝날 때까지 지우지 않는다.
- 미리 아는 한계: 자유 배치(오토 레이아웃 아님) 프레임에서 자식 위치가 서로 다르면 인스턴스로 못 맞출 수 있다(§2.1 실기 확인) → 그런 차이는 Variant로 보내거나 제외한다.
- 옛 기능에서 배운 것(보관 명세 참고): 컴포넌트로 바꿀 때 사진 자르기 · 글 줄바꿈이 바뀜(QA 5 결함 2), 90° 돌린 선이 하나만 처리됨, 안쪽 사진 · 아이콘을 감싸며 레이어 수가 늘어남(`docs/qa/backlog.md`).

### 3.7 중첩 — 안쪽 먼저 (R9)

- 묶음을 깊이 순으로 정렬해 **잎 쪽(아이콘 · 아바타 · 버튼)부터** 만든다. 바깥 묶음의 구조 지문은 안쪽이 "컴포넌트 X의 인스턴스"로 바뀐 것을 기준으로 다시 계산한다(계획 단계에서 가상으로 바꿔 계산 — 파일은 아직 안 바뀜).
- 이유: 바깥을 먼저 컴포넌트로 만들면 안쪽 노드는 "컴포넌트 안"이 되어 `createComponentFromNode`가 실패한다(§2.1).

### 3.8 특수 형태 — 에셋과 그릇을 나눈다 (7장)

| 유형 | 알아보는 법(제안) | 그릇(컴포넌트) | 에셋(바뀌는 내용) | 확신 |
|---|---|---|---|---|
| Icon | 벡터 · 도형 연산만 든 작은 정사각 프레임(지금 `isIconFrame`) | 아이콘 그림마다 컴포넌트 하나(`Icon/이름`). 같은 그림 · 다른 크기는 Size Variant | 아이콘을 담는 쪽(버튼 등)에 **인스턴스 교체 속성**(`INSTANCE_SWAP`) | 높음 |
| Image | 보이는 사진 채움이 있는 도형 · 프레임 | 비율 · 모서리 · 표시 방식(Cover = `FILL`, Contain = `FIT`)이 같은 것끼리 | 사진 = 채움 덮어쓰기(`imageHash` + 자르기) | 높음 |
| Avatar | 1:1 비율 · 원 또는 둥근 사각 · 작은 크기(제안 96px 이하) · 안에 사진 / 글자 1–2자 / 아이콘 | 한 세트: Type(Image · Initial · Default) × Size × Shape × Status | 사진 · 이니셜 글자 | 중간 — 작은 정사각 사진과 구별이 애매 |
| Thumbnail | 사진 영역 + 그 위 겹친 자식(오버레이 · 재생 버튼 · 딱지) | 일반 구조 묶기와 같음(사진은 내용 값) | 사진 | 중간 |
| Badge | 작은 높이 · 알약 모서리 · 글자 1개 | 일반 구조 묶기 + Color 축 | 글자 | 중간 |
| Logo | 구조로 알 수 없음(R11) | 사용자가 고르거나 이름에 logo | 그림 | 낮음 — 자동 인식 제외 제안 |

- 유형 판정은 확신 정도와 함께 보이고, 사용자가 유형을 바꿀 수 있다.
- "서로 다른 아이콘 그림을 한 컴포넌트로 합치지 않는다"(7-1 B)는 그대로 지킨다 — 그림 지문(벡터 길 데이터의 해시)이 같을 때만 같은 아이콘이다.

### 3.9 다시 실행해도 안전하게

- 만든 컴포넌트에 표시 데이터(구조 지문 · 가족 열쇠 · 사용자가 고친 이름)를 적는다.
- 다시 읽을 때: 이미 인스턴스인 프레임은 그 메인의 가족으로 센다(다시 만들지 않음). 새 프레임이 있는 가족과 같으면 **있는 컴포넌트의 인스턴스로** 바꾼다. 있는 세트에 없는 조합이면 Variant를 더한다.
- 이름이 같은 컴포넌트가 이미 있으면(사용자가 만든 것) 덮어쓰지 않고 묻는다.

### 3.10 되돌리기 · 성능

- 실행 앞뒤 `figma.commitUndo()` — 실행 한 번이 ⌘Z 한 번. 묶음 단위로 끊어 진행률을 보이고 묶음 사이에서 취소할 수 있다(끝난 묶음은 남는다).
- 읽기는 `skipInvisibleInstanceChildren`를 켜고 한 번만 걷는다. 지문은 문자열 해시라 노드 수에 비례한다. "현재 페이지 전체"는 노드 수 상한과 진행률을 둔다(지금 연결의 300곳 나눔과 같은 방식).
- 미리보기 그림은 묶음마다 대표 1장 + 펼쳤을 때만 나머지, 작은 크기로.

### 3.11 타이포그래피(8장) — 지금 기능과의 차이

지금 플러그인: 만들기 화면 Text Style 탭 · 값을 직접 고르기 › 타이포 — 글자 읽기 → 묶기 → 텍스트 스타일 등록(KRDS 이름) → 변수 연결 → 글상자에 적용.

| 정의서 | 지금 | 할 일 |
|---|---|---|
| 같은 속성끼리 묶어 스타일 등록 · 기존 스타일 재사용 | 있음 | — |
| Font Size 정수만 변수 연결 | 있음(`isIntegerSize` · 소수 크기는 만들지 않는 줄로 보임) | — |
| Line Height · Letter Spacing px만 · `%` 제외 | 있음(추정 — 코드에 PERCENT 처리 있음, 규칙 문장 대조 필요) | 대조 확인 |
| Font Family 연결 | 있음 | — |
| **Font Style · Font Weight · Paragraph Spacing · Paragraph Indent 연결** | 없음(굵기 변수는 만들지만 스타일에 붙이는지 확인 필요) | 새로 — API는 지원(§2.2). 굵기 + 스타일 어긋남은 실기 확인 |
| **Mixed Style 구간별 등록 · 적용** | 불확실 — 확인 필요 | 구간 API는 지원 |
| 스타일 이름 `Typography/Heading/H1` | KRDS 규칙 이름(`docs/text-style-krds.md`) | **사용자 결정**(§5 D7) |
| 변수 이름 `font-size-heading-h1` · 별도 Typography 컬렉션 | Global `font-size/16` + Semantic `font-size/body/large` | **사용자 결정**(§5 D7) — 제안: 지금 구조 유지 |
| 값이 다른 같은 이름 변수는 덮어쓰지 않고 확인 요청 | 지금은 같은 이름 · 같은 값만 재사용(다른 값이면 꼬리 이름) | 확인 화면이 필요한지 결정 |
| 적용 뒤 줄바꿈 · 높이 변화 감지 | 없음 | 새로 — §3.6의 앞뒤 비교를 같이 씀 |
| 전용 분석 화면(TextNode 수 · 조합 수 · 재사용 수 · 제외 수 …) | Text Style 탭에 줄 목록만 | 새로 — 도구 탭 › 텍스트 스타일 화면(로드맵 8번)에 넣는 것을 제안 |

### 3.12 화면

정의서 4장의 5단계를 이 플러그인의 틀로 옮긴 제안이다(대략 시안은 방향이 정해진 뒤).

- 들어가는 곳: 선택 탭 첫 화면 진행 줄(SC-D6) 아래 "그 밖"의 [컴포넌트 →] 또는 도구 탭.
- 한 화면 안에서: **범위**(선택 / 선택한 프레임 안 / 이 페이지) → [분석] → **요약 줄**(프레임 · 묶음 · 만들 컴포넌트 · Variant · 누락 · 따로 볼 프레임) → **묶음 목록**(일반 / 특수 형태 탭, 묶음마다 미리보기 그림 · Type · 축과 값 · 프레임 수 · 스위치) → 아래 고정 줄에 **옵션**(인스턴스로 바꾸기 · 누락 Variant 만들기)과 [n개 만들기] → **결과**(만든 수 · 확인 필요 목록 [선택]).
- 카드 안 카드 금지 규칙에 맞춰 묶음 목록은 트리 줄(§2.7 모양)로.

### 3.13 컴포넌트 속성(9장) — 글자 · 인스턴스 교체 · 보임

**API 확인(타입 정의 1.129.0):**

| 정의서 | API | 확인 |
|---|---|---|
| 속성 만들기 · 돌려받은 이름(`이름#id`)을 그대로 씀(9-9) | `addComponentProperty(name, type, defaultValue, options)` — 돌려주는 값이 id가 붙은 속성 이름 | 확인됨 |
| 글자 속성 → 글상자 `characters` | `node.componentPropertyReferences = { characters: 속성이름 }` | 확인됨 |
| 인스턴스 교체 속성 → 안쪽 인스턴스 `mainComponent` | `{ mainComponent: 속성이름 }` · 기본값은 컴포넌트 id | 확인됨 |
| 보임 속성 → `visible` | `{ visible: 속성이름 }` | 확인됨 |
| 연결할 수 있는 것은 이 **셋뿐** | `'visible' \| 'characters' \| 'mainComponent'` — 컴포넌트 · 인스턴스의 **하위 레이어**만(루트는 안 됨) | 확인됨 |
| 교체 후보 목록 | `preferredValues: { type: 'COMPONENT' \| 'COMPONENT_SET', key }[]` — **key로 적는다**(id 아님) | 확인됨 |
| Variant 세트의 속성 | 속성은 **세트에** 만든다(Variant마다 따로가 아님). 같은 속성을 Variant마다 같은 역할의 레이어에 연결해야 Variant를 바꿔도 값이 이어진다 | 세트에 만든다는 것은 확인됨 · 값이 이어지는 동작은 실기 확인 필요 |
| 컴포넌트 전체 바꾸기(9-6) | `instance.swapComponent(c)` — 덮어쓰기를 Figma 규칙으로 지킴 | 확인됨 |

**옛 기능과의 관계:** 옛 [등록]도 속성 노출(글자 · 인스턴스 교체)을 했다(`code.ts` `exposeProperties`). 규칙은 새로 정하되 연결 절차는 참고한다(§6).

**설계 제안:**

- **언제:** 컴포넌트를 만든 바로 뒤, 원래 프레임을 인스턴스로 바꾸기 **전에** 속성을 만든다. 그러면 인스턴스로 바꿀 때 글자는 속성 값으로(`setProperties`), 아이콘은 교체 속성으로 넣을 수 있어 덮어쓰기와 속성이 따로 놀지 않는다.
- **글자 속성 대상 고르기(9-2):** 가족 안 프레임들 사이에서 **글자가 실제로 다른 글상자**는 바뀌는 글자다 → 자동 대상. 모든 프레임에서 글자가 같은 글상자는 고정 글자일 가능성이 크다 → 기본 꺼짐(목록에는 보임). 프레임이 하나뿐이면 판단할 근거가 없으므로 이름 · 자리로 추정하고 "확인 필요".
- **속성 이름:** 지금 이름 정리가 붙이는 역할(제목 · 설명 · 라벨 등)을 쓴다 — `Title` · `Description` · `Label`. 같은 역할이 둘이면 자리로 가른다(`Title` · `Subtitle`, 그래도 겹치면 번호). 미리보기에서 고칠 수 있다.
- **혼합 서식 글상자:** 글자 속성으로 내용을 바꾸면 구간 서식이 어떻게 되는지는 **실기 확인 필요**. 기본은 자동 연결하지 않고 따로 표시(정의서 9-2 주의사항과 같음).
- **인스턴스 교체 대상(9-3 · 9-4):** 안쪽 인스턴스가 §3.8의 Icon · Avatar · Image 유형이면 대상. 후보 목록(`preferredValues`)은 **같은 유형 + 같은 크기 묶음**의 컴포넌트만(24px 아이콘 자리에 16px 아이콘을 넣지 않음). 이 플러그인이 만든 컴포넌트는 유형 · 크기를 표시 데이터로 알고, 사용자가 만든 컴포넌트는 이름 경로(`Icon/…`)와 크기로 추정 → 애매하면 후보에 넣지 않고 "확인 필요".
- **보임 속성(9-5):** 가족 안에서 **어떤 프레임에는 있고 어떤 프레임에는 숨겨진(또는 없는)** 자식이 자동 대상이다. 다만 "없는" 경우는 구조가 다른 것이라(§3.3) 먼저 "숨긴 자식으로 맞출 수 있는 구조 차이"로 묶을지 정해야 한다(§5 D11). 모든 프레임에 늘 보이는 자식은 기본 꺼짐.
- **이미 있는 속성:** 같은 레이어에 연결된 속성이 있으면 다시 만들지 않는다. 이름만 같은 다른 속성이 있으면 덮어쓰지 않고 다른 이름을 제안한다.
- **검증(9-9):** 연결 뒤 ① `componentPropertyDefinitions`에 그 속성이 있는지 ② 레이어의 `componentPropertyReferences`가 그 이름인지 ③ 시험 인스턴스 하나를 만들어 `setProperties`로 값을 바꾼 뒤 레이어에 반영되는지 보고 지운다.
