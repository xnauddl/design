작성: Claude(claude.ai 대화) → 사용자 확인 → Claude Code가 `docs/ia-v3.md`에 반영(명세 먼저, 코드 대조 검토 뒤 구현 — CLAUDE.md 순서).
상태: **초안(사용자 확인 전)**. 숫자(자리 줄 200 · 묶음 300)는 제안값이며 실기 확인 뒤 바꿀 수 있다.

## 0. 결정 기록에 넣을 줄 (§0 "결정 기록 (2026-11-05)")

| 항목 | 결정 |
|---|---|
| 연결 후보 상한 (QA #4 불합격 2) | 찾기와 연결에는 상한을 두지 않는다. 상한은 **보여주기**에만 둔다 — 카드 안 자리 줄 200줄 + "외 n곳". 연결은 300곳씩 나눠 실행하고 진행률을 보인다. [취소]는 연결 중에 두지 않는다(2026-11-04 결정 유지). `RESULT_CAP` 600은 없앤다. |

## 1. 왜 바꾸나

- 256노드 웹페이지 1장에서 후보 618곳 → 상한 600에 걸려 푸터 6개 글자(18곳)가 조용히 빠졌다(QA #4). 사용자는 "(찾음 600)"만 보고 전부 연결된 줄 안다.
- 상한을 그냥 없애면: 후보 1곳 ≈ 150~250B → 1만 곳이면 메시지 1~2.5MB, 자리 줄 1만 개 DOM, `setBoundVariable` 1만 번(≈10~20초, Figma 메인 스레드 멈춤). 그래서 "찾기는 전부, 보여주기는 줄여서, 연결은 나눠서".

## 2. §4.6에 추가할 절 — "찾기·연결의 수"

**찾기**
- 선택 안의 모든 자리를 센다. 상한 없음. (찾음 {n})의 n은 실제 전체 수다.
- 코드→UI 메시지(`APPLY_RESULT`)는 자리를 낱개로 보내지 않고 **변수별 묶음**으로 보낸다: `groups: { variableId, variableName, tier, type, value, places: number, nodeIds: string[], fields: Record<nodeId, string[]> }[]`. 자리 줄에 필요한 레이어 이름은 `nodes`(id→이름·종류)로 한 번만 보낸다. 1만 곳 기준 메시지 ≈ 300KB.
- `candidateTotal`·`resultCapped`(상한 잘림 표시)는 지운다. i18n `apply.resultCapped` 삭제.

**보여주기(카드)**
- 카드는 변수마다 하나, 전부 보인다(필터는 지금처럼 7개 이상일 때).
- 카드를 펼치면 자리 줄을 **200줄까지** 그리고, 넘으면 마지막 줄에 "외 {n}곳 · 레이어 선택으로 보기" (누르면 그 변수의 자리 레이어를 캔버스에서 선택 — 지금의 "사용 레이어 선택"과 같은 동작, 200개 상한 문구 재사용). 접힌 카드는 자리 줄을 그리지 않는다(지금과 같음).
- 카드 머리의 "{k}곳"은 실제 수다.

**연결**
- 켠 변수의 자리를 **300곳씩** 나눠 `setBoundVariable`을 호출한다. 묶음 사이에 `await` 한 번(이벤트 루프 양보)을 둬 진행률 메시지가 UI에 닿게 한다.
- 진행 줄: "연결 중… {done}/{total}" (지금 "연결 중…"에 숫자 추가). 최소화 창의 진행 테두리는 `done/total` 비율(§4.9 "진행률이 있으면 그 비율만큼"과 같음).
- [취소]는 두지 않는다(2026-11-04 결정 유지 — 연결은 중간에 멈추지 않는다). 창을 닫으면 그때까지 연결된 상태로 남고, 되돌리기는 ⌘Z 한 번(`commitUndo`는 마지막 묶음 뒤 한 번만).
- 연결 직전 다시 확인(그 사이 붙음·스타일·값 다름·사이 간격 자동·소수 선 두께)은 묶음마다 그 묶음 자리만 한다(지금 규칙 그대로).
- 결과 카드 "🔗 {n}곳 연결됨"의 n은 실제 연결 수. 건너뜀은 지금처럼 (건너뜀 {m} ▸).

**크기 안내(상황 안내 줄, 선택 때)**
- 선택의 하위 레이어가 3,000개를 넘으면 상황 안내 줄에 "선택이 커서 찾기에 시간이 걸려요 · 페이지를 나눠 선택하면 빨라요"를 띄운다(막지 않는다). 300개 자동 읽기 규칙(§4.1)은 그대로다.

- 부록 A.3 1438 "상한 안내는 칩 툴팁" → 삭제.
