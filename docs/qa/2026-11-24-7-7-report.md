## 항목별

### ① 큰 선택 — 개수 없음 · [읽기] 뒤 "선택을 읽는 중…"에 멈춤

- **개수 없음 [확인]:** 큰 선택 카드는 제목 `list.big`과 [읽기]뿐이다(`ui.ts` 8788–8796). 그런데 `SELECTION_STATE`가 이미 레이어 수 `scanned`(1,500에서 멈추면 `capped`) · 연결할 수 있는 레이어 수 `bindable` · 붙은 수 `bound`를 싣고 온다(`code.ts` 585–617). UI가 `bindable` · `capped`를 버린다(`ui.ts` 5997 · 6056). → 읽기 전에도 "레이어 1,500개 이상"처럼 보일 수 있다. "값 n곳"은 찾기가 돌아야 나온다.
- **멈춤 [확인 — 헤드리스 재현]:** [읽기]는 쓰는 변수 읽기(`SCAN_USAGE`) · 찾기 · 만들기 카드 추출을 함께 보낸다. 로컬 변수 0개면 첫 카드가 `usageReady`를 기다린다(`ui.ts` 8800–8803 — `if (localZero) { mcKick(); if (!usageReady) { put(reading()); … return; } }`). 이 분기에 실패 모습이 없다.
  - **경우 1 — 쓰는 변수 읽기 오류:** `usageFailedFor`만 세우고 다시 그리지 않으며(`ui.ts` 2807–2810), 다시 읽기는 300개 규칙 · `usageFailedFor`에 막힌다 → 영원히 멈춤.
  - **경우 2 — 늦거나 안 옴:** 오면 바로 풀린다. 로컬 0개 파일은 쓰는 변수가 모두 라이브러리 변수일 수 있어 `collectUsage`(`code.ts` 465–472)가 id마다 차례로 기다려 느릴 수 있다 **[추정]**.
  - **경우 3 — 다른 작업 중에 [읽기]:** 찾기가 미뤄지는데 "사용자가 누른 읽기"라는 표시가 없어, 다음 시도가 300개 규칙에 막힌다(`ui.ts` 8304–8305). 로컬이 있는 파일에서도 멈춘다.
  - 실기가 경우 1인지 2인지는 로그가 없어 모른다 — **멈출 때 아래 상태 줄에 오류 경고가 떴는지** 알면 가린다(떴으면 1, 안 떴으면 2).
  - 재현 스크립트: 세션 임시 폴더 `big-read.mjs` · `big-read2.mjs`(`verify-bind-flow` 방식, 무료 · scanned 1500 · capped). 기존 verify 31번(정상 흐름)은 통과.

### ② 변수를 만든 뒤 — 만든 수가 없고 "후보가 바뀌었어요"

- **[확인]** 헤더 [변수 만들기] 실행이 끝나면 첫 화면으로 돌아가며 상태 줄에 "Global 9개 · …"(`makeDoneText`)를 띄운다(`ui.ts` 4013–4035). 곧이어 조용한 다시 찾기 응답이 같은 상태 줄을 **"후보가 바뀌었어요 · a곳 추가 · b곳 제외"로 덮어쓴다**(`ui.ts` 2467). 같은 자리라도 붙을 변수가 바뀌면 추가 1 + 제외 1로 세므로(`bindGroups.ts` 52) 만든 직후에는 거의 늘 뜬다.
- 카드 1 제목은 늘 "변수 없는 값 {n}곳"이고, "새로 만들 값 {k}곳"은 k = 0이면 말없이 빠진다(`ui.ts` 8925 · 8947). 만든 일을 카드에 남기는 문장(`mkc.titleMade`)은 무료 만들기 카드의 ＋만들기 길에만 있다(`ui.ts` 8549–8556 · 8588).
- 작업 직후에도 "후보가 바뀌었어요"가 뜨는 것은 명세(ia-v3 §4.6 ⑧ "돌아올 때 조용히 다시 계산" · ia-v4 §7 "플러그인 작업 직후")보다 넓다 **[추정]**.
- **묶을 곳:** ROADMAP 9번(이미 결정 — "다 됨"이어도 첫 화면으로 바로 가지 않고 결과 화면, **아직 구현 안 됨** `ui.ts` 4032–4033) + 작업 직후 `candChanged`를 띄우지 않기.

### ③ 잠긴 "선택에서 변수 만들기"가 링크 파랑 · 손가락 커서

- **[확인] CSS 결함.** 잠금은 `aria-disabled="true"`(`ui.ts` 6031 · `applyLock`)로 걸리고 공통 규칙이 회색 · `not-allowed`로 바꾸려 하지만, 같은 세기(특이도)인 `button.link`(파랑 · `cursor: pointer`)와 `button.link-btn`이 **뒤에 선언돼** 이긴다(`ui.html` — 잠금 규칙 뒤 `button.link`). 누르면 상태 줄에 "선택이 없어요"가 뜨기는 한다(`onLockedActivate`).
- **고칠 곳:** `button.link[aria-disabled="true"]`(· `.link-btn`) 규칙 하나 — 다른 링크 버튼에도 같은 결함이 있을 수 있어 함께 본다. `docs/qa/backlog.md` "잠겨도 글자가 진한 작은 버튼"과 같은 뿌리.

### ④ 숫자 변수 줄의 `#` 칸

- **[확인]** 색이 아닌 값의 `#` 표시는 사양이다(트리 줄 TR-D3 "색이 아니면 종류 표시 `#`", 첫 화면 만들기 카드 `ui.ts` 8674).
- "숫자는 아래 줄"은 어느 화면인지에 따라 다르다 — 첫 화면 만들기 카드(`.mk-row`)는 한 줄 flex라 그렇게 나오지 않는다. **화면 확인 필요**(스크린샷). 견본 자리가 비어 보이는 문제는 9-1 보이는 모양으로.

### ⑤ 만들기 Global 탭 개수 ≠ [변수 N개 만들기]의 N

- **[확인]** 탭 개수 = 그 탭의 **모든 줄 수**(`ui.ts` 3617), N = 새로 만들거나 값을 맞출 Global(`created + updated`, `ui.ts` 3475 · 3866). 늘 탭 ≥ N이며, 갈리는 경우: 글자 줄(기본 끔) · #173 뒤 라이브러리와 같은 값 · 이미 다 붙은 값(기본 끔) · "있는 변수" · "있는 변수 · 용도 더함"(켜져 있어도 N에서 빠짐) · 잠긴 직접 만든 변수 · 사용자가 끈 줄.
- 명세(ia-v4 §4.3)상 **의도한 차이**지만 화면은 설명하지 않는다. "있는 변수"로 **연결만 하는 몫은 어디에도 수가 없다**.
- **묶을 곳:** 7-12 B-8("탭 · 만들 수 · 버튼 숫자 셋").

### ⑥ 글자 묶음이 빠졌다는 안내 없음

- **[확인]** 글자 줄 기본 끔은 결정대로 구현됐다(ia-v4 §4.3 · B.32, `ui.ts` 3358). 안내는 명세에도 코드에도 없다 — 다 됨 줄(`makeDoneText`)에도 끈 줄 이야기가 없다.
- **묶을 곳:** 7-12 B(숫자 셋을 정할 때 "끈 줄은 이번에 만들지 않아요"를 함께) — 정할 것 2.
