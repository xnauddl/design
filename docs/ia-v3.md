## 1. 왜 바꾸나 (문제)

1. **나누는 기준이 섞여 있었다.** 그래서 "변수를 보고 싶다"는 목적 하나에 갈 곳이 3곳이었다.
   - 피드백 1: "변수가 있는데 '만들기'에 들어가 없다는 걸 확인한 뒤 '적용'으로 이동했다."
   - 피드백 2: "무엇이 어디에 연결됐는지 알 수 없다."
   - 피드백 3: "[변수]가 적용 탭 안에서 열리는 건가?"
2. **우회로가 계속 늘었다.** 배너 2개, 링크 1개, 탭 이동 6곳.
3. **같은 데이터를 두 번 그렸다.** 연결 현황과 변수 관리 사용처가 같은 함수를 쓴다.
4. **노트북 화면을 너무 가렸다.** 13인치에서 높이의 약 75%를 가렸다. 510이면 약 58%다(추정). 최소화하면 140×104 작은 창만 남는다.
5. **역할이 사용자 의도와 반대였다.** 사용자 원칙은 "플러그인 = 쓰인 변수를 보고 변수를 고치는 도구, 레이어에 붙은 변수를 바꾸는 일 = 피그마"다. 그런데 지금은 레이어 연결을 바꾸는 기능만 있다. v3는 이미 붙은 연결을 바꾸는 기능(일괄 교체)을 없애고, 변수가 없는 값에 새로 붙이는 일만 사용자가 버튼을 눌러 할 수 있게 남긴다(§2.11).

## 2. 원칙

1. **탭 = 다루는 대상.**
   - **변수 탭:** 파일의 변수를 보고 만든다. 만드는 일(시작 화면, 만들기)은 선택한 레이어를 읽는다.
   - **레이어 탭:** 선택한 레이어에 변수를 연결하고, 이름을 정리하고, 컴포넌트로 만든다.
   - **설정 탭:** 자주 안 바꾸는 값과 라이선스.
2. **보기는 변수 탭, 연결하는 작업은 레이어 탭.**
3. **유료/무료는 탭이 아니라 컨트롤에서 표시한다.**
   - 있는 자산을 쓰는 일은 무료, 새로 만드는 일은 유료다.
   - 잠긴 컨트롤과 전제가 안 맞는 컨트롤은 `aria-disabled`로 둔다. 포커스는 받는다.
   - **모양:** 글자 `--muted`, 주 버튼은 `--surface-2` 바탕 + `--text-2` 글자, hover 없음, `cursor: not-allowed`, opacity는 쓰지 않는다.
   - **두 사유를 모양으로 구분한다:** 유료 잠금은 라벨 앞에 🔒를 붙이고, 전제 미충족(선택 없음 등)은 🔒 없이 흐리게만 한다.
   - **둘 다 해당하면 유료 잠금이 먼저다:** 🔒를 붙이고, 누르면 유료 사유를 띄운다. 전제 사유는 잠금이 풀린 뒤에 보인다.
   - **누르면** 동작 대신 공통 상태 줄에 사유를 띄운다.
     - 유료: "유료 기능이에요 · 설정 › 라이선스에서 풀 수 있어요 [라이선스 →]"
     - 선택 없음: "선택이 없어요 — 캔버스에서 레이어를 선택하세요"
   - 툴팁은 기존 설명 뒤에 " · 유료 기능 · 설정 › 라이선스"를 붙인다.
4. **변수 관리 범위.**
   - v3: 보기 · 복사 · 사용 레이어 선택 · 상세(읽기)
   - PR 3.5: 상세 팝업에서 별칭 대상 · 이름(전체 경로) · 값 고치기(§4.4 고치기)
   - 하지 않음: 변수 삭제, 레이어 연결 일괄 교체
   - 변수 삭제를 하지 않는 이유: 이 파일을 라이브러리로 쓰는 다른 파일의 연결이 끊기고, 그건 ⌘Z로 되돌릴 수 없다.
5. **화면과 스크롤 (#18 유지).**
   - 패널 전체가 스크롤한다. 목록마다 스크롤 상자를 두지 않는다.
   - **예외 (2026-11-03 결정 B):** 변수 탭 목록의 왼쪽 사이드바는 머리줄 아래에 고정하고, 창 높이를 넘으면 사이드바만 따로 스크롤한다. 오른쪽 목록은 패널 스크롤이다.
   - **예외 (PR 3.5):** 상세 팝업은 안에서 스크롤하고 단추 줄을 아래에 고정한다. 별칭 고르개 목록은 최대 200px에서 따로 스크롤한다(§4.4 고치기).
   - **고정(sticky)하는 것**
     - 지금처럼: 탭 바, 공통 상태 줄(아래)
     - **새로:** 카드의 버튼 줄(`.toolbar`), 변수 목록의 사이드바와 오른쪽 목록 머리, 레이어 › 연결의 단계 표시 + 버튼 줄
     - 고정은 최대 두 겹이다. 위쪽은 탭 바 아래에 붙는다.
   - 버튼 줄은 카드 제목 아래, 내용보다 위에 둔다(지금 위치). 고정했으므로 각 화면의 주 버튼은 스크롤해도 보인다.
   - 페이지 가로 스크롤은 0이다.
6. **상태 기억.**
   - 플러그인이 열려 있는 동안 기억하는 것: 탭별 하위 화면, 단계, 스크롤, 변수 사이드바의 고른 항목·펼친 컬렉션, 연결 화면에서 펼친 카드, 고른 모드, 검색어.
   - 다시 열면 모두 처음 상태다.
7. **피그마 기능은 검증된 것만 쓴다.** 레이어 변경 감지(`nodechange`)는 쓰지 않는다(§12.2).
8. **테마:** 라이트 고정.
9. **용어.**
   - 사용자에게 보이는 말은 **연결**("바인딩", "붙이기" 아님), **건너뜀**("스킵" 아님), **유료 기능**("Paid" 아님).
   - 선택 안내 동사는 "레이어를 선택하세요", 디자인 대상은 "선택한 프레임"이라고 쓴다.
   - G/S/C는 **계층**, **역할**은 색 역할(면·글자)에만 쓴다.
   - 플러그인 안 이동은 "→", 외부 링크(결제 페이지)는 "↗".
   - 체크박스·스위치로 고른 것은 "체크한"·"켠"이라고 쓴다. "선택"은 캔버스 선택에만 쓴다.
10. **접근성.**
    - 새 컨트롤의 누를 수 있는 영역은 24×24 이상이다. 글 속 인라인 링크만 예외다.
    - 링크·숫자 글자는 `--accent-strong` 또는 `--text-2`로, 대비 4.5:1 이상이다.
    - 메뉴는 `role="menu"`이고 열면 첫 항목으로 포커스가 간다. Esc를 누르거나 항목을 고르면 여는 버튼으로 포커스가 돌아간다.
    - **예외(항목이 다른 곳으로 보내는 경우):** "가리키는 변수로 이동" → 옮긴 행. 준비 현황 줄 → 이동한 화면의 첫 컨트롤. ⋯의 "컬렉션 계층 지정…" · "코드로 내보내기…" → 열린 팝업의 첫 컨트롤, 팝업을 닫으면 [⋯]. 행 메뉴 "상세" → 상세 팝업의 [닫기], "고치기…" → 이름 칸. 닫으면 원래 행(같은 변수 id의 행, 없으면 오른쪽 목록 머리 — §4.4 고치기).
    - 상세는 `role="dialog"` + `aria-modal`이고, 닫으면 원래 행으로 포커스가 돌아간다.
    - 회전 표시(진행 테두리, ↻)는 `prefers-reduced-motion`이면 정적 표시로 바꾼다.
11. **레이어에 하는 일 (2026-11-03 사용자 결정).** 플러그인은 변수를 고치는 도구다. 레이어에는 아래만 한다.
    - **이미 붙은 것은 바꾸지 않는다.** 건너뛰는 곳:
      - 변수가 붙은 속성. 글자는 일부 구간에만 붙어 있어도 그 속성 전체를 건너뛴다("이미 연결됨").
      - 삭제됐거나 찾을 수 없는 변수에 연결된 속성("삭제된 변수에 연결됨" — 다시 붙이는 일은 피그마에서, §4.4 "삭제된 변수에 연결된 곳").
      - 색·효과 스타일이 붙은 칠하기·선·효과, 텍스트 스타일이 붙은 글자("스타일 사용 중" — 변수를 붙이면 스타일이 끊기므로).
      - 텍스트 스타일을 붙일 때: 이미 텍스트 스타일이 붙은 글자, 글자 속성(크기·줄 높이·자간·글꼴)에 변수가 붙은 글자.
    - **레이어 값을 바꾸지 않는다.** "같은 값"에만 붙인다.
      - 숫자: 소수 둘째 자리까지 같으면 같다(화면에 보이는 값). 그보다 작은 차이(예: 15.9999 ↔ 16)는 연결하면 변수 값으로 맞춰진다.
      - 색: 화면의 #RRGGBB(채널마다 0~255 반올림)가 같고, 칠하기와 변수가 모두 불투명(투명도 1)일 때 같다. 반투명 칠하기·그림자 색은 언제나 건너뛴다("반투명" — 색 변수를 붙이면 칠하기 불투명도가 변수 값으로 바뀌므로). 투명도가 1이 아닌 색 변수는 연결 대상에서 뺀다(그 색의 칠하기는 다른 같은 색 변수에 붙거나 "매칭 없음").
      - 텍스트 스타일: 스타일이 정하는 모든 글자 속성(크기·줄 높이·자간·글꼴·대소문자·밑줄/취소선·문단 간격·들여쓰기)이 글자와 같을 때만 붙인다.
      - 사이 간격 자동 (2026-11-04, QA #3 불합격 1): 오토레이아웃 주 축 정렬이 Space between(`primaryAxisAlignItems = 'SPACE_BETWEEN'`)이면 사이 간격은 피그마가 계산한다. 저장된 숫자(`itemSpacing`)는 화면 값이 아니다. 그래서 만들기는 이 값을 토큰으로 뽑지 않고, 연결은 붙이지 않는다(사유 "사이 간격 자동"). 붙이면 피그마가 정렬을 왼쪽(`MIN`)으로 바꿔 레이어 모양이 바뀐다. 줄바꿈(wrap)의 줄 사이 간격(`counterAxisSpacing`)도 줄 정렬이 Space between(`counterAxisAlignContent = 'SPACE_BETWEEN'`)이면 같다. 여백(padding 네 방향)과 그리드 간격은 그대로 뽑고 붙인다.
      - 선 두께는 정수만 (2026-11-04 사용자 결정): 변수는 정수만 만든다 — 선 두께도 예외가 없다(이전의 0.5 단위 허용을 없앤다). 소수 선 두께(예: 1.5)는 만들기가 토큰으로 뽑지 않고, 연결은 찾을 때 사유 "소수 선 두께"(`fraction`)로 건너뛴다. 가까운 정수 변수에 당겨 붙이지 않는다(레이어 값을 바꾸지 않는다). 이미 있는 소수 선 두께 변수(예: `stroke-width/1_5`)는 지우지 않는다(§2.4) — 연결 대상도 아니다. 역할 사다리는 1 → thin, 2 → thick이다(hairline 없음).
      - 줄바꿈이 아님 (2026-11-04 사용자 결정): 줄 사이 간격(`counterAxisSpacing`)은 줄바꿈(`layoutWrap = 'WRAP'`)일 때만 피그마가 쓴다. 줄바꿈이 아니면 만들기는 뽑지 않고, 연결은 찾지 않는다. 건너뜀으로 세지도 않는다 — 그리드 모드의 `itemSpacing`처럼 이 레이어에 없는 값이기 때문이다(줄바꿈이 아닌 가로·세로 오토레이아웃마다 칩이 생기지 않게). 판정은 하나의 함수가 한다: 줄바꿈 아님이 먼저, 그다음 Space between. 만들기 추출 · 연결 찾기 · 연결 직전 다시 확인이 같은 함수를 쓴다.
    - **붙이는 일은 사용자가 버튼을 눌러서만 한다.** 레이어 › 연결의 [🔗 n곳 연결]과 [기존 스타일 연결]뿐이다. 마법사·만들기는 레이어에 변수를 붙이지 않는다. 연결할 때 각 자리를 다시 확인해, 그 사이 붙었거나 스타일이 생겼거나 값이 달라진 곳은 건너뛴다.
    - **인스턴스 안쪽은 건드리지 않는다**(변수 연결·텍스트 스타일 연결 모두).
    - 이름 정리는 레이어 이름만 바꾼다. 붙은 변수·스타일·값은 그대로다.
    - **예외 — 컴포넌트 만들기:** 레이어를 마스터의 인스턴스로 바꾸는 일이다 — [묶기](닮은 프레임 묶기)와 [등록] 안의 속성 접힘(같은 모양 멤버를 인스턴스로)·아이콘 자리 교체. 인스턴스로 바뀐 레이어의 연결·값은 마스터를 따른다(원본에 있던 다른 연결·값은 사라진다). [묶기]와 [등록]의 툴팁에 "원본의 연결과 값은 마스터를 따라요"를 적는다. 인스턴스는 원본 자리에만 두고, 그 밖의 레이어(부모·형제·그룹)는 그대로 남긴다(§4.7 "인스턴스 자리").

### 3.1 화면 사이 이동

| 출발 | 도착 | 언제 |
|---|---|---|
| 탭 바 | 각 탭(마지막 하위 화면) | 언제나 |
| 레이어 하위 탭 | 연결 / 이름 / 컴포넌트(베타) | 언제나. 컴포넌트는 설정에서 켰을 때만(§4.7 "베타") |
| 만들기 레일 칩, "다음 →" | 만들기의 다른 단계 | 언제나 |
| 변수 › 목록 "변수 없는 값 찾기 →", 안내 줄의 같은 버튼 | 레이어 › 연결 (찾기 자동, 예외 §4.6) | 지금 선택이 있을 때 |
| 준비 현황 팝오버의 줄 | 아래 표 | 다음에 할 일을 고를 때 |
| 시작 화면 "색부터 하나씩 만들기 →", 목록 [+] | 만들기 › 색 | 하나씩 만들 때 |
| 만들기 "← 돌아가기" | 변수 탭 첫 화면 | 그만둘 때 |
| 만들기 › 타이포 "변수 탭으로" / "레이어에 연결하기 →" | 변수 탭 첫 화면 / 레이어 › 연결 | 마쳤을 때 |
| 만들기 › 테마 "토큰 만들기로 →" | 만들기 › 토큰 | 다크를 만들 변수가 없을 때 |
| 마법사 완료 [변수 목록 보기] | 변수 › 목록 | 마법사가 로컬 변수를 늘렸을 때 |
| 마법사 요약 "레이어 › 연결에서 확인하고 연결하기 →" | 레이어 › 연결 (미리보기 자동, "변수 없는 값 찾기"와 같은 진입 규칙 §4.6) | 마법사가 끝났고 지금 선택이 있을 때 |
| 무료 안내 / 잠금 사유의 "라이선스 →" | 설정 › 라이선스 (키 입력칸에 포커스) | 유료 기능을 풀려 할 때 |
| 레이어 › 연결 "변수 탭에서 보기 →" | 변수 › 목록 (기준을 지금 선택으로) | 연결 결과를 확인할 때 |
| 레이어 › 연결 "토큰 만들기로 →" | 만들기 › 토큰 | 연결할 변수가 없고, 계층 없는 로컬 변수도 없을 때 |
| 레이어 › 연결 "계층 지정하기 →" | 변수 › 목록 + 계층 팝업 | 로컬 변수는 있지만 계층이 지정된 컬렉션이 없을 때 |
| 레이어 › 연결 "타이포에서 등록 →(유료)" | 만들기 › 타이포 | 기존 스타일 연결을 하려는데 등록된 텍스트 스타일이 없을 때 |
| 공통 상태 줄 "[보기]"(최소화 중 실패) | 실패한 작업의 탭·카드. 컴포넌트 작업인데 컴포넌트(베타)가 꺼져 있으면 설정 › 기본값의 "컴포넌트(베타) 보이기" 체크박스(§4.7 "베타") | 펼친 뒤 |
| 행 메뉴 "사용 레이어 선택" / "별칭으로 쓰는 레이어 선택", 삭제된 변수 [선택] | 캔버스 선택 (탭 이동 없음, 기준 유지) | 레이어를 볼 때 |
| 별칭 알약 / "가리키는 변수로 이동" | 같은 목록의 그 행 | 별칭을 따라갈 때 |

**준비 현황 줄 → 도착**

| 줄 | 도착 |
|---|---|
| 색 | 만들기 › 색 |
| 토큰 | 만들기 › 토큰 |
| 역할 매핑 | 만들기 › 토큰 + 상태 줄 "역할 매핑은 토큰을 적용할 때 함께 만들어져요" (지금 가리키는 숨은 카드 대신) |
| 다크 | 만들기 › 테마 |
| 텍스트 스타일 | 만들기 › 타이포 |
| 연결 | 레이어 › 연결 |
| 이름 | 레이어 › 이름 |

- 팝오버 아래에 각주 "컴포넌트는 필요할 때 레이어 › 컴포넌트에서"를 둔다. 컴포넌트(베타)를 켰을 때만 보인다(§4.7 "베타").

## 4. 화면별 상세

와이어는 폭 400, 높이 510 기준이고 숫자·사유 칩은 **예시**다.

### 4.1 공통 셸

```
┌────────────────────────────────────────┐
│ [ 변수 ]  레이어   설정              —  │  탭 바 (고정)
├────────────────────────────────────────┤
│                탭 내용 (패널 스크롤)      │
├────────────────────────────────────────┤
│ 상태 줄                                  │  공통 상태 줄 (고정, 높이 24)
└────────────────────────────────────────┘
```

**탭 모양 3단계**

| 단계 | 모양 |
|---|---|
| 상단 탭 | 지금 `.tabs` |
| 레이어 하위 탭 | 밑줄 글자 탭(**13px/600, 높이 32px, 탭 사이 20px**, 비활성 `--text-2`, 활성은 `--text` + 2px `--accent-strong` 밑줄). `tablist`, ←→, 정지점 1개. (2026-11-03 실기 확인: 11px는 너무 작아 알아보기 어려웠음) |
| 변수 사이드바 | 항목 높이 28px(11px), 고른 항목은 `--accent-subtle` 바탕 + `--accent-strong` 글자. `tree`, ↑↓←→, 정지점 1개(§4.4) |

**선택 표시줄은 두지 않는다** (2026-11-03 사용자 결정)

탭 바 바로 아래부터 탭 내용이다. 선택 표시줄이 하던 일은 아래처럼 나눈다.

| 하던 일 | 이제 |
|---|---|
| 목록 기준이 지금 선택과 다르다는 알림 + [기준 바꾸기] | 변수 탭(목록·시작 화면)의 상황 안내 줄 맨 앞 순위(§4.4) |
| 선택 없음 | 각 화면의 안내 문구(아래 표). 잠긴 버튼을 누르면 공통 상태 줄의 "선택이 없어요" |
| 선택한 레이어 이름 | 캔버스의 선택 강조. 레이어 › 연결은 (찾음 n) 배지 툴팁과 "찾은 곳 0" 빈 상태에 이름이 나온다 |
| 선택 크기(하위 n) | 300개를 넘으면 상황 안내 줄의 "선택이 커서 자동으로 읽지 않아요 · [읽기]" |

**선택이 없을 때 각 화면의 안내**

| 화면 | 안내 (자리) |
|---|---|
| 변수 › 목록 | 처음 고른 항목은 첫 컬렉션이고, 상황 안내 줄에 "레이어를 선택하면 쓰는 변수가 ★ Inspect에 모여요"(§4.4). ★를 고르면 같은 안내가 오른쪽 빈 상태로 옮겨 간다. 사이드바 숫자는 `전체` |
| 변수 › 시작 화면 | 마법사 카드 설명 아래 "레이어를 선택하면 실행할 수 있어요" |
| 변수 › 만들기 | 지금 단계 카드의 버튼 줄 아래 "레이어를 선택하면 그 안의 값으로 만들어요" |
| 레이어 › 연결 | 목록 자리의 "선택 없음" 빈 상태 그림 + "캔버스에서 레이어를 선택하세요"(§4.6) |
| 레이어 › 이름 · 컴포넌트 | 목록 자리 "선택이 없어요 — 캔버스에서 레이어를 선택하세요"(지금 빈 상태 문구를 이 말로) |
| 설정 | 없음 |

**공통 상태 줄**
- 창 맨 아래에 고정된다. 높이 24px, 한 줄 말줄임, `aria-live="polite"`, 모든 탭 공통이다.
- 메시지 끝의 버튼은 말줄임 밖에 항상 보인다. 글만 줄인다(예: "유료 기능이에요 · 설정 › 라이선스에서… [라이선스 →]"). 줄인 글 전체는 툴팁으로 보인다.
- **여기에 띄우는 것:** 잠금·전제 사유, 선택 없음, 다시 읽기 결과, 이동·되돌리기, 숨김 안내, 작업 진행("…읽는 중"), 최소화 중 실패.
- **카드의 상태 영역에는** 그 카드 작업의 결과 요약만 남긴다(예: "✓ 18곳 연결").
- 누를 수 있는 메시지([← 되돌리기], [보기], [라이선스 →])는 다음 사용자 조작까지 유지한다. 배경 메시지가 덮지 않는다.
  - 지우는 조작: 클릭, 버튼·행 실행(Enter·Space), 글자 입력, 탭 전환, 캔버스 선택 변경.
  - 지우지 않는 조작: 포커스 이동(Tab, 화살표), 포인터 이동·hover, 스크롤.
- 일반 메시지는 4초 뒤 사라진다.

**포커스 순서**
1. 상단 탭
2. [—]
3. 화면 컨트롤(상황 안내 줄의 [기준 바꾸기]는 목록 바로 앞)
4. 목록 또는 트리
5. 공통 상태 줄의 버튼(있을 때)

- 최소화했다가 펼친 뒤에는 포커스를 [—]로 돌려놓는다. [—]의 툴팁과 접근성 이름은 "최소화"다.
- [—]로 최소화하면 포커스는 펼치기 버튼으로 간다.
- [기준 바꾸기]를 눌러 그 버튼이 사라지면 포커스는 목록(직전 포커스 행, 없으면 첫 행)으로 간다. 시작 화면에서는 LIB 구역의 첫 행, 없으면 마법사의 주 버튼으로 간다.
- [← 되돌리기]를 누르면 포커스는 이동 전의 원래 행으로 간다.

**다시 읽기**

| 때 | 무엇을 |
|---|---|
| 탭·하위 화면에 들어갈 때 | 아래 "화면별" 표 |
| 플러그인 작업이 끝난 직후 (연결, 이름 적용, 만들기, 다크, 텍스트 스타일 등록·연결, 계층 지정, 변수 고치기, 컴포넌트 등록·묶기·분류) | 준비 상태 + 변수 표 + 지금 화면의 표. 실패(⚠)로 끝나도 파일을 바꿨으면 읽는다 — 컴포넌트 등록은 등록 또는 세트가 1개 이상, [묶기]는 마스터를 컴포넌트로 만든 결과면 인스턴스가 0개여도(마스터 이름이 빈 결과 — 마스터를 찾지 못함 · 대상 2개 미만 — 는 아무것도 바꾸지 않았으므로 읽지 않음), 분류는 세트가 1개 이상 |
| 창에 다시 들어올 때(포인터가 나갔다 들어옴, 창 포커스 회복) | 두 신호를 합쳐 400ms 뒤 한 번. 지금 화면의 표 |
| ↻ | 지금 화면의 표. 300개 제한 무시 |
| 최소화를 펼칠 때 | 지금 화면의 표 한 번 |

**화면별로 읽는 것**

| 화면 | 읽는 것 |
|---|---|
| 변수 › 시작 화면 | 준비 상태, 사용 수(LIB 구역용, 300개 규칙) |
| 변수 › 목록 | 준비 상태, 변수 표, 사용 수(300개 규칙) |
| 변수 › 만들기 | 준비 상태, 다크 카드용 컬렉션 목록 |
| 레이어 › 연결 | 준비 상태, 로컬 변수가 0개면 선택의 라이브러리 사용 여부(300개 규칙). 찾은 결과가 있으면 아래 "복귀 규칙" |
| 레이어 › 이름·컴포넌트 | 없음. 결과가 있으면 "피그마에서 바뀌었을 수 있어요 · [다시 보기]" |
| 설정 | 없음 |
| 계층 팝업을 열 때 | 계층 정보 |

**보류와 간격 (④)**
- 다음 경우에는 반영하지 않고 미룬다. 닫히거나 끝나면 1번 반영한다.
  - 메뉴·팝업·팝오버가 열려 있거나 포인터가 눌린 동안 — **창 다시 들어옴·탭 진입의 다시 읽기만** 미룬다. 플러그인 작업이 끝난 직후의 다시 읽기는 팝업이 열려 있어도 바로 한다
  - 진행 테두리 대상 작업(§4.9)이 실행 중일 때
  - 같은 종류의 직전 요청이 아직 끝나지 않았을 때
- 창 다시 들어옴이 직전 반영 뒤 2초 안에 다시 일어나면 버리지 않고, 2초가 차는 때로 1번 미룬다. 그 사이 여러 번 들어와도 1번만 반영한다.
- **조용한 반영:** 창 다시 들어옴과 탭 진입은 "…" 표시나 상태 줄 문구 없이 결과만 바꿔 넣는다. 응답이 이전과 같으면 다시 그리지 않는다. 스크롤과 포커스 행을 지킨다.
- 최소화 상태에서는 다시 읽지 않는다.

### 4.2 변수 탭 — 불러오는 중

- 첫 준비 상태가 오기 전에는 "변수 정보를 불러오는 중…" 한 줄만 보인다.
- 선택이 있는 채로 처음 목록에 들어가면, 사용 수가 올 때까지 오른쪽 목록 자리에 "선택에서 쓰는 변수 읽는 중…" 한 줄만 둔다. 처음 고를 항목은 사용 수가 온 뒤 정한다(§4.4 사이드바).
- 단, 자동으로 읽지 않는 경우(큰 선택 ⑤, 마법사 실행 중)에는 이 한 줄을 두지 않고 목록 + 상황 안내 줄을 바로 보여 준다.

### 4.3 변수 탭 — 시작 화면

```
┌────────────────────────────────────────┐
│ 아직 로컬 변수가 없어요                   │
│ 선택한 프레임에서 만들어 보세요             │
│ ⓘ 무료 버전에서는 변수를 새로 만들 수 없어요 │ ← 무료만
│   이름 정리는 무료 · 라이선스 →           │
│ ┌ 한 번에 정리 ── [이름 정리 실행] ───────┐ │ ← 버튼 줄 (무료 문구)
│ │ 무료 버전에서는 레이어 이름만 정리돼요.    │ │
│ │ 변수 만들기는 유료예요                   │ │
│ │ ☐ 역할 매핑🔒 ☐ 다크🔒 ☐ 텍스트 스타일🔒 │ │
│ └─────────────────────────────────────┘ │
│ ── LIB · 선택에서 쓰는 것 ──              │ ← 라이브러리 연결이 있을 때
│ ⓘ 라이브러리 변수는 원본 파일에서 관리해요.  │
│   같은 변수를 여기서 또 만들 필요는 없어요.   │
│ [색부터 하나씩 만들기 →]   준비 현황 n/7 ▾  │
├────────────────────────────────────────┤
│ 상태 줄                                  │
└────────────────────────────────────────┘
```

**보이는 조건**
- 로컬 변수가 0개일 때, **또는** 로컬 변수가 0개일 때 시작한 마법사(시작 화면이든 만들기 맨 위든)가 실행 중이거나 그 요약이 보이는 동안이다(①).
- 요약이 보이는 동안에는 로컬 변수가 생겨도 목록으로 바꾸지 않는다. [변수 목록 보기]를 누르거나, 요약을 본 뒤 변수 탭을 떠날 때 바꾼다.
- 마법사가 끝날 때 다른 탭에 있었으면(요약을 아직 못 봤으면), 변수 탭으로 돌아올 때 시작한 곳을 보여 준다. 시작 화면에서 시작했으면 시작 화면 + 요약, 만들기 맨 위에서 시작했으면 만들기(카드 안 요약).
- 만들기 맨 위에서 실행했으면 완료 머리와 [변수 목록 보기]가 그 카드 안에 보이고, "← 돌아가기"를 누르면 시작 화면 + 요약으로 간다. 이후 규칙은 위와 같다.

**마법사 카드 문구**

| 사용자 | 설명 | 주 버튼 |
|---|---|---|
| 유료 | "선택한 프레임의 색·간격을 변수로 만들어요. 레이어 연결은 끝난 뒤 확인하고 해요" | [전체 실행] |
| 무료 (로컬 변수 0개) | "무료 버전에서는 레이어 이름만 정리돼요. 변수 만들기는 유료예요" | [이름 정리 실행] |
| 무료 (로컬 변수 있음) | "무료 버전에서는 레이어 이름만 정리돼요. 변수 만들기는 유료예요" | [이름 정리 실행] |

- 마법사에는 연결 단계가 없다(§2.11). 단계는 추출 → 만들기 → 역할 매핑 → 다크 → 텍스트 스타일 → 이름 정리(→ 컴포넌트, 숨김)다. 무료는 추출과 이름 정리만 돈다.
- 라이브러리를 쓰는 파일에는 LIB 구역의 중복 생성 안내만 보인다.
- 잠긴 옵션(역할 매핑, 다크, 텍스트 스타일)은 체크 해제 + `aria-disabled` + 🔒다.
- 선택이 없으면 주 버튼은 `aria-disabled`이고, 누르면 상태 줄에 사유가 뜬다.
- 컴포넌트 옵션은 지금처럼 숨긴다.

**완료**
- **로컬 변수가 늘었을 때:** 머리를 "변수 {n}개를 만들었어요"로 바꾸고, [변수 목록 보기]를 보여 주고, 준비 현황을 다시 센다. n = 마법사 전후 로컬 변수 수의 차이다.
  - 머리 아래에 마법사 요약을 그대로 둔다. 뒤 단계(다크, 이름 정리 등)의 실패·건너뜀·취소도 이 요약에 ⚠로 보인다.
- **취소:** 실행 중 [취소]를 누르면 지금 단계가 끝난 뒤 남은 단계를 실행하지 않는다. 남은 단계는 요약에 "취소로 건너뜀"으로 보인다.
- **늘지 않았을 때:** 머리는 그대로 두고 요약만 보여 준다.
  - 무료일 때 요약: "레이어 이름 {n}개 정리 · 변수는 만들지 않았어요"(로컬 변수 수와 관계없이 같다).
  - 취소·실패 때 요약: 마법사의 현재 요약 형식
- **요약 끝 연결 안내:** 마법사가 끝나면(취소·실패 포함) 요약 끝에 "레이어 › 연결에서 확인하고 연결하기 →"를 둔다. 누르면 레이어 › 연결로 가서 찾기를 자동으로 실행한다(진입 규칙은 §4.6 "변수 없는 값 찾기로 들어올 때"와 같다).
  - 지금 선택이 없으면 `aria-disabled`, 사유 "선택이 없어요". 연결할 변수가 없으면(계층이 지정된 로컬 변수 0개) 이 안내를 숨긴다.
  - 마법사는 레이어에 변수를 붙이지 않는다. 그래서 끝난 직후 같은 선택으로 변수 목록을 보면 "선택에서 쓰는 것"은 비어 있고(처음 고른 항목은 첫 컬렉션), 새 변수는 "안 씀"으로 보이며, 상황 안내 "이 선택은 로컬 변수를 쓰지 않아요 · [변수 없는 값 찾기 →]"가 뜬다(§4.4). 연결하면 쓰는 변수가 된다.
  - 이름 정리는 레이어에 붙은 변수 이름을 역할 신호로 쓴다. 마법사는 연결 전에 이름을 정리하므로 이 신호 없이 정리한다. 연결한 뒤 레이어 › 이름을 다시 실행하면 이름이 더 정확해질 수 있다.

**나머지**
- 무료 안내의 "라이선스 →"는 설정 › 라이선스로 가서 키 입력칸에 포커스를 둔다.
- "색부터 하나씩 만들기 →"는 무료여도 보인다. 무료이면 버튼 옆에 "(추출까지 무료)"를 붙인다.
- 준비 현황 `n`은 완료 단계 수다. 로컬 텍스트 스타일만 있어도 1 이상일 수 있다.
- LIB 구역의 행은 목록의 LIB 행과 같은 규칙이다(§4.4 LIB). 큰 선택이면 구역 자리에 "선택이 커서 자동으로 읽지 않아요 · [읽기]"가 보인다.
- 마법사 화면 요소는 1개다. 시작 화면과 만들기 맨 위 중 보이는 곳에 붙는다. 만들기 쪽에서는 실행 중이거나 요약이 있으면 펼친 채로 붙고, 접힌 머리에도 "실행 중 2/4"처럼 보인다.
- **만들기 맨 위에서 실행한 마법사**(로컬 변수가 이미 있는 경우)는 머리를 바꾸지 않는다. 완료 요약은 카드 안에, "변수 {n}개 생성"은 상태 줄에 띄운다.

#### 머리줄

| 요소 | 동작 |
|---|---|
| 준비 현황 n/7 ▾ | 팝오버(폭 240px, 메뉴 모양)로 7단계를 연다. 목록을 밀지 않는다. 줄을 누르면 닫히고 이동한다 |
| 변수 없는 값 찾기 → | **지금 캔버스 선택**에 대해 동작한다(기준이 아니라). 지금 선택이 없으면 `aria-disabled`. 툴팁 "선택에서 변수로 바꿀 수 있는 색·간격을 찾아 연결 미리보기를 엽니다" |
| [+] | 아이콘만. 만들기 › 색. 툴팁 "선택한 프레임에서 변수 만들기(색·토큰·테마·타이포)" |

- **[↻] 결과** (상태 줄, 2초)
  - "다시 읽음 · 변경 없음"
  - "다시 읽음 · 사용 수가 바뀐 변수 n개"
  - "다시 읽음 · 변수 목록이 바뀌었어요"
  - 둘 다 바뀌었으면 마지막 문구 + 개수
- 링크 모양 버튼("준비 현황", "변수 없는 값 찾기")은 `--accent-strong` 글자, 높이 24px 이상이다.

#### 사이드바 (왼쪽, 112px)

**항목** (위에서 아래로)
1. **★ Inspect** (2026-11-03 사용자 결정: 사이드바 폭에 맞는 짧은 이름. 툴팁·접근성 이름 "Inspect — 선택에서 쓰는 변수") — 목록 기준 레이어가 쓰는 **로컬** 변수(직접 + ↳ 간접)를 모든 로컬 컬렉션에서 모아 보여 준다. 라이브러리 변수는 넣지 않는다(LIB 항목). 숫자는 쓰는 로컬 변수 수.
   - 선택이 없거나, 큰 선택이라 아직 안 읽었으면 숫자 자리에 "—", 읽는 중이면 "…".
   - **비어 있을 때 오른쪽**(빈 상태 한 줄):

     | 경우 | 오른쪽 |
     |---|---|
     | 선택 없음 | "레이어를 선택하면 쓰는 변수가 여기에 모여요" |
     | 큰 선택, 아직 안 읽음 | "선택이 커서 자동으로 읽지 않아요 · [읽기]" |
     | 읽는 중 | "선택에서 쓰는 변수 읽는 중…" |
     | 마법사 실행 중(아직 안 읽음) | "마법사가 끝나면 읽어요" |
     | 다 읽었고 쓰는 로컬 변수 0 | "이 선택은 로컬 변수를 쓰지 않아요 · [변수 없는 값 찾기 →]" |

   - 위 빈 상태가 오른쪽에 보이는 동안에는 같은 내용을 상황 안내 줄에 띄우지 않는다(한 안내는 한 곳에만).
2. **컬렉션** — 계층 순서(Component → Semantic → Global → 계층 없음), 같은 계층 안에서는 피그마 순서. 표기는 [▾/▸] + 계층 배지 + 이름 + 숫자.
   - **계층 배지**(누를 수 없는 표시): G / S / C. 직접 지정했거나, 지정하지 않았어도 이름이 정확히 Global · Semantic · Component면 그 계층이다. "계층 아님"으로 지정한 컬렉션은 "–", 지정 안 함(이름으로도 정해지지 않음)은 "?". "계층 없음" 안에서는 –와 ?를 나누지 않고 피그마 순서를 따른다.
   - 로컬 컬렉션이 0개면 변수 탭은 목록이 아니라 시작 화면이다(§4.3).
   - **그룹** — 펼친 컬렉션 아래에 들여 쓴다. 그룹 키는 컬렉션 + 경로(이름의 마지막 "/" 앞). "/"가 없는 변수는 "(그룹 없음)". 표기는 경로 + 숫자.
3. 구분선
4. **LIB** — 목록 기준 레이어가 라이브러리 변수를 쓸 때만. 숫자는 쓰는 라이브러리 변수 수.
5. **삭제된 변수** — 삭제된 변수에 연결된 자리가 있을 때만. 숫자는 자리 수. `--danger` 글자.

**숫자** (`--text-2`, 고른 항목은 `--accent-strong`)
- 선택이 있고 사용 수를 읽었으면 `사용/전체`, 아니면 `전체`. 읽는 중(사용자가 일으킨 읽기)이면 "…". 툴팁: "선택에서 쓰는 변수 {n}개(직접 {d} · 간접 {i}) / 전체 {t}개"(읽기 전에는 "전체 {t}개").
- 쓰는 변수가 0인 컬렉션·그룹은 이름도 `--text-2`다.

**고르기와 펼치기**
- 항목을 누르면 고른 것이 된다(`--accent-subtle` 바탕). 오른쪽에 그 항목의 변수가 보인다.
- 컬렉션의 ▾/▸(24×24)는 그 컬렉션의 그룹을 사이드바에서 펼치고 접는다. 컬렉션 이름을 누르면 컬렉션을 고르고, 접혀 있으면 함께 펼친다.
- **처음 고른 항목:** 목록에 처음 들어갈 때, 선택이 있고 300개 이하면 ★(읽는 중 빈 상태)를 고르고, 사용 수가 온 뒤 쓰는 로컬 변수가 0이면 첫 컬렉션으로 옮긴다(그 사이 사용자가 직접 고른 항목이 있으면 옮기지 않는다). 선택이 없거나 큰 선택이면 계층 순서의 첫 컬렉션.
- **처음 펼친 컬렉션:** 쓰는 변수가 있는 컬렉션. 없으면 첫 컬렉션만.
- **선택이 바뀌면:** 사용자가 사이드바에서 직접 고른 항목이 있으면 그대로 둔다. 직접 고른 적이 없으면 "처음 고른 항목" 규칙으로 다시 정한다 — 사용 수가 온 뒤(큰 선택에서 [읽기]를 누른 뒤, 마법사가 끝난 뒤 포함) 쓰는 로컬 변수가 있으면 ★, 없거나 선택을 풀었으면 첫 컬렉션.
- **고른 항목이 사라지면**(다시 읽기 뒤 그룹·컬렉션이 없어짐, 목록 기준이 바뀌어 LIB·삭제된 변수 항목이 없어짐): 그룹이면 같은 컬렉션을(그 컬렉션도 없으면 "처음 고른 항목" 규칙), 컬렉션·LIB·삭제된 변수면 "처음 고른 항목" 규칙의 항목을 고른다. 포커스가 사라진 항목에 있었으면 새로 고른 항목으로 옮긴다. 상태 줄 알림은 없다.
- **검색 중에 사이드바 항목을 누르면:** 검색을 지우고 그 항목을 고른다.
- 직접 펼치거나 접은 컬렉션, 고른 항목은 세션 동안 기억한다(§2.6).
- **이름이 길면** 말줄임하고 툴팁에 전체 이름. 사이드바 폭은 바꿀 수 없다.

**스크롤**
- **머리줄**(준비 현황 · 변수 없는 값 찾기 · [+][⋯][↻])은 탭 바 아래에 고정한다. 상황 안내 줄은 고정하지 않는다(스크롤하면 올라간다).
- **사이드바**는 머리줄 바로 아래에 고정한다(top = 탭 바 + 머리줄). 높이는 창 높이 − 탭 바 − 머리줄 − 상태 줄(24px)까지이고, 항목이 더 많으면 사이드바만 따로 스크롤한다(§2.5 예외).
- **오른쪽 목록 머리**도 머리줄 바로 아래에 고정한다. 오른쪽 목록은 패널 스크롤이다. 고정은 머리줄 + 오른쪽 목록 머리 두 겹이다.

#### 오른쪽 목록 머리 (고정)

- 고른 항목 이름(예: "★ Inspect", "S Semantic", "color/text") + [모드 ▾] + [🔍].
- **모드 ▾:** 오른쪽에 행이 보이는 로컬 컬렉션들(★: 행이 있는 컬렉션, 검색: 결과가 있는 컬렉션, LIB: 없음 → 숨김)의 모드 이름을 모은다. 보이는 모드가 1개면 숨긴다. 고른 모드가 없는 컬렉션은 그 컬렉션의 **기본 모드**(피그마 `defaultModeId`) 값을 보여 준다. 값 복사와 색 견본도 이 모드를 따른다.
- **🔍 검색**
  - 누르면 입력칸(✕, Esc)이 오른쪽 머리를 덮어 열린다.
  - 범위는 **모든 로컬 컬렉션 + LIB**다(고른 항목과 관계없이). 결과는 오른쪽에 경로 머리로 묶어 보인다. 사이드바의 고른 표시는 흐리게(`--text-2`) 두고, 검색을 지우면 돌아온다.
  - **맞추는 방법:** 변수의 전체 경로(예: `color/text/default`)에 검색어가 들어 있으면 맞는다. 대소문자는 구분하지 않는다. 값과 별칭 대상 이름은 찾지 않는다.
  - 결과 없음: "'{q}'와 맞는 변수가 없어요 · [검색 지우기]".

#### 상황 안내 줄 (목록 바로 위, 하나만)

- 여러 상황이 겹치면 표의 위쪽 하나만 보인다. 목록 기준이 달라 다른 안내(큰 선택 등)가 가려져도, [기준 바꾸기]를 누르면 그 기준의 안내가 이어서 보인다.
- 시작 화면에는 표의 첫 행("목록 기준 다름")만 LIB 구역 위에 둔다(LIB 구역이 목록 기준으로 읽으므로). 큰 선택 안내는 지금처럼 LIB 구역 자리에 두고(§4.3), 나머지 행은 시작 화면에 쓰지 않는다.

| 상황 (위가 먼저) | 문구 |
|---|---|
| 목록 기준이 지금 선택과 다름 (③) | "목록 기준: {기준 이름 또는 "레이어 m개"} · 지금 선택과 달라요 · [기준 바꾸기]" (지금 선택이 없으면 "· 지금 선택 없음 ·"). 기준 이름은 120px에서 말줄임 |
| 선택 노드 300개 초과, 아직 안 읽음 (⑤) | "선택이 커서 자동으로 읽지 않아요 · [읽기]" |
| 마법사 실행 중(선택 300개 이하), 아직 안 읽음 | "마법사가 끝나면 읽어요" (끝나면 작업 후 다시 읽기로 자동 반영) |
| 선택이 로컬 변수를 하나도 안 씀 | "이 선택은 로컬 변수를 쓰지 않아요 · [변수 없는 값 찾기 →]" |
| 선택 없음 | "레이어를 선택하면 쓰는 변수가 ★ Inspect에 모여요" |

- 이 줄은 머리줄 바로 아래, 사이드바·목록 위에 전체 폭으로 둔다. 이 줄의 버튼은 포커스 순서에서 머리줄 다음, 사이드바 앞이다.
- ★가 골라져 있고 그 빈 상태(§4.4 사이드바)가 같은 내용을 보이면, 그 행(큰 선택 · 마법사 실행 중 · 안 씀 · 선택 없음)은 이 줄에 띄우지 않는다.

#### 쓰는 변수 판정

- **직접 사용:** 목록 기준 레이어(인스턴스 안쪽 포함, 숨긴 레이어 제외) 안에 그 변수가 연결돼 있다.
- **간접 사용:** 직접 사용 변수가 별칭으로 가리키는 변수다.
  - 모든 모드를 보고, 최대 5단계까지 따라간다. 라이브러리 변수 사이의 별칭도 따라간다.
  - 직접과 겹치면 직접으로 센다.
- **사용 수:** 연결된 속성 자리 수("곳"). 툴팁 "레이어 {k}개 · {n}곳".
  - 연결 작업(레이어 탭)은 지금처럼 인스턴스 안쪽을 건드리지 않는다. 보기와 작업의 범위가 다르다는 것을 상세 팝업에 적는다: "인스턴스 안쪽 포함".

#### 오른쪽 목록

**무엇이 보이나**
- **★ Inspect:** 쓰는 변수(직접 + ↳ 간접)만. 경로 머리("S Semantic › color/text")로 묶고, 순서는 컬렉션 계층 순서 → 그룹 → 피그마 순서.
- **컬렉션:** 그 컬렉션의 모든 변수. 그룹마다 경로 머리. 선택이 있고 읽었으면 쓰는 변수를 먼저(그룹 안에서), 안 쓰는 변수는 뒤에 "안 씀" 모양으로.
- **그룹:** 그 그룹의 모든 변수(쓰는 변수 먼저, 위와 같다). 경로 머리 없음.
- **LIB:** 쓰는 라이브러리 변수(실제 이름 + `LIB`, 행 규칙은 아래 §4.4 LIB).
- **삭제된 변수:** "삭제된 변수에 연결된 곳 {n}개 · [선택]" 한 줄. [선택]은 그 레이어들을 캔버스에서 선택한다(기준은 유지).
- 경로 머리는 고정하지 않는다(오른쪽 목록 머리만 고정).

#### 행

**열 폭** (오른쪽 목록 약 263px)
- 이름(마지막 "/" 뒤만): 남는 폭(약 95px), 말줄임 + 툴팁 전체 경로
- 값: 74px (색은 견본 + #RRGGBB, 별칭은 알약을 말줄임)
- 사용: 34px ("12곳" · "↳" · "안 씀" · "—")
- ⋯: 24px (항상 자리를 비워 둠)

**⋯ 버튼**
- 행 hover, 행 포커스, 메뉴가 열린 동안에만 보인다.

**행 상태별 모양** (opacity를 쓰지 않음)

| 상태 | 이름 | 사용 열 |
|---|---|---|
| 직접 사용 | `--text` 600 | "12곳" |
| 간접 사용 | `--text` 400 | "↳" (툴팁 "직접 붙어 있진 않고, {첫 별칭} 같은 별칭을 통해 쓰여요") |
| 안 씀 | `--text-2` | "안 씀" |
| 선택 없음 | `--text` 400 | "—" |

- **포커스 행이 사라질 때**(선택이 바뀌어 ★ Inspect에서 빠짐): 포커스를 오른쪽 목록 머리로 옮기고, 상태 줄에 "선택에서 안 쓰여 목록에서 빠졌어요"를 띄운다.

**별칭과 이동**
- 별칭 값은 알약(`→ gray/50`)이다. 라이브러리 대상이면 실제 이름 + `LIB`를 붙인다. 색 견본은 별칭을 따라간 실제 색이다.
- **알약 또는 "가리키는 변수로 이동"을 누르면**
  - 검색어를 지우고, 사이드바에서 대상 변수의 그룹을 고르고(컬렉션을 펼침), 그 행으로 포커스를 옮긴다.
  - 상태 줄에 "{이름} 행으로 옮겼어요 · [← 되돌리기]"를 띄운다. 되돌리기는 고른 항목, 사이드바 펼침, 검색어, 스크롤을 복원한다.
- 대상이 라이브러리 변수면 사이드바 LIB를 고른다. LIB에 없으면 "라이브러리 변수예요 · 원본 파일에서 관리해요"를 띄운다.

#### LIB

- 사이드바 LIB 항목은 목록 기준 레이어가 라이브러리 변수를 직접 또는 간접으로 쓸 때만 보인다.
- **행:** 실제 이름 + `LIB` + 사용 수("n곳" / "↳").
- **메뉴:** 복사 3종 · 사용 레이어 선택(직접일 때) · 상세. 수정 메뉴는 이후에도 없다.

#### 선택이 바뀔 때

- **사용자의 캔버스 선택 변경:** 기준이 지금 선택으로 바뀐다. 400ms 뒤 사용 수를 요청한다.
  - 요청 중에는 사이드바 숫자 "…" + 상태 줄 "선택에서 쓰는 변수 읽는 중…"이 뜬다. 목록은 비우지 않는다. 응답이 오면 한 번에 바꾼다.
- **플러그인이 만든 선택:** 기준을 바꾸지 않는다. 상황 안내 줄에 "목록 기준: … · [기준 바꾸기]"가 나온다. 사용 레이어 선택, 건너뜀 사유 칩, 삭제된 변수 [선택], 연결 직후 피그마가 보내는 선택 상태가 여기에 해당한다.
- **바뀌는 것:** 사이드바 숫자, "선택에서 쓰는 것"의 내용, 행 상태(직접·간접·안 씀), LIB·삭제된 변수 항목. 열린 상세는 닫지 않는다.
- **큰 선택(⑤):** 노드가 300개를 넘으면 자동으로 요청하지 않고 상황 안내 줄을 띄운다. 마법사 실행 중에도 자동 요청하지 않는다(새 규칙).
- [기준 바꾸기]는 캔버스 선택 변경과 같게 처리한다. 새 기준이 300개를 넘으면 바로 읽지 않고 상황 안내 줄의 [읽기]를 띄운다.

#### 행 메뉴 (우클릭 / 행 ⋯ / Shift+F10)

| 항목 | 조건 |
|---|---|
| 이름 복사 · 값 복사 · CSS 변수명 복사 | 항상 |
| 사용 레이어 선택 | 직접 사용이 있을 때 |
| 별칭으로 쓰는 레이어 선택 | 간접 사용만 있을 때. 그 변수를 가리키는 별칭이 연결된 레이어를 선택한다 |
| 가리키는 변수로 이동 | 값이 별칭일 때 |
| 상세 | 항상 |
| 고치기… | 로컬 변수일 때(LIB 행에는 없음). 상세를 열고 이름 칸에 포커스 |

- 선택이 없어 사용 판정이 없으면 두 "선택" 항목은 `aria-disabled`이고, 보조 문구는 "레이어를 선택하면 그 안에서 찾아요"다.
- **레이어 선택은 한 번에 최대 200개**(지금 상한과 같음)다. 넘으면 상태 줄에 "레이어 200개만 선택했어요(전체 {n}개)"를 띄운다. 쓰는 레이어는 그때 새로 찾아서 고르므로 600개 결과 상한과 무관하다.
- 교체, 삭제는 없다. 이름·값은 상세 팝업에서 고친다(아래 고치기).

#### 상세 팝업

- **공통:** 컬렉션 · 계층, 모드별 값, 용도, 설명, 쓰인 곳
- **쓰인 곳**
  - 팝업을 열 때 그 변수를 쓰는 레이어를 **목록 기준 레이어 안에서** 새로 찾는다(목록의 사용 수와 같은 범위).
  - 목록 기준이 없으면: "레이어를 선택하면 그 안에서 찾아요".
  - 목록 기준이 300개를 넘으면 자동으로 찾지 않고 "선택이 커서 자동으로 찾지 않아요 · [찾기]"를 둔다.
  - 레이어 이름 목록을 최대 50개까지 보여 주고, 넘으면 "외 {n}개"를 붙인다. 항목을 누르면 그 레이어를 선택한다.
  - 맨 위에 "레이어 {k}개 · {n}곳 · 인스턴스 안쪽 포함"을 둔다.
- **간접 행:** "별칭을 통해 쓰임: {별칭 이름들}"과 그 별칭들의 쓰인 곳을 보여 준다.
- **LIB 행:** 컬렉션 "라이브러리 · {이름}", 맨 아래 "원본 파일에서 관리해요".

#### 고치기 (상세 팝업 · PR 3.5)

**범위**
- 로컬 변수의 **이름(전체 경로)**과 **모드별 값**(값 ↔ 별칭 전환 포함)을 고친다.
- 고치지 않는 것: 설명, 용도(scopes), 컬렉션·모드, 삭제, 라이브러리 변수(LIB 행 상세는 지금처럼 읽기 전용).
- 유료 잠금 없음(§6 무료 목록).
- 원칙(§2.11)과의 관계: 레이어는 건드리지 않는다. 변수 값이 바뀌면 그 변수에 이미 연결된 레이어의 모습이 피그마에서 따라 바뀐다 — 값 변경의 영향은 팝업에 따로 적지 않는다(사용자 결정). 쓰인 곳 줄로 이 선택 안의 범위만 보인다.

**모양** (로컬 행 상세)

```
┌ ■ color/text/default ───────────────────────┐
│ 컬렉션  Semantic                               │
│ 이름    [color/text/default                ]   │
│ Light   [■ → gray/900                    ▾]   │
│ Dark    [■ → gray/50                     ▾]   │
│ 용도    chip chip                              │
│ 설명    —                                      │
│ 쓰인 곳 레이어 4개 · 12곳 · 인스턴스 안쪽 포함 │
│ ┄ 저장하면 바뀌는 것 ┄ (이름이 바뀔 때만)      │
│ · 그룹 이동: color/text → color/fg (새 그룹)    │
│ · CSS: --color-text-default → --color-fg-default│
│ (오류 줄)                                      │
│ (확인 줄: 고친 내용을 버릴까요? [버리기] [계속 고치기]) │
│                          [닫기]  [저장]        │  ← 팝업 아래에 고정
└───────────────────────────────────────────────┘
```

- 컬렉션 줄은 지금 상세와 같다(이름과 계층 이름이 같으면 하나만, 다르면 "Tokens · Semantic").
- 칸은 처음부터 고칠 수 있다(따로 [고치기] 모드 없음).
- **높이:** 팝업 최대 높이는 지금과 같다(창 높이 − 80px). 내용이 넘치면 팝업 안이 스크롤하고, 단추 줄(오류 줄 · 확인 줄 · 단추)은 팝업 아래에 고정한다.
- **열 때 포커스:** "상세"(Enter · 더블클릭 · 메뉴 상세)로 열면 [닫기], "고치기…"로 열면 이름 칸(§2.10). 지금 팝업은 첫 입력 칸에 포커스를 주므로 첫 포커스를 지정할 수 있게 한다(A.3c).

**단추와 오류 줄**
- 고친 것이 없으면 [닫기] + [저장](잠김). 고친 것이 있으면 [취소] + [저장].
- [저장]이 잠긴 채 누르면(§2.3) 사유는 상태 줄이 아니라 **팝업 안 오류 줄**에 띄운다(상태 줄은 팝업 뒤에 가려진다).
  - 고친 것 없음: "고친 것이 없어요"
  - 입력 오류: "입력을 확인해 주세요" + 첫 오류 칸으로 포커스
  - 저장 중: 누를 수 없다("저장 중…")
- **알림 줄 하나(오류 줄):** 한 번에 한 문구만 띄운다.
  - **남는 상태 문구:** "변수가 삭제됐어요" > "다른 곳에서 바뀌었어요" · "저장됐을 수 있어요 · 닫고 다시 열어 주세요"(같은 급, 나중 것이 바꿈). 이 중 하나가 뜨면 팝업을 닫을 때까지 남고, 다른 문구가 이것을 덮지 않는다.
  - **사건 문구**(저장 중이에요 · 저장 실패 사유 · 입력을 확인해 주세요 · 고친 것이 없어요): 새 사건이 앞의 것을 바꾼다. 응답이 오면 "저장 중이에요"는 응답 문구로 바뀐다. 칸을 고치면 사건 문구를 지운다.
  - 확인 줄이 떠 있어도 그대로 둔다.
- **"고친 것" 판정:** 칸의 값을 정규화한 것이 열 때 값(base)을 정규화한 것과 다를 때만 고친 것이다.
  - 이름: 앞뒤 공백과 토막마다 앞뒤 공백을 뗀 문자열.
  - 색: 대문자 `#RRGGBB` + 투명도(0–255 정수로 반올림해 비교). `#ffffff`와 `#FFFFFF`는 같다.
  - 숫자: 읽은 수. `1`과 `1.0`은 같다. 손대지 않은 칸은 열 때 표시값(소수 셋째 자리 반올림)이어도 고친 것이 아니다.
  - 글자 · 참거짓: 그대로 비교. 별칭: 대상 id.

**이름 칸**
- 전체 경로를 한 칸에 적는다. 저장할 때 앞뒤 공백과 토막마다 앞뒤 공백을 뗀다(`color/ text` → `color/text`).
- 입력할 때마다 정리한 이름으로 검사하고, 오류는 칸 바로 아래에 한 줄로 띄운다.
  - 비었거나 "/" 사이가 빔(`a//b`, 앞뒤 "/"): "이름의 '/' 사이가 비어 있어요"
  - 같은 컬렉션에 같은 이름(대소문자까지 같을 때): "이 컬렉션에 같은 이름이 있어요"
- 피그마가 이름을 거절하면(저장 응답) 같은 자리에 "피그마가 이 이름을 받지 않아요"를 띄우고, 피그마가 준 원문은 그 줄의 툴팁에 둔다. 이 거절은 입력 오류가 아니라서 [저장]을 잠그지 않는다. 이름 칸을 고치면 지운다.
- 피그마가 거절하는 글자와 대소문자만 다른 이름의 허용 여부는 실기에서 확인해 미리 검사에 더한다(A.3c).
- **바뀌는 것 줄(이름)** — 그룹 = 마지막 "/" 앞 경로, 없으면 "(그룹 없음)".
  - 그룹이 바뀌면: "그룹 이동: {이전 그룹} → {새 그룹}".
    - 같은 컬렉션에 이름이 `{새 그룹}/`로 시작하는 다른 변수가 없으면 "(새 그룹)"을 붙인다.
    - 같은 컬렉션에 이름이 `{이전 그룹}/`로 시작하는 다른 변수가 없으면 "· {이전 그룹} 그룹은 비어서 사라져요"를 붙인다.
  - CSS 이름(코드 내보내기와 같은 규칙)이 **다를 때만**: "CSS: {이전} → {새}". 다른 로컬 변수(모든 컬렉션 — CSS 내보내기는 컬렉션을 나누지 않는다)와 CSS 이름이 같아지면 "· {그 변수 이름}과 CSS 이름이 같아져요"를 붙인다(경고만, 저장은 된다).

**값 칸** (컬렉션의 모든 모드, 한 줄씩)
- **값일 때** 타입별 입력
  - COLOR: 견본 + 글자칸. 불투명이면 `#RRGGBB`, 투명도가 있으면 `#RRGGBBAA`로 보여 준다. 6자리로 적으면 불투명(투명도 1)이다. 틀리면 "#RRGGBB 형식으로 적어 주세요". 색 고르개는 없다.
  - FLOAT: 숫자 칸. 틀리면 "숫자를 적어 주세요".
  - STRING: 글자 칸. BOOLEAN: 스위치(`role="switch"`).
- **별칭일 때:** 알약(견본 + `→ 대상 이름`, 라이브러리면 `LIB`)을 버튼으로 보여 준다. 누르면 별칭 고르개를 연다.
  - 대상이 삭제됐으면 알약은 "→ (삭제된 변수)"를 경고 색으로 보이고 줄 아래에 "가리키던 변수가 삭제됐어요"를 띄운다. 손대지 않으면 그대로 저장된다.
- **값이 없는 모드:** 빈 칸(자리 표시 "—")이다. 손대지 않으면 고친 것이 아니다.
- **값 칸 끝 [▾]:** 별칭 고르개를 연다(값일 때도 있음).
- **견본 색과 "값으로 적기"의 값:** 그 모드 줄의 별칭에서 시작해, 대상 변수는 **대상 컬렉션의 기본 모드** 값을 본다. 로컬 별칭만 최대 5단계 따라간다(목록의 견본 규칙과 다르다: 목록은 고른 모드를 따른다).

**별칭 고르개** (값 줄 아래에 펼치는 목록, `listbox`)
- 맨 위 검색 칸(변수 전체 경로에 들어 있으면 맞음, 대소문자 무시) → 후보 목록(경로 머리 "G Global › gray"로 묶고 순서는 사이드바와 같음) → 맨 아래 안내 줄.
- 후보 목록은 최대 높이 200px이고 넘치면 목록만 따로 스크롤한다(§2.5 예외, 사이드바와 같은 이유).
- 한 번에 고르개는 하나만 열린다. 다른 [▾]를 누르면 앞의 것은 닫힌다.
- 별칭일 때만 맨 위에 "값으로 적기"가 있다. 고르면 위 규칙으로 따라간 실제 값을 칸에 채운다. 따라갈 수 없으면(라이브러리 대상 · 삭제된 대상) 칸을 비우고 오류 "값을 적어 주세요"를 띄운다.
- **후보 규칙**
  - 같은 타입의 로컬 변수만. 자기 자신은 빼고, 고르면 순환이 생기는 변수(그 변수의 별칭을 어느 모드든 따라가면 이 변수에 닿는 것)도 뺀다.
  - **계층 규칙:** 자기 컬렉션 계층이 Semantic(2) · Component(3)이면 계층이 자기보다 낮은(1 이상, 자기 미만) 컬렉션의 변수만.
  - Global(1)은 후보가 없다. 목록 대신 "Global은 다른 변수를 가리키지 않아요"를 띄운다.
  - 계층이 없는 컬렉션(0)이면 모든 로컬 컬렉션에서 고르고, 안내 줄에 "계층이 없는 컬렉션이라 모든 변수를 보여요"를 띄운다.
  - 라이브러리 변수는 새 대상으로 고를 수 없다(안내 줄 "라이브러리 변수는 대상으로 고를 수 없어요").
  - **지금 대상이 후보가 아니면**(라이브러리 · 계층 규칙 밖 · 삭제됨): 목록 맨 위에 ✓와 함께 보이되 누를 수 없고(`aria-disabled`), 안내 줄에 "지금 대상은 규칙 밖이라 다시 고를 수 없어요 · 그대로 두면 바뀌지 않아요"를 띄운다.
- 후보 행: 견본/값 + 이름(마지막 토막, 툴팁 전체 경로). 지금 대상은 ✓.
- 키보드: 검색 칸에서 ↓로 목록, ↑↓ 이동, Enter 고르기. Esc는 **고르개만** 닫고 그 [▾]로 포커스(팝업까지 닫지 않는다). 고르면 닫힌다.

**바뀌는 것 줄** (저장 전, 고친 것이 있을 때만)
- **이름이 바뀔 때만** 보인다. 내용은 위 이름 칸 규칙(그룹 이동 · CSS 이름).
- 값 변경에 대한 줄(가리키는 별칭 수 · 모든 레이어 영향 · 투명도와 연결 대상 · 라이브러리 게시)은 띄우지 않는다(2026-11-03 사용자 결정).

**저장**
- [저장]을 누르면 고친 것만 한 번에 보낸다: `UPDATE_VARIABLE { reqId, id, name?, values?: { [modeId]: EditValue }, base }`.
  - `EditValue` = `{kind:'color', hex, alpha}`(hex는 `#RRGGBB`, alpha는 0–1) · `{kind:'number', value}` · `{kind:'string', text}` · `{kind:'bool', value}` · `{kind:'alias', targetId}`
  - `base` = 팝업을 열 때(또는 마지막 저장 응답 뒤)의 이름과, 고친 모드의 `VarCell`(변수 표와 같은 형식).
- 플러그인은
  1. 변수가 없으면 "변수가 삭제됐어요"로 끝낸다.
  2. 지금 이름과 고친 모드의 값을 **변수 표를 만들 때와 같은 변환**으로 `VarCell`로 바꿔 `base`와 비교한다. 다르면 아무것도 바꾸지 않고 "다른 곳에서 바뀌었어요 · 닫고 다시 열어 주세요"로 끝낸다.
  3. 이름 → 값 순서로 바꾼다. 별칭은 대상 변수로 별칭 값을 만들어 넣는다. 중간에 실패하면 멈추고, 이미 바뀐 것과 실패 사유를 돌려준다.
  4. 하나라도 바꿨으면 `commitUndo` — ⌘Z 한 번에 전부 되돌린다.
  5. `VARIABLE_UPDATED { reqId, ok, applied: ('name'|modeId)[], error? }`를 보낸다. 플러그인은 변수 표를 따로 보내지 않는다.
- UI는 응답을 받으면 하나라도 바뀌었을 때(`applied`가 비지 않음) §4.1 "플러그인 작업이 끝난 직후" 다시 읽기(준비 상태 + 변수 표 + 지금 화면의 표)를 한다. 팝업이 열려 있어도 바로 한다(§4.1 ④).
- **저장 중:** [저장]은 "저장 중…"으로 잠기고 칸도 잠긴다. Esc · 바깥 누름 · [취소]로 닫히지 않고 오류 줄에 "저장 중이에요"를 띄운다. **끝나는 때:** 하나라도 바뀐 응답이면 그 뒤 첫 변수 표를 받아 팝업을 다시 그릴 때까지 유지한다(그 사이 [저장]을 다시 눌러 옛 `base`로 충돌하지 않게). 아무것도 안 바뀐 응답(1·2·3단계 실패)이면 응답을 받을 때 바로 끝난다.
  - **응답이나 표가 오지 않을 때**(`ERROR`의 `op`가 `UPDATE_VARIABLE` 또는 `GET_VAR_TABLE`, 또는 [저장]을 누르고 10초): 결과를 알 수 없으므로 한 가지로 처리한다.
    - '저장 중'을 끝내고, [저장]은 팝업을 닫을 때까지 잠근다. 닫기는 다시 된다.
    - 알림 줄에 남는 상태 문구 "저장됐을 수 있어요 · 닫고 다시 열어 주세요"를 띄운다(응답이 바뀐 것으로 왔든 안 왔든 같다).
    - 그 뒤 늦게 오는 같은 요청의 응답 · 변수 표로는 **팝업을 다시 그리지 않는다**(잠금 유지). 늦은 응답의 `applied`가 비지 않았으면 다시 읽기를 해서 목록을 실제와 맞추고, 닫을 때 상태 줄 판정에도 넣는다. 늦은 표는 목록만 바꾼다.
- **응답 뒤 팝업**
  - **1·2단계로 끝난 응답**("변수가 삭제됐어요" · "다른 곳에서 바뀌었어요", 아무것도 안 바뀜): `base`를 새로 잡지 않고 [저장]을 잠근 채 둔다. 잠금은 팝업을 닫고 다시 열어야 풀린다.
  - **3단계에서 첫 변경부터 실패한 응답**(예: 피그마가 이름을 거절, `applied`가 빔): `base` 유지, 다시 읽기 없음, [저장]은 잠그지 않는다. 사유는 해당 칸 아래(이름 거절이면 이름 칸)와 알림 줄에, 포커스는 첫 오류 칸. 칸과 묶이지 않는 실패는 알림 줄에만 띄우고 포커스는 [저장]. 고쳐서 다시 저장할 수 있다.
  - **하나라도 바뀐 응답**(성공 · 일부 실패): 응답 뒤 처음 오는 변수 표로 `base`를 새로 잡는다. 그 표가 직전 표와 같아도 이 처리는 한다(A.3c).
    - `applied`에 든 칸과 **손대지 않은 칸**은 새 값으로 다시 그린다.
    - 실패해서 남은 칸만 입력을 그대로 둔다. 그래서 다시 [저장]하면 남은 것만 보낸다.
  - 성공: **문구를 띄우지 않는다**(2026-11-03 사용자 결정). 칸이 새 값으로 다시 그려지고(고친 표시가 사라짐), [취소]가 [닫기]로, [저장]이 잠김으로 바뀌는 것이 저장된 표시다. 알림 줄의 사건 문구는 지운다. 포커스는 [닫기].
  - 일부 실패 · 실패: 오류 줄에 사유. 일부만 바뀌었으면 "일부만 저장됐어요"를 덧붙인다. 포커스는 첫 오류 칸(없으면 [저장]).
- 값이나 별칭이 바뀌었으면 쓰인 곳을 다시 찾는다(간접 사용이 바뀔 수 있다). 규칙은 열 때와 같다(목록 기준 · 300개).
- **목록:** 새 변수 표로 목록·사이드바를 다시 그린다. 그룹이 옮겨져 고른 사이드바 그룹이 사라지면 지금 규칙(같은 컬렉션으로)을 따른다. 열린 상세는 닫지 않는다.

**팝업이 열린 동안 피그마에서 바뀐 것** (2026-11-03 사용자 결정 A)
- 팝업이 열려 있으면 창 다시 들어옴의 다시 읽기를 미룬다(§4.1 ④, 지금과 같음). 그 사이 피그마 패널이나 ⌘Z로 바뀐 것은 **저장할 때** 알려 준다(위 2단계 "다른 곳에서 바뀌었어요", 1단계 "변수가 삭제됐어요").
- 이 두 경우에는 [저장]을 잠그고(사유 같은 문구), 칸은 그대로 둔다. 닫으면 미뤄 둔 다시 읽기가 반영된다.

**닫기**
- 팝업에 "닫기 전 확인"을 둔다(A.3c). [취소] · Esc · 바깥 누름은 모두 같다.
  - 고친 것이 없으면 바로 닫는다.
  - 고친 것이 있으면 확인 줄 "고친 내용을 버릴까요? [버리기] [계속 고치기]"를 단추 줄 바로 위(팝업 안)에 띄우고 [계속 고치기]로 포커스를 옮긴다.
  - 확인 줄이 떠 있을 때 Esc는 [계속 고치기]와 같다(확인 줄을 닫고 직전 칸으로 포커스). [버리기]는 팝업을 닫는다.
- **닫은 뒤 포커스:** 지금 오른쪽 목록에서 **변수 id로 행을 다시 찾아** 그 행으로 간다(저장 뒤 목록을 다시 그렸으므로 원래 행 요소는 없다). 행이 지금 목록에 없으면(그룹을 옮김 등) 오른쪽 목록 머리로 포커스를 옮긴다. 사이드바에서 고른 항목은 바꾸지 않는다.
- **닫을 때 상태 줄**(상태 줄은 한 줄, 팝업이 열린 동안은 가려져 있었음): 저장 성공 문구는 띄우지 않는다. 팝업을 연 뒤 `applied`가 비지 않은 응답(무엇이든 바뀐 응답)이 한 번이라도 있었을 때만(닫는 방법 · [버리기]와 무관) 아래 중 하나를 띄운다.
  - 마지막으로 무엇이든 바뀐 응답이 일부 실패였고 행이 목록에 있으면: "일부만 저장됐어요"
  - 일부 실패였고 행이 목록에 없으면: "일부만 저장됐어요 · {새 이름} 행은 지금 고른 목록에 없어요"
  - 성공이었고 행이 목록에 없으면: "{새 이름} 행은 지금 고른 목록에 없어요"
  - 그 밖에는 아무것도 띄우지 않는다.

**포커스 순서** (팝업 안, Tab은 팝업 안에서만 돈다)
- 이름 칸 → 모드마다 값 칸(또는 알약 · 스위치) · [▾] → (열린 고르개: 검색 칸 → 목록) → 쓰인 곳([찾기] 또는 레이어 단추들) → (확인 줄: [버리기] · [계속 고치기]) → [닫기]/[취소] → [저장].

#### 키보드 (사이드바는 `tree`, 오른쪽 목록은 `grid`, 각각 정지점 1개)

- **포커스 순서:** 탭 → [—] → 머리줄(준비 현황 · 변수 없는 값 찾기 · [+] · [⋯] · [↻]) → 상황 안내 줄 버튼(있을 때) → 사이드바 → 오른쪽 목록 머리([모드 ▾] · [🔍]) → 오른쪽 목록 → 공통 상태 줄 버튼(있을 때).
- **사이드바 접근성:** 고른 항목은 `aria-selected="true"`. 항목의 접근성 이름에 숫자를 넣는다(예: "Semantic, 계층 S, 사용 7 / 전체 25", "선택에서 쓰는 것, 17개").

### 4.5 변수 탭 — 만들기

```
┌────────────────────────────────────────┐
│ ← 돌아가기                               │
│ ▸ 한 번에 정리                            │
│ (색)─(토큰)─(테마)─(타이포)               │
├────────────────────────────────────────┤
│ 카드 제목                                 │
│ [미리보기][적용][다음 →]                   │ ← 버튼 줄 (새로 고정)
│ (카드 내용 — 패널 스크롤)                   │
└────────────────────────────────────────┘
```

- 지금 만들기 탭의 4단계를 그대로 옮긴다(카드, 미리보기, 잠금, "다음 →", 레일).
- **토큰 단계에 보이는 카드는 1개**(간격·크기)다. 역할 매핑은 토큰을 적용할 때 자동으로 만들어진다.
- 타이포 단계의 "기존만 연결"은 레이어 › 연결로 옮긴다. 카드 안내는 "화면 연결은 레이어 › 연결에서"로 바꾼다.
- 타이포 단계 끝: "변수 탭으로", "레이어에 연결하기 →".
- 토큰 단계가 값을 격자로 옮기면, 옮긴 값의 변수는 원래 레이어에 연결되지 않는다(§2.11). 카드의 격자 안내는 "격자로 옮긴 {k}개 값은 원래 레이어와 달라 연결되지 않아요"로 바꾼다(허용오차를 올리라는 안내는 없앤다).
- 테마 단계에서 다크를 만들 변수가 없으면 "토큰 만들기로 →"(지금 버튼)를 보여 준다.
- "← 돌아가기"를 누르면 변수 탭 첫 화면으로 간다.

### 4.6 레이어 탭 — 연결

> **그림으로 읽히게 (2026-11-03 사용자 결정):** 사용자는 설명을 꼼꼼히 읽지 않는다. 지금 단계, 무엇이 무엇에 붙는지, 몇 곳인지를 글 없이 모양으로 보이게 한다. 글은 툴팁과 빈 상태 한 줄로만 남긴다.
> 이 절에서 "찾기"는 지금까지의 "미리보기"(연결하지 않고 후보만 계산)와 같은 동작이다.

```
┌────────────────────────────────────────┐
│  연결    이름    컴포넌트                 │  하위 탭 13px · 높이 32
│  ‾‾‾‾                                   │
├────────────────────────────────────────┤
│ (✓)찾기 ── (2)고르기 ── (3)연결           │ ← 단계 표시 (고정)
│ [🔍 다시 찾기] [🔗 6곳 연결]              │ ← 버튼 줄 (고정)
│ (찾음 18) (건너뜀 4 ▸)        [필터 🔍]  │ ← 배지 줄
│ ┌──────────────────────────────────┐  │
│ │ [8] → # spacing/8         12곳 ○  │  │ ← 변수 카드(끔 = 흐린 글자 + 회색 스위치)
│ └──────────────────────────────────┘  │
│ ┌──────────────────────────────────┐  │
│ │ [□#FFFFFF] → ● color/bg/surface 3곳▾ ●│ │ ← 변수 카드(켬, 펼침)
│ │    ▣ Card 채움                      │  │ ← 자리 줄(속성 아이콘 + 레이어 + 속성)
│ │    ▣ Title 채움                     │  │
│ │    ▣ Footer 채움                    │  │
│ └──────────────────────────────────┘  │
│ ┌ [16] → # spacing/16        2곳  ● ┐  │
│ ┌ [4]  → # radius/4          1곳  ● ┐  │
│ Aa 텍스트 스타일        [기존 스타일 연결] │
├────────────────────────────────────────┤
│ 상태 줄                                  │
└────────────────────────────────────────┘
```

와이어 숫자: 찾은 18곳 = spacing/8 12 + color/bg/surface 3 + spacing/16 2 + radius/4 1. spacing/8을 꺼서 버튼은 6곳이다. "건너뜀 4" = 사유별 숫자의 합(이미 연결됨 3 + 스타일 사용 중 1). 카드는 처음에 모두 접혀 있고, color/bg/surface는 사용자가 펼쳤다.

**단계 표시 (버튼 줄 위, 함께 고정)**
- ① 찾기 ─ ② 고르기 ─ ③ 연결. 동그라미 숫자 + 이름, 사이를 선으로 잇는다. 누를 수 없는 표시다(`aria-hidden`이 아니라 `role="list"`, 지금 단계에 `aria-current="step"`).
- 모양: 지금 단계 = 검은 동그라미 + `--text`, 끝난 단계 = `--ok` 동그라미 안 ✓ + `--ok` 글자, 아직 = 빈 동그라미 + `--muted`.

| 상태 | ① 찾기 | ② 고르기 | ③ 연결 |
|---|---|---|---|
| 선택 없음 · 연결할 변수 없음 | 아직 | 아직 | 아직 |
| 찾기 전 | 지금 | 아직 | 아직 |
| 찾은 뒤(1곳 이상) | 끝 | 지금 | 아직 |
| 찾은 곳 0 | 끝 | 아직 | 아직 |
| 연결 후 | 끝 | 끝 | 끝 |
| 찾는 중(진행률) | 지금(돌아가는 표시) | 아직 | 아직 |
| 찾기 취소됨 | 찾기 전과 같음 | | |
| 다른 선택에서 만든 결과(연결 잠김) | 지금 | 아직 | 아직 |
| 300개 초과 안내(⑧) | 찾은 뒤와 같음 | | |

**버튼**
- [🔍 찾기]: 찾기 전 주 버튼(파랑). 찾은 뒤에는 [🔍 다시 찾기](보조).
- [🔗 연결]: 찾기 전·찾은 곳 0·연결 후에는 숫자 없이 [🔗 연결] + `aria-disabled`. 찾은 뒤에는 [🔗 {n}곳 연결] 주 버튼(n = 켠 변수들의 곳 수 합).
- 잠금 사유(누르면 상태 줄): 선택 없음 "선택이 없어요" → 다른 선택의 결과 "선택이 바뀌었어요 · 다시 찾아 주세요" → 찾기 전·연결 후 "먼저 [찾기]를 누르세요" → 찾은 곳 0 "연결할 곳이 없어요" → 모두 끔 "연결할 변수를 켜세요".
- 아이콘은 글자 앞 14px. 접근성 이름은 글자만("찾기", "6곳 연결").

**빈 상태 (목록 자리, 점선 상자)**

| 상태 | 그림 | 한 줄 |
|---|---|---|
| 찾기 전 | 예시 두 줄 `[□#FFFFFF] → ● color/…`, `[16] → # spacing/…` — 계층이 지정된 로컬 컬렉션을 사이드바 순서로 훑어 첫 색 변수와 첫 숫자 변수를 쓴다(값은 그 컬렉션 기본 모드, 이름은 전체 경로를 140px에서 말줄임). 그런 변수가 없으면 그 종류 줄은 빼고, 둘 다 없으면 그림 없이 한 줄만 | "값이 변수와 같은 곳을 찾아 연결해요" |
| 선택 없음 | ⬚ ↖ (빈 사각형 + 커서) | "캔버스에서 레이어를 선택하세요" |
| 찾은 곳 0 | ∅ | "{선택 이름}에서 변수와 같은 값을 찾지 못했어요" |

- 연결할 변수가 없음 안내(아래 표)가 보이면 빈 상태 상자는 숨긴다(누를 수 없는 행동을 권하지 않게).
- 선택 이름은 찾을 때의 이름으로 고정한다(1개면 레이어 이름, 여럿이면 "레이어 {k}개", 20자 넘으면 줄임).

**배지 줄 (찾은 뒤)**
- 찾은 곳이 0이면 (건너뜀 {m} ▸)만 보이고(건너뛴 곳이 있을 때), (찾음)·모두 켜기/끄기·필터는 숨긴다.
- (찾음 {n}) — `--ok-subtle` 바탕 `--ok` 글자. n = 찾은 곳 수. 툴팁 "{선택 이름}에서 변수와 같은 값 {n}곳을 찾았어요 · 연결하지 않을 변수는 끄세요".
- (건너뜀 {m} ▸) — 회색 배지, 건너뛴 곳이 있을 때만. 누르면 아래에 사유 칩 줄이 펼쳐진다(▾). 펼침 버튼이다(`aria-expanded`, 접근성 이름 "건너뜀 {m}곳 사유 보기"). 사유 칩은 지금처럼 "{사유} {수} ›"이고 누르면 그 레이어를 캔버스에서 선택한다(툴팁 "레이어 {k}개 선택 — {이름들}", 잘렸으면 "· 목록은 {shown}개까지"). m = 사유별 숫자의 합(속성 단위).
- 오른쪽 끝에 [필터 🔍](24×24): 누르면 변수 이름 필터 입력칸이 배지 줄 아래에 열린다. 카드가 6개 이하면 숨긴다. 단 필터 칸에 글자가 있으면 카드 수와 관계없이 보인다.
- 오른쪽 끝(필터 앞)에 [모두 켜기]/[모두 끄기] 글자 버튼 하나: 보이는 카드가 하나라도 꺼져 있으면 "모두 켜기", 모두 켜져 있으면 "모두 끄기". 필터 중에는 보이는 카드에만 적용한다. 누른 뒤 포커스는 그 버튼에 남고, 바뀐 이름은 그대로 읽힌다(상태 줄 알림 없음).

**변수 카드 — "값 → 변수"**
- **"곳"** = 변수를 연결할 자리 하나(레이어 하나의 속성 하나). 네 방향 여백처럼 같은 레이어에서 같은 변수에 묶이는 자리는 자리 줄 한 줄이고 끝에 "· {k}곳".
- **카드 머리:** [값 칩] → [변수 칩] · {k}곳 [▾/▸] · [스위치]
  - 값 칩: 레이어의 값. 색은 견본(□) + #RRGGBB, 숫자는 숫자. `--surface` 바탕 + 테두리, 고정폭 글자.
  - → : `--accent-strong`.
  - 변수 칩: 타입 표시(● 색 · # 숫자 · T 글자) + 변수 이름. `--accent-subtle` 바탕 `--accent-strong` 글자. 이름이 길면 말줄임 + 툴팁.
  - {k}곳 ▾/▸: 누르면 자리 줄을 펼치고 접는다(24px 높이 버튼). 처음에는 모두 접힘. 직접 펼치거나 접은 카드는 세션 동안 기억한다.
  - **스위치**(`role="switch"`, 28×16, 누를 수 있는 영역 24×24 이상): 켬 = `--accent` 바탕, 끔 = 회색. 접근성 이름 "{변수 이름} 연결". 처음에는 모두 켬.
  - 끈 카드: 카드의 글자와 칩을 `--text-2`/회색으로 바꾼다(opacity를 쓰지 않음). 툴팁 "끄면 이 {k}곳은 그대로 둬요".
  - 카드 툴팁: "{변수 이름}을(를) 이 {k}곳에 연결해요 · 일부만 빼려면 그 레이어를 뺀 나머지를 선택하고 다시 찾기".
- **스위치는 변수 단위다.** 어떤 변수를 붙일지가 사용자의 판단이다(같은 값이지만 뜻이 다른 변수를 빼는 일).
  - **한계:** 한 변수의 일부 자리만 뺄 수는 없다. 피그마에서 연결을 풀어도 다음 찾기에서 다시 후보로 나오고 켜져 있다. 빼야 할 레이어가 있으면 그 레이어를 뺀 나머지 레이어들을 캔버스에서 직접 선택하고 다시 찾는다(선택한 프레임 안쪽 레이어라면 그 형제 레이어들을 선택한다).
- **자리 줄(보기만):** [속성 아이콘] 레이어 이름 · 속성 이름. 값은 카드 머리에 있으므로 쓰지 않는다.
  - 속성 아이콘(14px, 회색 네모 안). 연결 코드가 다루는 필드 전부:

    | 아이콘 | 필드 |
    |---|---|
    | ▣ | 채움(fills) |
    | ▢ | 선 색(strokes) |
    | ┃ | 선 두께(strokeWeight · 방향별 두께) |
    | ◰ | 모서리(cornerRadius · 모서리별) |
    | ⇔ | 여백·간격(padding 네 방향 · itemSpacing · counterAxisSpacing · 그리드 간격) |
    | ↔ | 크기(width · height · min/max) |
    | ◑ | 불투명도(opacity) |
    | T | 글자(fontSize · lineHeight · letterSpacing · fontFamily · 문단 간격) |
    | ◐ | 효과(effects 색) |
    | · | 그 밖(위에 없는 새 필드) |
  - 레이어 이름을 누르면 캔버스에서 그 레이어를 선택한다("이 화면에서 만든 선택" — 목록은 그대로). 툴팁 "캔버스에서 선택 · 이 목록은 그대로 둬요".
- **순서:** 곳 수가 많은 변수부터. 같으면 변수 이름 순.
- **필터:** 보이지 않는 카드의 스위치는 그대로 둔다. 버튼 숫자 n은 보이지 않는 카드를 포함한 전체 켠 곳 수다. 필터 중이고 보이지 않는 카드 중 켠 것이 있으면 필터 칸 옆에 "필터 밖 {h}곳 포함".
- **키보드:** 스위치(Tab · Space), ▾/▸(Enter · Space), 레이어 이름(링크 버튼). 카드는 정지점이 아니다.
- **포커스 순서:** 하위 탭 → 버튼 줄([찾기] · [연결]) → 배지 줄([건너뜀 ▸] · 사유 칩(펼쳤을 때) · [모두 켜기/끄기] · [필터]) → 필터 칸(열렸을 때) → 카드마다 [▾/▸] · 스위치 · (펼쳤으면) 레이어 이름들 → [기존 스타일 연결]. 단계 표시는 정지점이 아니다.
- 카드 사이 6px, 카드 모서리 8px, 머리 높이 32px.

**찾는 범위 (§2.11)**
- §2.11의 "같은 값"인 곳만 찾는다.
- 건너뛰는 곳: §2.11의 이미 붙은 것("이미 연결됨" · "삭제된 변수에 연결됨" · "스타일 사용 중"), §2.11의 "사이 간격 자동" · "소수 선 두께", 그 밖 지금 사유(크기 고정 아님 · 반투명 등).
- 인스턴스 안쪽은 찾지 않는다.
- [🔗 n곳 연결]을 누르면 각 자리를 다시 확인한다. 그 사이 붙었거나 스타일이 생겼거나 값이 달라진 곳은 연결하지 않고 연결 후 건너뜀으로 센다. 그 사이 정렬이 Space between으로 바뀐 간격은 "사이 간격 자동"으로 센다. 그 사이 줄바꿈이 꺼진 줄 사이 간격은 "그 사이 바뀜"으로 센다(§2.11 "줄바꿈이 아님").

**남는 것**

- 변수 이름 필터(찾은 뒤, 카드 7개 이상일 때)

**없애는 것**
- 연결 현황 버튼과 자동 조회, 흐리게 하던 대기 처리, "=" 줄, 연결 후 결과 트리, "변수 관리에서 보기"
- **레이어 트리 모양의 후보 목록**(레이어 머리 + 그 아래 후보 카드). 변수별 묶음으로 바꾼다.
- 자리마다의 체크, 여러 문장 설명, 칩 아래 "건너뜀 사유 · 누르면…" 안내 줄
- (그림 개편) 카드 제목 "변수 연결", 찾기 전 한 줄 글, 설명 문장, 목록 머리(열 이름)와 전체 체크박스, 변수 묶음 줄의 체크박스 → 단계 표시 · 빈 상태 그림 · 배지 · 스위치로

**연결 후**
- 배지 줄·필터·카드를 지우고, 결과 카드 하나를 둔다: `--ok-subtle` 바탕 "🔗 {n}곳 연결됨" + 오른쪽 "변수 탭에서 보기 →".
- 연결할 때 다시 확인해서 건너뛴 곳이 있으면 결과 카드 아래에 (건너뜀 {m} ▸) 배지를 두고, 누르면 그 사유 칩이 펼쳐진다(m = 그 곳 수). 찾을 때의 건너뜀은 지운다.
- 단계 표시는 셋 다 끝(✓). 버튼은 [🔍 다시 찾기](주 버튼) + [🔗 연결](잠금, 사유 "먼저 [찾기]를 누르세요").

**연결할 변수가 없을 때** (지금 경고 자리)

| 상황 | 안내 |
|---|---|
| 로컬 변수 0개 + 선택에 라이브러리 연결 있음 (②) | "이 파일엔 로컬 변수가 없어요 · 라이브러리 변수 연결은 피그마 오른쪽 패널에서 해요". "토큰 만들기로 →"는 숨김 |
| 로컬 변수는 있지만 계층이 지정된 컬렉션 없음 | "변수는 있지만 계층이 지정되지 않았어요 · [계층 지정하기 →]" |
| 로컬 변수 0개 (유료) | 지금 경고 + "토큰 만들기로 →" |
| 로컬 변수 0개 (무료) | "연결할 변수가 없어요 · 변수 만들기는 유료 기능이에요 [라이선스 →]" |

- ②는 라이브러리 사용 여부를 읽었을 때만 판정한다. 선택이 없거나, 300개를 넘거나, 아직 읽는 중이면 ② 행을 건너뛰고 "로컬 변수 0개 (유료)" / "로컬 변수 0개 (무료)" 행을 보여 준다.
- "계층이 지정된"은 직접 지정했거나 이름(Global · Semantic · Component)으로 정해진 계층을 모두 포함한다(§4.4 사이드바 계층 배지와 같다).

**"변수 없는 값 찾기"로 들어올 때** (§0·§3.1이 가리키는 예외)

| 상황 | 동작 |
|---|---|
| 같은 선택의 찾은 결과가 이미 있음 | 다시 실행하지 않고 화면만 보여 줌 |
| 찾기나 연결이 실행 중 | 화면만 보여 줌 |
| 연결할 변수가 없음 | 찾기를 보내지 않고 위 안내 |
| 그 밖 | 찾기 실행 |

**다른 탭에서 돌아오거나 창에 다시 들어올 때 (⑧)**
- **조용히 다시 계산하는 경우:** 찾은 결과가 있고, 그 찾기가 만들어진 뒤 창을 떠났었고, 선택 노드가 300개 이하일 때.
  - 스위치는 변수 단위로 이어받는다. 전에 있던 변수는 켬/끔을 유지하고, 새로 생긴 변수는 켠다. 펼침 상태와 스크롤·포커스는 바꾸지 않는다(§2.6·§4.1).
  - "같은 곳" = 같은 레이어 · 같은 속성 · **같은 변수**. 변수가 바뀐 곳은 제외 1 + 추가 1로 센다.
  - 후보가 달라졌을 때만 상태 줄에 "후보가 바뀌었어요 · {a}곳 추가 · {b}곳 제외"를 띄운다.
- **안내만 하는 경우:** 300개를 넘으면 결과 위에 "피그마에서 바뀌었을 수 있어요 · [다시 찾기]"를 둔다.
- **아무것도 하지 않는 경우:**
  - 이 화면에서 만든 선택(사유 칩, 자리 줄의 레이어 이름) 직후의 복귀
  - 최소화 중에 끝난 찾기
- **찾은 결과가 지워질 때:** 사용자가 캔버스에서 선택을 바꾸거나 풀면 찾은 결과·스위치·연결 후 결과를 지우고 "찾기 전"으로 돌아간다. 예외는 플러그인이 바꾼 선택이다 — 이 화면에서 만든 선택(위 "아무것도 하지 않는 경우")과 다른 화면에서 만든 선택(아래 "선택이 다른 경우")은 결과를 남긴다. 
- **선택이 다른 경우 (조용한 재계산보다 먼저 판정, 재계산하지 않음):** 다른 화면에서 플러그인이 선택을 바꾼 뒤(변수 탭의 사용 레이어 선택, 삭제된 변수 [선택], 상세 항목 클릭) 돌아오면, 결과와 스위치는 그대로 두고 결과 위에 "다른 선택에서 만든 결과예요 · [다시 찾기]"를 둔다. [🔗 n곳 연결]은 `aria-disabled`이고, 사유는 "선택이 바뀌었어요 · 다시 찾아 주세요"다.

**텍스트 스타일 "기존 스타일 연결"** (무료, 카드 목록 아래 한 줄 "Aa 텍스트 스타일 [기존 스타일 연결]")
- 등록된 텍스트 스타일이 없으면 `aria-disabled`이고, 사유는 "등록된 텍스트 스타일이 없어요 · 타이포에서 등록 →(유료)"다.
- 결과는 버튼 아래 한 줄 "✓ 텍스트 {n}개에 스타일 연결 · 건너뜀 {m}"이다. m = 건너뛴 텍스트 레이어 수. 줄의 툴팁에 사유별 수를 적는다(예: "이미 스타일 있음 3 · 같은 스타일 없음 2 · 같은 모양 스타일이 둘 이상 1 · 글자 속성에 변수 있음 1 · 서식이 섞임 1").
- 건너뛰는 글자: §2.11의 이미 붙은 것(텍스트 스타일 · 글자 속성의 변수), 인스턴스 안쪽, 서식이 섞인 글자(구간마다 크기·글꼴이 다름).
- §2.11의 모든 글자 속성이 같은 스타일에만 붙인다. 줄 높이 단위만 다르고 실제 높이가 같으면 같다(예: 16px 글자의 줄 높이 24px ↔ 150%로 등록된 스타일). 숫자를 다른 단위로 읽어야만 맞는 경우(줄 높이 150px ↔ 150%)는 모양이 달라지므로 건너뛴다.
- 같은 모양의 스타일이 둘 이상이면 건너뛴다(지금처럼).

**선택이 없을 때**
- [🔍 찾기], [🔗 연결](선택을 풀면 찾은 결과가 지워지므로 — ⑧ "찾은 결과가 지워질 때" — 숫자 없는 이름), [기존 스타일 연결]이 `aria-disabled`이고, 누르면 사유가 뜬다. 목록 자리에는 "선택 없음" 빈 상태 그림이 보인다.
- 사유가 겹치면 "선택이 없어요"가 먼저다(버튼 절의 순서).
- ⑧의 "안내만 하는 경우"(300개 초과)에도 [🔗 n곳 연결]은 누를 수 있다. 연결할 때 다시 확인하므로 그 사이 바뀐 곳은 건너뛴다.

### 4.7 레이어 탭 — 이름, 컴포넌트

- 지금 적용 탭의 두 단계를 그대로 옮긴다.
- 단계 레일을 밑줄 하위 탭으로 바꾸고, **연결·이름 카드의 "다음 →" 두 개를 모두 없앤다.** 세 작업은 순서가 없다.
- 버튼 줄은 고정한다. 결과 트리는 패널 스크롤이다.
- [묶기]·[등록] 버튼의 툴팁 끝에 "원본의 연결과 값은 마스터를 따라요"를 붙인다(§2.11 예외).

#### 인스턴스 자리 (2026-11-04, QA #3 불합격 3 · 코드 대조 검토 뒤 고침)

레이어를 마스터의 인스턴스로 바꾸는 세 곳이 이 규칙을 함께 쓴다(공용 모듈 하나).
- **[등록]** — 단독 · 베리언트 세트 · 속성 접힘. 원본 레이어 자리를 인스턴스로 바꾼다.
- **[묶기]** — 마스터가 아닌 멤버 자리를 인스턴스로 바꾼다.
- **아이콘 자리 교체** — [등록]의 속성 접힘에서, 마스터 안의 날 벡터 자리를 아이콘 컴포넌트의 인스턴스로 바꾼다(그림이 다른 슬롯을 인스턴스 바꾸기 속성으로 담기 위해).

인스턴스는 **원본이 있던 자리에만** 둔다.

1. **같은 부모, 같은 순서.** 인스턴스는 원본의 부모 안, 원본이 있던 순서(index)에 넣는다.
2. **같은 위치, 같은 크기 규칙.**
   - 부모가 오토레이아웃이면 위치는 레이아웃이 정한다(x·y를 쓰지 않는다). 원본이 절대 배치(`layoutPositioning = 'ABSOLUTE'`)였으면 인스턴스도 절대 배치로 하고, x·y와 제약(constraints)을 원본과 같게 한다.
   - 그 밖에는 x·y와 제약을 원본과 같게 한다.
   - 크기 규칙을 원본에서 이어받는다(2026-11-04 사용자 결정): 가로·세로 크기 방식(`layoutSizingHorizontal` · `layoutSizingVertical` — 채우기 FILL · 내용 맞춤 HUG · 고정 FIXED), 늘이기(`layoutGrow`), 맞춤(`layoutAlign`), 최소·최대 크기(`minWidth` · `maxWidth` · `minHeight` · `maxHeight`). 넣은 **뒤에** 하나씩 따로 시도하고, 인스턴스와 이미 같은 값은 건너뛴다. 피그마가 거절하는 조합(예: 오토레이아웃이 아닌 부모에서 FILL, 오토레이아웃이 아닌 마스터의 HUG)은 그 하나만 건너뛰고 나머지는 계속한다. 건너뛴 크기 규칙은 실패로 세지 않는다.
3. **원본을 비우는 순서.**
   - **[묶기] · 아이콘 자리 교체 · [등록] 속성 접힘의 마스터가 아닌 멤버는 넣고 나서 지운다.** 인스턴스를 먼저 그 자리에 넣고, 그 뒤에 원본을 지운다. 부모의 자식 수가 잠깐이라도 0이 되지 않으므로 4번의 표지가 필요 없다. 속성 접힘 멤버는 컴포넌트로 바꾸지 않는다 — 인스턴스를 만들어 8번 검사를 통과해야 넣고, 통과하지 못하면 원본을 손대지 않고 그대로 둔다(원본을 복제해 둘 필요가 없다).
   - **[등록]의 단독 · 세트 · 속성 접힘의 마스터는 원본이 먼저 빠진다.** 원본 자체가 컴포넌트가 되어 Components 페이지로 옮겨진다. 그 뒤에 인스턴스를 만들어 원본 자리에 넣는다. 그래서 4번의 표지로 그룹을 지킨다.
4. **부모가 그룹(GROUP)일 때.** 피그마는 자식이 0개가 된 그룹을 바로 지운다.
   - [등록]은 원본을 바꾸기 **전에** 원본 바로 앞에 빈 표지 레이어(사각형, 채움·선 없음, 원본과 같은 위치·크기)를 넣어 그룹을 지킨다. 표지의 크기·위치는 그룹에 넣기 **전에** 정한다(넣는 순간 그룹 경계가 잠깐 바뀌지 않게). 인스턴스는 표지 자리에 넣고 표지는 지운다.
   - 표지는 실행이 끝나면 어떤 경우에도 남지 않는다. 표지를 만든 뒤 그룹에 넣거나 칠하기를 비우다 실패하면 그 표지를 바로 지운다(페이지 맨 위에 남기지 않는다). 표지 없이 기록한 순서로 넣기를 시도한다.
   - 표지는 GROUP 부모에만 넣는다. [묶기] · 아이콘 자리 교체에는 넣지 않는다(3번).
   - 그룹 자식의 x·y는 그룹 밖 가장 가까운 프레임 기준이다. 넣은 뒤 인스턴스의 절대 위치(`absoluteTransform`)를 원본의 절대 위치와 비교해 다르면 그만큼 x·y를 고친다. 그룹이 회전·뒤집힘·배율이 없을 때만 고친다.
   - **불리언 연산(BOOLEAN_OPERATION) 부모:** 그룹처럼 자식이 0개가 되면 사라지고 x·y 기준도 같으므로 절대 위치 보정은 같게 한다. 표지는 넣지 않는다 — 표지 사각형이 불리언 모양에 더해지기 때문이다. 불리언 연산은 인스턴스를 자식으로 받지 않을 수 있다. 그러면 [묶기]는 원본을 그대로 두고, [등록]은 5번의 복사본으로 채운다. 원본이 그 불리언의 유일한 자식이었으면 원본이 옮겨질 때 불리언이 사라져 자리가 빈다.
5. **못 넣으면 페이지 맨 위에 두지 않는다.** 부모가 없어졌거나 넣기가 실패하면 인스턴스를 페이지 맨 위(0, 0)에 두지 않고 지운다. 인스턴스 만들기(`createInstance`) 자체가 실패해도 같다.
   - [묶기]: 원본을 그대로 둔다(원본은 아직 지우지 않았다).
   - 아이콘 자리 교체: 마스터 안의 벡터를 그대로 두고, 그 슬롯은 인스턴스 바꾸기 속성이 되지 않는다. 실패 진단 목록에 "아이콘 자리 교체 실패({레이어 이름})"를 남긴다. 원본 레이어 자리가 아니므로 아래 두 목록에는 넣지 않는다.
   - [등록] (2026-11-04 사용자 결정): 원본은 이미 마스터가 되어 Components 페이지에 있거나 지워졌으므로, 자리를 **복사본**으로 채운다.
     - 복사본 = 같은 마스터의 인스턴스를 새로 만들어(속성 접힘이면 그 멤버의 속성 값·사진까지 넣고) 바로 떼어 낸(`detachInstance`) 보통 프레임. 컴포넌트와 이어지지 않은 보통 레이어이고, 이름은 원본 레이어 이름이다.
     - 떼어 내는 것은 바깥 한 겹뿐이다. 복사본 안에 들어 있는 중첩 인스턴스(아이콘 자리 교체로 넣은 아이콘 인스턴스 등)는 그 컴포넌트에 연결된 채로 남는다.
     - 복사본도 1~4번 규칙으로 같은 자리에 넣는다. 넣지 못하면 떼어 낸 프레임에 자식이 하나뿐일 때(예: 벡터 아이콘) 그 자식만 같은 규칙으로 넣어 본다.
     - 그래도 못 넣거나 인스턴스를 만들 수 없으면 자리를 비운다.
   - **결과 줄 꼬리**(이름은 원본 레이어 이름, 3개까지 + " 외", 순서대로 속성 값 → 채움·크기 → 복사본 → 빈 자리):
     - [등록] 속성 접힘에서 속성 값·사진을 못 넣은 멤버(6번): " · 속성 값을 못 넣은 {n}개: {이름들}"
     - [등록] 속성 접힘에서 8번 검사로 묶지 않은 멤버: " · 채움·크기가 달라 건너뛴 {n}개: {이름들}"
     - [등록]의 복사본: " · 제자리에 인스턴스를 못 넣어 복사본을 둔 {n}개: {이름들}"
     - 빈 자리([등록]) · 원본을 그대로 둔 자리([묶기]): " · 제자리에 못 둔 {n}개: {이름들}"
     - 어느 꼬리든 있으면 상태를 경고로 하고, 최소화 중이면 ⚠(§4.9). [묶기]의 결과 메시지(`COMPONENTIZE_RESULT`)도 `placeFailed`를 싣는다 — [등록]과 같은 꼬리·경고·⚠가 여기서 나온다. [묶기]에서 인스턴스가 하나도 없는 결과 줄("컴포넌트화하지 못했어요 — …")에도 같은 꼬리를 붙인다.
     - 실패 진단 목록(§4.9 ⚠ 대상)에도 이름마다 남긴다. 실행 전체는 ⌘Z 한 번으로 되돌린다.
   - **문구(i18n)**

     | 키 | 문구 |
     |---|---|
     | `component.placeFailed` | " · 제자리에 못 둔 {n}개: {names}" |
     | `component.placeCloned` | " · 제자리에 인스턴스를 못 넣어 복사본을 둔 {n}개: {names}" |
     | `component.propFailed` | " · 속성 값을 못 넣은 {n}개: {names}" |
     | `component.fillKept` | " · 채움·크기가 달라 건너뛴 {n}개: {names}" |
     | `component.placeFailedMore` | " 외" (네 꼬리가 함께 씀) |

6. **[등록] 결과 줄의 수.** "컴포넌트 {registered} · 베리언트 세트 {sets}" 뒤에 " · 건너뜀 {m}"(§2.9 — "스킵"이라 쓰지 않는다) · 단일 · 속성 · 아이콘 · 5번 꼬리 순이다.
   - 건너뜀 m = 컴포넌트로 만들지 못한 대상 수(사라진 레이어 · 대상이 아닌 레이어 · 컴포넌트화 실패).
   - 자리 결과(인스턴스 · 복사본 · 빈 자리)는 건너뜀에 넣지 않는다. 원본은 이미 컴포넌트로 등록됐기 때문이다. 복사본·빈 자리는 5번의 두 목록으로만 센다. 인스턴스 만들기 실패와 넣기 실패를 같은 길(5번)로 센다.
   - **속성 값을 못 넣을 때 (2026-11-04 사용자 결정).** 속성 접힘에서 멤버 인스턴스에 속성 값(텍스트 · 인스턴스 바꾸기 · 보이기)이나 사진(fill 덮어쓰기)을 넣다가 실패하면, 인스턴스는 지우지 않고 그 자리에 둔다. 넣지 못한 속성·사진은 마스터 값 그대로다.
     - 속성 값은 한 번에 넣어 보고, 실패하면 속성마다 따로 넣어 본다. 그래도 안 되는 속성만 마스터 값으로 남는다.
     - 그 멤버(원본 레이어 이름)를 결과 줄 꼬리 " · 속성 값을 못 넣은 {n}개: {이름들}"에 한 번 센다(속성·사진 실패를 합쳐 멤버당 1). 실패 진단 목록에는 멤버와 속성(또는 사진 경로)마다 남긴다. 상태는 경고, 최소화 중이면 ⚠.
     - 이 멤버는 등록·자리 결과로는 성공이다(건너뜀 · 복사본 · 빈 자리에 넣지 않는다). 자리를 복사본으로 채우게 되면 복사본도 같은 값으로 만들고, 실패는 한 번만 센다.
     - 그 자리가 결국 **빈 자리로 끝나면** 그 자리를 채우며 기록한 속성 값 항목만 꼬리에서 빼고(이름으로 찾지 않는다 — 같은 이름의 다른 멤버 항목은 그대로) " · 제자리에 못 둔 {n}개"(5번)에만 센다 — 남은 레이어가 없으니 속성 값을 따질 것이 없다. 실패 진단 목록의 속성별 줄은 그대로 둔다.
     - 속성 이름은 컴포넌트 속성 정의의 **키**에서 읽는다. 피그마는 텍스트·인스턴스 바꾸기·보이기 속성의 키를 "이름#id"(예: `Title#12:3`)로 주고, 정의 값에는 이름이 없다. 키 끝의 "#…"를 떼면 이름이다. 베리언트 속성은 키에 "#"가 없으므로 키가 곧 이름이다.
   - 속성 접힘에서 마스터가 아닌 멤버는 원본이 자리에 남아 있으므로 5번의 복사본으로 가지 않는다. 넣기에 실패하면 [묶기]처럼 원본을 그대로 두고 " · 제자리에 못 둔"에 센다.
7. **결과.** 바뀐 원본 수만큼 인스턴스(또는 [등록]의 복사본)가 생기고 부모·형제·그룹은 그대로다. 페이지 맨 위에 새로 생기는 레이어는 Components 페이지로 옮겨진 컴포넌트·세트뿐이다. 작업이 경고로 끝나도 파일을 바꿨으면 다시 읽는다(§4.1).
8. **사진·크기 지키기 — [등록] 속성 접힘 (QA #3 실기 ② 불합격 6).**
   - 원인 기록: 속성 접힘은 멤버마다 사진과 크기가 다를 수 있다. 사진 슬롯을 찾을 때 레이어 자신(루트)을 빼서, 레이어 자신이 사진인 멤버(사각형 히어로 이미지 · 카드 사진 · 원 아바타)의 사진을 옮기지 않았다. 크기도 맞추지 않았다. 그래서 인스턴스가 마스터 사진·크기로 바뀌었다. 단독 · 세트는 원본이 저마다 컴포넌트가 되므로 해당 없다.
   - **사진 슬롯에 레이어 자신도 넣는다.** 멤버 사이에 이미지 해시가 다른 레이어(자신 포함)의 채움 전체(이미지 해시 · 맞춤 방식 `scaleMode` · `imageTransform` 등)를 인스턴스의 같은 경로 레이어에 덮어쓴다(인스턴스 오버라이드).
   - **경로 맞추기:** 피그마는 도형(사각형 · 원 등)을 컴포넌트로 만들 때 컴포넌트 프레임으로 감싼다. 마스터 컴포넌트의 자식이 하나이고 그 종류가 원본 도형과 같으면, 인스턴스에서는 경로 앞에 그 자식을 붙여 찾는다.
   - **크기:** 인스턴스를 멤버 크기로 바꾼다(`resize`).
   - **검사(넣기 전):** 멤버 안에서 사진 채움이 있는 모든 레이어(자신 포함)마다, 인스턴스의 같은 경로 레이어가 같은 이미지 해시와 같은 크기(소수 둘째 자리)인지 본다. 인스턴스 자신의 크기도 멤버와 같아야 한다. 하나라도 다르면(예: 감싼 도형에 제약이 없어 인스턴스를 키워도 사진 레이어가 따라오지 않음 — 1000×333 멤버가 280 높이로 남음) 인스턴스를 지우고 멤버 원본을 그대로 둔다.
   - 그대로 둔 멤버는 결과 줄 꼬리 " · 채움·크기가 달라 건너뛴 {n}개: {이름들}"(5번 문구 표)에만 센다. 건너뜀 m · 속성 값 꼬리 · 제자리 꼬리에는 넣지 않는다. 상태는 경고, 최소화 중이면 ⚠. 실패 진단 목록에는 멤버와 다른 점(경로 · 해시 또는 크기)을 남긴다.
   - 마스터 자신은 검사하지 않는다(마스터의 인스턴스는 언제나 같다).

#### 베타 (2026-11-04 결정 A, QA #3 불합격 4)

v1.0에서 레이어 › 컴포넌트 하위 탭은 **베타**다. 기본으로 숨긴다.

- **켜는 곳:** 설정 › 기본값 카드 맨 아래 체크박스 "컴포넌트(베타) 보이기"(§4.8). 처음 상태는 끔이다. 이전 버전을 쓰던 사람도 끔에서 시작한다(옮겨 오는 값 없음).
- **기억:** 켬/끔은 다른 기본값(기준 크기 · 이름 정리 깊이 · 격자)과 함께 저장한다. 플러그인을 다시 열어도 유지된다(§2.6 "플러그인이 열려 있는 동안만"의 예외 — 설정값이므로).
- **유료와 무관:** 무료·유료 모두 켤 수 있다. 켠 뒤의 잠금은 §6 그대로다(후보 스캔·등록·묶기 등은 유료 🔒, 닮은 스캔은 무료).
- **끔일 때 (기본):**
  - 레이어 하위 탭은 연결 · 이름 둘이다. 하위 탭 바에 컴포넌트 탭이 없다(흐리게 두지 않는다). 키보드 화살표는 보이는 두 탭만 돈다 — 화살표 이동은 하위 탭 목록(`APPLY_STEPS`)에서 보이는 탭만 걸러 낸 목록으로 계산한다(Home·End도 같다).
  - 준비 현황 팝오버의 각주 "컴포넌트는 필요할 때 레이어 › 컴포넌트에서"를 숨긴다.
  - 마법사의 컴포넌트 옵션은 지금처럼 숨긴다(v1.0 마법사는 켬/끔과 관계없이 컴포넌트를 등록하지 않는다).
  - 기억해 둔 레이어 하위 화면이 컴포넌트면(같은 세션에서 켰다가 끈 경우) 레이어 탭은 연결로 연다.
  - 컴포넌트 작업이 도는 중에 끄면 작업은 끝까지 돈다. 결과 줄은 숨은 카드에 남는다. 최소화 중 실패의 [보기](§4.9)는 컴포넌트 카드 대신 설정 › 기본값의 이 체크박스로 간다.
- **켬일 때:**
  - 하위 탭은 연결 · 이름 · 컴포넌트 셋이고, 컴포넌트 이름 뒤에 [베타] 배지를 붙인다.
  - 컴포넌트 카드 제목 "컴포넌트" 뒤에도 [베타] 배지를 붙인다.
  - 배지 모양: 글자 "베타", 10px/600, `--surface-2` 바탕, `--text-2` 글자, 모서리 4px, 좌우 여백 4px. 누를 수 없다. 배지는 접근성 트리에서 숨기고(`aria-hidden`), 하위 탭의 접근성 이름은 `layer.componentsBetaAria` "컴포넌트 (베타)"로 준다.
  - 켠 순간 화면을 옮기지 않는다. 공통 상태 줄에 "레이어 › 컴포넌트(베타)를 켰어요"를 띄운다. 끌 때는 "레이어 › 컴포넌트(베타)를 숨겼어요".

### 4.8 설정 탭

- 기본값(기준 크기 · 이름 정리 깊이 · 격자), 라이선스.
  - **허용오차는 없앤다**(2026-11-03 결정). 연결은 언제나 §2.11의 "같은 값"만 찾는다. 이전 버전에서 저장된 허용오차 값은 읽지 않는다(다른 기본값은 그대로 읽는다).
  - 격자 툴팁에서 허용오차와 짝을 이루는 설명을 지운다. 격자는 만들기가 값을 맞추는 간격이다.
  - 기본값 안내: "변수 만들기와 연결에 쓰는 값이에요"
  - 결제 버튼: "결제 · 구독 관리 ↗"
  - 맨 아래 체크박스 "컴포넌트(베타) 보이기"(기본 끔, 저장함) — §4.7 "베타".
- 컬렉션 계층과 내보내기는 변수 탭 ⋯로 옮긴다.
- "라이선스 →"로 들어오면 라이선스 카드로 스크롤하고 키 입력칸에 포커스한다.

### 4.9 최소화

```
펼친 상태                          최소화 상태 (140 × 104)
┌──────────────────────┐          ┌──────────────────────┐
│ [변수] 레이어 설정  — │   [—] →  │   [ ↙↗ ]   │
│ …                    │   ← 클릭  └──────────────────────┘
└──────────────────────┘          실행 중: 테두리 · 끝: ✓ / ⚠
```

- **펼치기 버튼:** 창 가운데 40×40 둥근 사각형(`--surface-2` 바탕, 8px 모서리)에 펼치기 아이콘(↙↗ 16px, `--text-2`). (2026-11-03 사용자 지정: 80×80은 너무 큼) 피그마가 그리는 창 머리(플러그인 아이콘 · ✕)는 그대로다.
- **진행 테두리 규칙:** 사용자가 일으킨 작업 요청을 보내고 그 결과가 올 때까지 그린다. 대상은 미리보기·적용·만들기·등록·스캔·추출·내보내기·마법사다.
  - 조용한 다시 읽기는 대상이 아니다.
  - 진행률이 있으면(연결 화면의 찾기·연결) 그 비율만큼, 없으면 회전으로 그린다.
- **✓ / ⚠** (14px 배지, ✓ `--ok`, ⚠ `--danger`)

| 결과 | 표시 |
|---|---|
| 성공 | ✓ 3초 |
| 실패(오류 응답, 유료 잠금 응답, 다크 생성 오류, 컴포넌트 실패 1건 이상, 마법사 단계 실패) | ⚠, 펼칠 때까지 유지 |
| 취소, 최소화 중 선택이 바뀌어 미리보기가 버려짐 | 표시 없음 |

- **펼칠 때**
  - ⚠가 있었으면 공통 상태 줄에 "{작업 이름} 실패 · [보기]"를 남긴다. [보기]는 그 작업의 탭과 카드로 간다. 예외: 컴포넌트 작업인데 그 사이 컴포넌트(베타)를 껐으면 설정 › 기본값의 "컴포넌트(베타) 보이기" 체크박스로 간다(§4.7 "베타").
  - 보던 화면을 유지하고, 포커스는 [—]로 간다. 다시 읽기가 1번 일어난다.
- 접근성 이름은 "펼치기"다. 작업 중이면 "펼치기 · 작업 중", 실패면 "펼치기 · 실패한 작업 있음"이다.
- 최소화할 때 메뉴·팝업은 닫는다. 작업은 계속된다. 다시 열 때 최소화는 기억하지 않는다.
- 피그마 플러그인 창의 최소 크기는 너비 70, 높이 0이다(사실).

## 7. 주요 흐름

**A. 처음 쓰는 파일 (로컬 변수 0)**
1. 열기 → 불러오는 중 → 시작 화면
2. 유료: 프레임 선택 → [전체 실행] → (실행 중 시작 화면 유지) → "변수 n개를 만들었어요 · [변수 목록 보기]" + 요약 끝 "레이어 › 연결에서 확인하고 연결하기 →" → 레이어 › 연결(찾기 자동) → 변수 카드 확인 → [🔗 n곳 연결]
3. 무료: 프레임 선택 → [이름 정리 실행] → "레이어 이름 n개 정리 · 변수는 만들지 않았어요"

**B. 변수가 있는 파일에서 "이 프레임이 뭘 쓰지?"**
1. 열기 → 목록(사이드바 첫 컬렉션 + 안내)
2. 프레임 선택 → "…" → 사이드바 "★ Inspect"이 골라지고 쓰는 행만 보임 → 행 더블클릭 → 상세(쓰인 곳)

**C. 변수 없는 값 연결**
- 목록 "변수 없는 값 찾기 →" → 레이어 › 연결(찾기 자동) → 빼고 싶은 변수 끄기 → [🔗 n곳 연결] → "변수 탭에서 보기 →" → 목록(기준 = 지금 선택, 작업 직후 다시 읽기)

**D. 피그마에서 직접 바꾼 뒤 확인**

- ⋯ → 코드로 내보내기 → 형식 → 저장

**G. 최소화**
- [—] → 작업 → ✓/⚠ → 펼치기 → 실패면 상태 줄 "[보기]"
