# IA v4 — 선택 탭 · 변수 탭 · ⚙ (2026-11-09 사용자 확정)

> 시안 9장(2026-11-09 확정): ① 선택 탭 ② 쓰는 변수 펼침 ③ 선택 없음 ④ 변수 없는 파일 ⑤ 변수 탭 ⑥ 변수 탭 ＋ 메뉴 ⑦ 연결 화면 ⑧ 변수 만들기 ⑨ 이름 정리.
> 이 문서는 ia-v3의 **화면 구조**(§3 전체 구조 · §3.1 이동 · §4 화면별 상세 · §5 이동표 · §6 유료 · §7 흐름 · §8 크기)를 바꾼다. **ia-v3 §4.4 "변수 목록 개편"과 A.13은 이 문서가 통째로 대체한다**(A.13 체크리스트는 닫고 B.3으로 옮김). ia-v3의 원칙 중 §2.2에 적은 것은 그대로 쓰고, 여기서 다르게 적은 것만 바뀐다. 둘이 다르면 이 문서를 따른다.

## 0. 결정 요약

| 항목 | 결정 |
|---|---|
| 탭 | **[선택] [변수]** 두 개 + ⚙(설정) + —(최소화). 레이어 탭 · 설정 탭은 없앤다 |
| 탭 규칙 | **선택 탭 = 지금 선택한 레이어에서 할 일, 변수 탭 = 파일의 변수** |
| 선택 탭 첫 화면 | 선택 이름 + 카드 최대 3장(변수 없는 값 · 쓰는 변수 · 삭제된 변수) + 맨 아래 "레이어 정리"(이름 정리 · 컴포넌트) |
| 연결 | 카드 [n곳 연결] → 연결 화면 하나(찾기 · 고르기 · 연결 3단계를 합침). 찾기는 목록 기준이 바뀌면 자동(300개 규칙) |
| 만들기 | 화면 하나(종류 체크 + "만든 뒤" 옵션) — v3 시작 화면 마법사를 대신한다. 자세한 화면은 [값을 직접 고르기 →](v3 만들기 4단계 색 · 토큰 · 테마 · 타이포) |
| 변수 탭 | 사이드바 = 컬렉션만. 오른쪽 = 그룹 머리 → Global은 값 알약 · 색 동그라미, 그 밖은 줄(이름 · 값). 사용 수 · 사용 표시 없음 |
| 변수 클릭 | **지금 캔버스 선택에 연결**(이미 붙은 것도 바꿈, Global도 — 사용자가 직접 고른 경우의 예외, §2.3) |
| 우클릭 | 다른 곳에 연결 ▸ · 상세… · 복제 · 삭제 (라이브러리 변수는 상세…만) |
| 상세 | "상세"와 "고치기…"를 하나로. 이름 복사 · CSS 복사 · 가리키는 변수로 → · 쓰인 곳 {n}곳 · [모두 선택] |
| 간접 사용 | 세지도 보이지도 않는다(↳ 없앰, Global의 사용 표시 없음, 상세의 간접 줄 없음, 계산 코드도 지움) |
| 변수 추가 · 복제 | 무료, 단 개수 제한(숫자 · 기준은 추후 결정 — §9) |
| 삭제 | 무료, 확인 창 늘 띄움(라이브러리 게시 경고는 넣지 않음) |
| 설정 | ⚙ → 설정 화면(기본값 · 라이선스) |

## 1. 왜 바꾸나

- 사용자가 하는 일은 셋이다: ① 선택한 디자인을 변수에 **연결** ② 변수가 없으면 **만들기** ③ 변수 **보기 · 고치기**. 가끔 하는 일로 레이어 정리(이름 · 컴포넌트)와 설정이 있다.
- v3에서는 ①이 세 곳(레이어 › 연결, 변수 탭 ★ Inspect · LIB · 삭제된 변수, 머리줄 링크)에, ②가 만들기 4단계 + 시작 화면 마법사에 나뉘어 20개 넘는 기능이 8곳에 흩어졌다. 가끔 쓰는 기능도 탭 하나씩을 차지했다.
- v4는 "지금 선택에서 할 일"을 한 화면(선택 탭)에, "파일의 변수"를 한 화면(변수 탭)에 모은다.

## 2. 원칙

### 2.1 탭 · 머리 · 하위 화면
- 머리: [선택 | 변수](세그먼트 `tablist`, 남는 폭) + ⚙(32×32, 툴팁 · 접근성 이름 "설정") + —(최소화, v3 그대로).
- 창을 열면 **선택 탭**이다(v3는 변수 탭). 고른 탭은 세션 동안 기억한다.
- **하위 화면**(연결 · 만들기 · 값을 직접 고르기 · 이름 정리 · 컴포넌트)은 선택 탭 안에서 "← 제목" 머리로 들어가고, ←(또는 Esc — 입력 칸 · 메뉴 · 팝업이 없을 때)로 한 단계 돌아온다. 탭을 바꿨다 돌아오면 그 하위 화면이 그대로 있다(v3 §2 원칙 6 상태 기억).
  - 들어가면 포커스는 그 화면의 첫 컨트롤(아래 각 화면의 "포커스")로, ←로 돌아오면 그 화면을 연 버튼으로 간다(버튼이 없어졌으면 첫 화면의 첫 카드 버튼).
  - 쓰기 작업이 진행 중인 하위 화면에서도 ← · Esc · 탭 바꾸기가 된다(작업은 계속된다). 끝난 결과는 공통 상태 줄에 나온다.
- **⚙ 설정은 탭 밖의 화면**이다. 열려 있는 동안 세그먼트는 둘 다 고르지 않은 모양(`aria-selected=false`)이다. ←(또는 Esc)는 설정을 연 그 탭의 그 화면(하위 화면 포함)으로 돌아간다. 세그먼트의 탭을 누르면 설정을 닫고 그 탭의 마지막 화면으로 간다. 공통 상태 줄의 [라이선스 →]도 이 설정 화면을 연다(키 입력 칸에 포커스).

### 2.2 ia-v3에서 그대로 쓰는 것
- 창 480 × 510 · 최소화 140 × 104(v3 §0 · A.11), 공통 상태 줄 · 포커스 · 보류와 간격(v3 §4.1), 잠금 표시와 사유(v3 §2 원칙 3), 상태 기억(원칙 6), `nodechange` 안 씀(원칙 7), 라이트 고정(원칙 8), 접근성(§2.10), 다시 읽기(v3 §4.1 — 바뀐 점은 §7), 최소화(v3 §4.9 — 바뀐 점은 §2.6).
- **연결 원칙(v3 §2.11)** · **역할(§2.12)** · **플러그인 컬렉션(§2.13)**은 **자동 연결** — 연결 화면(§4.2)과 만들기의 "바로 연결"(§4.3) — 에 그대로 적용한다. 바뀌는 것은 §2.3뿐이다.
- 상세 팝업의 고치기 규칙(v3 §4.4 "고치기" — 칸 · 저장 · 오류 · 닫기 확인)은 그대로, 더하는 것만 §4.8.

### 2.3 v3 규칙에서 바뀌는 것 (2026-11-09 사용자 결정)
1. **클릭 연결 예외.** 사용자가 변수 탭에서 변수를 **직접 클릭**하거나 "다른 곳에 연결"을 고르면 지금 캔버스 선택에 붙인다.
   - 값이 달라도 붙인다(레이어 모습이 변수 값으로 바뀐다).
   - 이미 다른 변수가 붙어 있어도 바꾼다.
   - Global도 붙인다.
   - 인스턴스 안쪽 레이어를 선택했어도 붙인다(피그마의 오버라이드가 된다).
   - v3 §2.11의 "이미 붙은 것은 바꾸지 않는다 · 값이 같은 곳만 · 인스턴스 안쪽은 건드리지 않는다", §2.12 "레이어에는 Semantic만", v3 §0 · §2.11 "이미 붙은 연결은 바꾸지 않는다" · §11 "하지 않음 — 레이어 연결 일괄 교체"는 **자동 연결에만** 적용된다. 클릭 연결은 한 번에 변수 하나 · 지금 선택한 레이어만이라 일괄 교체가 아니다.
2. **만들기의 "바로 연결".** v3 §2.11 "붙이는 일은 [연결]과 [기존 스타일 연결]뿐 · 마법사 · 만들기는 붙이지 않는다"를 바꾼다. 만들기 화면에서 사용자가 "바로 레이어에 연결"을 켠 채 [변수 만들기]를 누르면, 만든 뒤 연결 화면의 [연결]과 같은 자동 연결을 한다(같은 규칙 · 같은 결과 문구). 사용자가 버튼을 눌러 시킨 일이라는 원칙은 지킨다.
3. **변수 관리 범위(v3 §2 원칙 4 · §11 "하지 않음 — 변수 삭제").** 새 변수 · 복제 · 삭제를 더한다. 삭제는 확인 창을 늘 띄우고 피그마 ⌘Z로 되돌린다(되돌려지는지 B.3에서 실기로 확인한다). 라이브러리 게시 경고는 넣지 않는다.
4. **새로 만드는 일은 유료(v3 원칙 3)의 예외.** 새 변수 · 복제는 무료 개수 안에서 된다(§9).
5. **삭제된 변수 연결 풀기(2026-11-09 사용자 결정 C).** v3 §2.12 12.8 · §11 "이미 붙은 연결 바꾸기 · 풀기는 하지 않는다"의 예외 — **삭제된 변수에 붙은 연결만** 사용자가 [연결 풀기]를 눌러 뗀다(§4.1 카드 3). 살아 있는 변수의 연결은 여전히 풀지 않는다.

### 2.4 용어
- 레이어에 변수를 붙이는 일은 어디서든 **"연결"**이라고 부른다(v3 §2.9). "적용"이라는 말은 쓰지 않는다.
- 플러그인 안 이동은 "→", 밖으로 나가는 링크만 "↗"(v3 §2.9).
- **타입**은 피그마 변수 타입(색 · 숫자 · 글자 · 참거짓 = COLOR · FLOAT · STRING · BOOLEAN), **종류**는 §4.6의 구분(간격 · 반경 · 크기 · 선 두께 · 투명도 · 색 · 글자 · 기타)이다. "글자 종류"는 글자 크기 · 줄 높이 · 자간 · 글꼴 변수를 말한다.

### 2.5 목록 기준 (선택 탭)
- 선택 탭의 카드 · 하위 화면은 **목록 기준**(v3 ③)의 레이어로 계산한다. 사용자가 캔버스에서 선택을 바꾸면 기준이 그 선택으로 바뀐다.
- 플러그인이 만든 선택(상세 [모두 선택], 삭제된 변수 [선택], 연결 직후 피그마가 보내는 선택)은 기준을 바꾸지 않는다. 그동안 선택 탭 첫 화면 머리 줄에 "지금 선택과 달라요 · [기준 바꾸기]"가 붙는다(하위 화면 머리에는 붙이지 않는다).
- **[기준 바꾸기]:** 지금 캔버스 선택을 기준으로 삼고 §7 "목록 기준이 바뀜"과 같이 읽는다. 지금 선택이 없으면 선택 없음(③)이 된다. 새 기준이 300개를 넘으면 [읽기] 상태가 된다. 버튼이 사라지면 포커스는 첫 카드의 버튼(없으면 레이어 정리의 [이름 정리])으로 간다.
- 계산 메시지(찾기 `APPLY` · 추출 `EXTRACT` · 이름 `RENAME` · 텍스트 스타일 미리보기 `PREVIEW_TEXT_STYLES`)는 **기준의 `nodeIds`를 받는다**(`resolveRoots`, 지금 `SCAN_USAGE`처럼). 지금처럼 `figma.currentPage.selection`을 읽지 않는다. 연결(`APPLY_SELECTED`)은 고른 자리의 nodeId를 이미 담으므로 그대로다.
- 변수 탭의 클릭 연결은 기준이 아니라 **지금 캔버스 선택**에 한다(플러그인이 만든 선택이어도). 결과 문구의 "레이어 n개"가 그 수다.

### 2.6 최소화 (v3 §4.9에서 바뀌는 점)
- 공통 상태 줄 "{작업 이름} 실패 · [보기]"의 도착: 연결 · 찾기 → 선택 탭 연결 화면, 만들기 → 만들기 화면, 이름 → 이름 정리 화면, 컴포넌트 → 컴포넌트 화면, 클릭 연결 · 새 변수 · 복제 · 삭제 · 고치기 → 변수 탭, 내보내기 → 변수 탭(내보내기 팝업은 다시 열지 않음).
- 자동 읽기(§4.1 카드 1의 찾기 · 텍스트 스타일 미리보기, §4.3 자동 추출, §4.4 자동 이름 미리보기)는 **조용한 읽기**다 — 진행 테두리 · ✓ / ⚠ · 진행률 · [취소]가 없고, 300개 규칙을 따른다(넘으면 그 화면에 "선택이 커서 자동으로 읽지 않아요 · [읽기]"). 사용자가 누른 [읽기] · [다시 읽기]는 진행 테두리 대상이다. 진행률 "{p}%" + [취소]는 찾기(`PROGRESS{op:'bind'}` · `CANCEL`)에만 있다 — 추출 · 이름 미리보기 · 텍스트 스타일 미리보기는 진행률 · 취소가 없는 "읽는 중…"(지금 코드와 같음).
- [취소]한 뒤에는 그 자리에 "읽기를 취소했어요 · [다시 읽기]".
- 최소화 중에는 다시 읽지 않는다(v3). 펼칠 때 기준이 바뀌었으면 §7 "목록 기준이 바뀜"을 1번 한다.

## 3. 구조

```
플러그인 (480 × 510 · 최소화 140 × 104)
├─ 머리: [선택 | 변수] ⚙ —
├─ 선택 탭 (기본)
│   ├─ 첫 화면: 머리 줄(선택 이름) · 카드(변수 없는 값 / 쓰는 변수 / 삭제된 변수) · 레이어 정리
│   ├─ ← 연결 화면 (⑦)
│   ├─ ← 변수 만들기 (⑧) ─ ← 값을 직접 고르기(v3 만들기 4단계: 색 · 토큰 · 테마 · 타이포)
│   ├─ ← 이름 정리 (⑨)
│   └─ ← 컴포넌트 (베타, v3 레이어 › 컴포넌트 내용)
├─ 변수 탭
│   ├─ 머리 줄: 🔍 검색 · 모드 ▾ · ＋ · ⋯
│   ├─ 사이드바(컬렉션) │ 오른쪽(그룹 → 알약 · 동그라미 · 줄)
│   └─ 팝업: 상세 · 새 변수 · 삭제 확인 · 내보내기 · 준비 현황(팝오버)
├─ ⚙ 설정 화면 (탭 밖): 기본값 · 라이선스
└─ 공통 상태 줄 (v3 그대로)
```

## 4. 화면

### 4.1 선택 탭 — 첫 화면

**머리 줄**(높이 32): 선택 이름(굵게, 200px 말줄임) + "레이어 {count}개"(`--text-2`, count = 기준에서 사용자가 고른 레이어 수). 여러 개면 "{첫 이름} 외 {count−1}개". 목록 기준이 지금 선택과 다르면 오른쪽에 "지금 선택과 달라요 · [기준 바꾸기]"(§2.5).
- 300개 규칙의 노드 수는 기준 아래 하위 레이어 수(`reread.ts selectionSummary`의 scanned — 인스턴스 안쪽 제외, 1500에서 멈춤)다.

**상태별 본문** — 위에서부터 처음 맞는 줄 하나를 보인다.

| 순서 | 상태 | 본문 |
|---|---|---|
| 1 | 첫 정보 전 | "불러오는 중…" |
| 2 | 선택 없음 (③) | 가운데 "디자인에서 레이어를 선택하세요" 한 줄. 로컬 변수가 0개면 둘째 줄 "이 파일엔 아직 변수가 없어요". 레이어 정리 버튼은 `aria-disabled`(사유 "선택이 없어요") |
| 3 | 큰 선택(scanned 300 초과), 아직 안 읽음 | "선택이 커서 자동으로 읽지 않아요 · [읽기]" 한 줄 |
| 4 | 읽는 중 | 결과가 오지 않은 카드 자리마다 "선택을 읽는 중…"(조용한 읽기 — §2.6). [읽기]로 시작한 읽기는 "선택을 읽는 중… {p}%" + [취소]. 결과는 온 카드부터 그린다 |
| 5 | 로컬 변수 0개 + 선택이 라이브러리 변수를 직접 씀 | 카드 하나: "라이브러리 변수만 써요 · 연결은 피그마 오른쪽 패널에서 해요"(버튼 없음) + 그 아래 쓰는 변수 카드(라이브러리만) |
| 6 | 로컬 변수 0개 (④) | 카드 하나: "이 파일엔 아직 변수가 없어요" + 둘째 줄 종류별 곳 수("색 9곳 · 간격 6곳 · 반경 3곳" — 카드 1의 찾기 결과의 "변수가 없는 값" 자리를 종류별로 센 것. 만들기 화면의 종류 줄은 값 개수라 숫자가 다를 수 있다, EXTRACT를 돌리지 않는다) + [변수 만들기 →](→ §4.3, 들어가는 것은 무료) |
| 7 | 그 밖 (①) | 아래 카드들 |

- "로컬 변수 0개"는 로컬 컬렉션이 있어도 변수가 0개면 해당한다(변수 탭 빈 상태와 같은 조건 — §4.6).
- **텍스트 스타일만 연결하기:** 5 · 6번과 noTier(아래 "연결할 변수가 없을 때")에서도 텍스트 스타일 미리보기 후보가 1곳 이상이면, **같은 카드**(5번은 라이브러리 안내 카드, 6번은 ④ 카드, noTier면 카드 1) 안 둘째 줄 아래에 "텍스트 스타일 {t}곳" + [{t}곳 연결](t = 스타일 후보 레이어 수, 무료)을 더한다. 카드는 늘지 않는다. 버튼 → 연결 화면의 "텍스트 스타일만" 모습(§4.2). v3에서 변수가 없어도 [기존 스타일 연결]을 할 수 있던 것을 지킨다.
- 로컬 변수가 0개이면 5 · 6번은 쓰는 변수 결과가 온 뒤에 가린다. 오기 전에는 4번(읽는 중)이다. 5번은 라이브러리 변수를 **직접** 쓸 때만이다.

**카드 1 — 변수 없는 값**
- 목록 기준이 바뀌면 250ms 뒤(`AUTO_SCAN_DELAY`, 지금 코드 상수) **찾기와 텍스트 스타일 미리보기를 자동으로** 돌린다(v3의 [찾기] 버튼은 없앤다). 300개를 넘으면 [읽기]로만. 찾기는 v3 §4.6 `APPLY`(preview)와 같은 계산이며 범위도 같다(인스턴스 안쪽 · 숨긴 레이어 제외).
- 숫자는 연결 화면과 **같은 규칙**(§4.2 "텍스트 스타일이 먼저다" · 스위치는 모두 켬)으로 센다 — 카드의 m과 연결 화면 첫 [n곳 연결]은 같다.
- **숫자** (찾기 결과의 자리 단위, 사유 키는 `reason.*`):
  - m = 연결할 수 있는 곳 = preview 후보 자리 수 − 스타일 후보 레이어의 글자 종류 자리 + 스타일 후보 레이어 수.
  - k = 변수가 없는 값 = 건너뜀 사유가 `no-match` · `size-fraction`인 자리 수.
  - s = 그 밖의 건너뜀 중 **자리 단위** 사유만(`styled` · `hug-fill` · `translucent` · `space-between` · `fraction` · `empty-text` · `deleted-var`). 이미 연결 `already-bound`과, 코드가 레이어 단위로 세는 사유(`instance-children` · `hidden` · `no-autolayout` · `size-free-layout` · `font`)는 세지 않는다 — 연결 화면의 건너뜀 칩에만 레이어 수로 나온다.
  - 스타일 후보 레이어의 글자 종류 자리(fontSize · lineHeight · letterSpacing · fontFamily)는 m에서만이 아니라 k · s에서도 뺀다 — 그 레이어는 스타일 줄 1곳으로만 센다(④ · 종류별 수도 같다).
  - n = m + k. 제목 "변수 없는 값 {n}곳"(n 툴팁 "인스턴스 안쪽 · 숨긴 레이어 제외").
- 둘째 줄 종류별 수(아래 속성 → 종류 표의 순서, 0은 뺌). 버튼 **[{m}곳 연결]**(주 버튼) → 연결 화면(§4.2).
- m = 0이고 k > 0이면 버튼 대신 [변수 만들기 →](→ §4.3).
- m > 0이고 k > 0이면 둘째 줄 끝에 " · 변수가 없는 값 {k}곳 [만들기 →]".
- n = 0이고 s = 0이면 카드를 `--ok-subtle` 바탕 "✓ 찾은 값은 모두 변수에 연결돼 있어요"로 바꾸고 버튼은 없다. n = 0이고 s > 0이면 "연결할 수 있는 값이 없어요 · 건너뜀 {s}곳 [보기]"([보기] → 연결 화면, 건너뜀 칩이 펼쳐진 채).
- **연결할 변수가 없을 때**(v3 §4.6 표를 이렇게 바꾼다):
  - 로컬 변수는 있지만 계층 컬렉션에 변수가 없음(`hasBindable` false): 둘째 줄 "변수는 있지만 계층으로 쓸 컬렉션이 없어요"(`bind.noTier`) + [변수 만들기 →].
  - 로컬 변수 0개: 위 상태표 5 · 6번.
  - Global만 있는 파일 · Semantic · Component만 있는 파일도 찾기를 보낸다(v3 §4.6 그대로).

**카드 2 — 쓰는 변수**
- 제목 "쓰는 변수 {n}개", 둘째 줄 계층별 수("Semantic 5 · Component 1 · 라이브러리 1"). 오른쪽 [보기 ▾] / [접기 ▴](펼침은 세션 동안 기억).
- n = 목록 기준 레이어(인스턴스 안쪽 포함, 숨긴 레이어 제외 — v3 쓰는 변수 판정)에 **직접 연결된** 변수 수. 간접(별칭이 가리키는 변수)은 세지도 보이지도 않는다. 라이브러리 변수도 직접 연결된 것만(코드의 별칭 따라가기를 지운다, B.1).
- 카드 1과 범위가 다르다(인스턴스 안쪽 포함). n 툴팁 "인스턴스 안쪽 포함".
- 펼치면(②) 카드 아래에 목록: 경로 머리("S Semantic › color/text", 라이브러리는 "라이브러리 › {컬렉션}") + 줄(끝 이름 · 값 알약 · "{n}곳"). 순서는 계층(Component → Semantic → Global → 계층 없음 → 라이브러리) → 그룹 → 피그마 순서.
- 줄 클릭 · Enter = 상세…(§4.8). 우클릭 메뉴는 "상세…" 하나. 줄 안의 알약도 상세를 연다.
- 0개면 카드를 보이지 않는다.

**카드 3 — 삭제된 변수** (자리가 있을 때만)
- `--danger` 글자 "삭제된 변수 {n}곳" + [선택] [연결 풀기](둘 다 보조 버튼, 무료).
- [선택]: 그 레이어들을 캔버스에서 선택한다(기준은 유지 — §2.5).
- [연결 풀기](§2.3-5): 목록 기준 안에서 삭제된 변수에 붙은 자리(n과 같은 범위 — 인스턴스 안쪽 포함, 숨긴 레이어 제외)의 연결을 뗀다.
  - 레이어 모습은 바뀌지 않는다 — 피그마는 변수가 지워져도 마지막 값을 갖고 있고, 연결을 떼면 그 값이 그대로 남는다.
  - **푸는 자리 = 세는 자리.** 카드 3의 n과 풀기는 같은 함수(`deletedBindings(node, deletedIds)` — 삭제된 id 집합은 `collectUsage`처럼 먼저 비동기로 만든다. 자리마다 필드 · 배열 번호 · 글자 구간)로 정한다. 살아 있는 변수(로컬 · 라이브러리)의 연결은 건드리지 않는다.

  | 자리 | 푸는 법 |
  |---|---|
  | 칠 · 선의 색(`fills` · `strokes`의 단색 페인트) | `setBoundVariableForPaint(paint, 'color', null)`이 돌려준 복사본으로 배열을 새로 만들어 다시 넣는다 |
  | 그림자 색(`effects`) | `setBoundVariableForEffect(effect, 'color', null)` 복사본으로 배열을 새로 넣는다 |
  | 글자 구간 속성(fontSize · lineHeight · letterSpacing · fontFamily · fontWeight 등 — 값이 구간 배열) | 글꼴을 모두 불러온 뒤 `getStyledTextSegments([field, 'boundVariables'])`로 구간을 읽고, **삭제된 변수가 붙은 구간에만** `setRangeBoundVariable(start, end, field, null)` |
  | 글자 내용(`characters`) | 글꼴을 불러온 뒤 `setBoundVariable('characters', null)` |
  | 그 밖의 한 값 속성(간격 · 여백 · 반경 · 크기 · 선 두께 · 투명도 · `visible` 등) | `setBoundVariable(field, null)` |

  - **범위 밖**(세지도 풀지도 않는다): 구간별 글자 색(`textRangeFills`), 레이아웃 그리드(`layoutGrids`), 그라디언트 색 단계, 그림자의 흐림 · 퍼짐 · 위치, 컴포넌트 속성. 이 자리의 삭제된 연결은 피그마에서 고친다.
  - 실패 사유: "글꼴을 불러올 수 없음" · "오류".
  - 연결을 푼 자리는 다음 찾기에서 카드 1의 후보가 된다(같은 값의 변수가 있으면 다시 연결할 수 있다).
  - 인스턴스 안쪽 자리는 오버라이드가 된다(받아들임 — 사용자가 누른 일).
  - 확인 창은 없다. ⌘Z 한 번으로 되돌린다. 결과(상태 줄): "삭제된 변수 연결 {k}곳을 풀었어요 · ⌘Z로 되돌리기" + 못 뗀 자리가 있으면 " · {m}곳은 풀지 못했어요"(툴팁에 사유별 수).
  - 쓰기 작업이다(v3 OPS write · 공통 잠금). 끝나면 §7 "플러그인 작업 직후" 다시 읽기 → 카드 3이 사라진다.
  - 메시지 `UNBIND_DELETED{reqId, nodeIds}`(기준) → `DELETED_UNBOUND{reqId, unbound, failed, failReasons}` / `ERROR{op:'UNBIND_DELETED', reqId}`. 삭제 판정은 지금 `collectUsage`와 같다(로컬도 라이브러리도 아닌 id).
- 포커스: [연결 풀기]를 누른 뒤 카드가 사라지면 레이어 정리의 [이름 정리]로.

**레이어 정리**(맨 아래 고정, 구분선 위): "레이어 정리" + [이름 정리] → §4.4, [컴포넌트 베타] → §4.5. 선택이 없으면 `aria-disabled`.

**스크롤:** 머리 줄은 고정, 카드 영역은 패널 스크롤, 레이어 정리 줄은 아래 고정.

**포커스 순서:** 탭 → ⚙ → — → [기준 바꾸기](있을 때) → 보이는 첫 카드의 버튼들(카드 1, 또는 상태 5 · 6 카드의 [변수 만들기 →] · [{t}곳 연결]) → 카드 2 [보기 ▾] → 펼친 목록(`grid`, 정지점 1개, ↑↓ = 줄, Home/End) → 카드 3 [선택] · [연결 풀기] → [이름 정리] → [컴포넌트 베타] → 공통 상태 줄 버튼(있을 때).

### 4.2 연결 화면 (⑦)

- 머리: "← {선택 이름}" + 오른쪽 "변수 없는 값 {n}곳".
- 내용은 카드 1의 찾기 결과(결과 상한 없음 — v3 "찾기 · 연결의 수")를 **변수별 줄**로 보인다.
  - 종류 머리(카드 1의 속성 → 종류 표 순서, "색 9곳"), 그 아래 줄: [견본] 값 → 붙을 변수 이름(+ 새 역할이면 N 배지, 툴팁 "{Global 이름}을 가리켜요" — v3 §4.6) · "{n}곳" · 스위치.
  - 줄 = (변수, 종류) 한 쌍. 같은 변수가 두 종류에 걸치면 종류마다 줄 · 스위치가 따로 있다. 종류 안 줄 순서는 곳 수가 많은 순, 같으면 변수 이름 순.
  - 머리 줄 아래 "모두 켜기 · 모두 끄기" 링크(v3 그대로).
  - 스위치를 끄면 그 줄의 곳은 빠지고 아래 버튼 숫자가 바뀐다. 모든 줄을 끄면 버튼은 `aria-disabled`(사유 "연결할 곳을 켜 주세요").
  - 텍스트 스타일(로컬 텍스트 스타일과 값이 같은 글자 — v3 [기존 스타일 연결])은 "텍스트 스타일" 머리 아래 같은 모양의 줄로(견본 Aa · 스타일 이름 · "{n}곳" · 스위치).
  - **텍스트 스타일이 먼저다:** 스타일 후보가 있는 글자 레이어의 글자 종류 자리(fontSize · lineHeight · letterSpacing · fontFamily)는 글자 변수 후보에서 뺀다. 그 스타일 줄을 끄면 그 자리들을 글자 변수 후보로 되돌린다. 곳 수는 한 자리를 한 번만 센다(스타일 줄은 레이어 1개 = 1곳).
  - 줄 수 상한은 없다(줄이 변수 단위라 많아야 수십 개).
- [건너뜀 {s}곳 ▸] 칩: s는 카드 1과 **같은 정의**(자리 단위 사유의 곳 수)라 카드의 "건너뜀 {s}곳"과 숫자가 같다. 누르면 사유 칩이 펼쳐진다: 자리 단위 사유는 "{사유} {n}곳", 레이어 단위 사유(`instance-children` · `hidden` · `no-autolayout` · `size-free-layout` · `font`)와 텍스트 스타일 사유(hasStyle · noStyle · ambiguous · mixed · boundVars · instance)는 "{사유} 레이어 {n}개" — 이 둘은 s에 더하지 않는다. s = 0이고 레이어 단위 사유만 있으면 칩은 "[건너뛴 레이어 ▸]".
- 아래 고정: [{n}곳 연결](주 버튼). 연결 직전 다시 확인(v3 그대로) → 끝나면 첫 화면으로 돌아오고 상태 줄 "🔗 {n}곳 연결 · ⌘Z로 되돌리기"(건너뛴 곳이 있으면 " · 건너뜀 {m}"). 카드는 다시 읽는다.

**상태**

| 상태 | 모습 |
|---|---|
| 찾는 중 | 목록 자리 "선택을 읽는 중…"(자동 — 조용한 읽기). [읽기] · [다시 읽기]로 시작했으면 "{p}%" + [취소], 취소 뒤 "읽기를 취소했어요 · [다시 읽기]" |
| 후보 0 | "연결할 수 있는 값이 없어요"(+ 건너뜀 칩, k > 0이면 [변수 만들기 →]) |
| 선택 없음 | 첫 화면으로 돌아간다(선택 없음 안내가 보인다) |
| 로컬 변수 0개 · noTier | 텍스트 스타일 후보가 있으면 **텍스트 스타일만** 모습: 머리 오른쪽 "텍스트 스타일 {t}곳", 줄은 텍스트 스타일 줄만, 건너뜀 칩에는 텍스트 스타일 사유만("[건너뛴 레이어 ▸]"), 버튼 [{t}곳 연결]. 후보가 없으면 첫 화면으로 돌아간다 |
| 연결 중 | 아래 버튼 자리에 진행 줄 "연결 중… {done} / {total}"(`PROGRESS{op:'link'}`, [취소] 없음 — v3) |
| 연결 실패 | 화면에 남고 버튼 위 오류 줄 + [다시 시도] |

- 화면에 있는 동안 기준이 바뀌거나 창에 다시 들어오면(§7) 다시 찾는다. 끈 스위치는 같은 (변수, 종류) 줄이면 꺼진 채 이어받는다(v3 ⑧ 규칙).
- 연결 중에는 자동 찾기를 미룬다(끝난 뒤 1번, v3 `bindLinking`).
- **포커스:** 들어오면 첫 스위치. 순서: ← → 모두 켜기 · 모두 끄기 → 줄 목록(`grid`, ↑↓ = 줄, Space = 스위치) → [건너뜀 ▸] → 사유 칩 → [n곳 연결].
- 없애는 것(v3 §4.6): 단계 표시(찾기 · 고르기 · 연결), [찾기] · [다시 찾기], 필터 칸, 속성 아이콘, 줄의 레이어 펼치기, 연결 후 결과 카드, 자리 200줄 제한, "변수 탭에서 보기 →" · "토큰 만들기로 →" · "타이포에서 등록 →" 링크.
- 메시지: 텍스트 스타일 미리보기를 새로 둔다 — `PREVIEW_TEXT_STYLES{reqId, nodeIds}` → `TEXT_STYLES_PREVIEW{reqId, rows:[{styleId, name, nodeIds}], skips}`. 연결은 `APPLY_SELECTED`에 켠 스타일 줄(`textStyles:[{styleId, nodeIds}]`)을 함께 보내 한 번(⌘Z 한 번)에 한다.

### 4.3 변수 만들기 (⑧)

- 머리: "← 변수 만들기" + 오른쪽 "{선택 이름}에서 찾은 값".
- 들어오면 목록 기준을 추출한다(v3 `EXTRACT`, 무료). 기준이 바뀌면 250ms 뒤 다시 추출한다(실행 중이면 끝난 뒤, 조용한 읽기 · 300개 규칙 — §2.6). 종류 체크는 같은 종류면 이어받는다.
- 추출 결과는 이 화면의 상태로만 쓴다 — "값을 직접 고르기"의 토큰 목록(`tokens` · 체크 · 정리 상태)을 덮어쓰지 않는다.
- **종류 줄**(값이 있는 것만): 체크 + 종류 이름 + 개수 + 미리보기(색 16px 동그라미, 숫자 알약, 최대 12개 + "+n"). 기본은 글자만 끄고 모두 켬.

| 종류 줄 | 추출 분류(TokenCategory) |
|---|---|
| 색 | color · effectColor |
| 간격 | gap |
| 반경 | radius |
| 크기 | size |
| 선 두께 | strokeWidth |
| 투명도 | opacity |
| 글자 | fontSize · lineHeight · letterSpacing · fontFamily (글자 토큰 — 텍스트 스타일 등록이 아니다) |

- fontWeight · effectFloat(그림자 흐림 등)은 이 화면에서 만들지 않는다 — 연결 · 클릭 연결로 붙일 속성이 없어서다(값을 직접 고르기 › 토큰에서는 v3 그대로 만들 수 있다). 종류 줄은 §2.4의 종류만 쓴다.

- 숫자 토큰은 격자 정리(tidyNumbers)를 **하지 않는다** — 정리로 옮긴 값은 원래 레이어와 달라 "바로 연결"이 되지 않기 때문이다(v3 §4.5 안내, v3 마법사도 정리하지 않은 값을 보냈다). 격자 정리는 값을 직접 고르기 › 토큰에서 한다.
- 추출 뒤 정리(색 이름 huefy · `colorAuthoritativeRoles` 등 지금 `EXTRACT_RESULT` 처리기가 하는 것)는 값을 직접 고르기와 같은 함수로 해서 만든 이름이 같게 한다.
- **만든 뒤**:
  - [✓] 바로 레이어에 연결(기본 켬) — §2.3-2
  - [ ] 레이어 이름도 정리
  - [ ] 다크 모드도 만들기
- 아래 고정: 만들 수("Global {g}개 · 역할 {r}개" — 켠 종류의 토큰으로 `previewCreateTokens` · `createUsageRoles(preview)`를 다시 계산, 체크를 바꿀 때마다) + [변수 만들기].
- **무료:** 화면 · 추출 · 미리보기는 무료. 무료 사용자의 실행 버튼은 **[연결 · 이름 정리 실행]**이다 — 변수를 만들지 않고, 켠 옵션 중 "바로 레이어에 연결"(기존 변수로, 연결 화면과 같은 규칙)과 "레이어 이름도 정리"만 돈다(둘 다 끄면 `aria-disabled`, 사유 "무료로는 연결 · 이름 정리만 할 수 있어요"). 종류 체크 · 다크 옵션은 잠금(사유 "변수 만들기는 유료예요 · [라이선스 →]"). B.1~B.3 마법사의 무료 범위와 같다.
- **실행 순서**(새 순서, `wizard.ts`를 고친다): 추출 → 만들기(Global + 역할, `CREATE_TOKENS`) → 다크(켰을 때, `GENERATE_DARK_MODE`) → 연결(켰을 때, 기준 `nodeIds`로 `APPLY` 실제 연결 — 연결 화면과 같은 변수 규칙. 텍스트 스타일은 붙이지 않는다) → 이름 정리(켰을 때, `RENAME`). v3 마법사의 역할 매핑(`semantics`, 매핑 글 상자) · 텍스트 스타일 · 컴포넌트 단계는 이 화면에 없다 — 값을 직접 고르기(토큰 · 타이포)와 컴포넌트 화면에서 한다.

**실행 상태**

| 상태 | 모습 |
|---|---|
| 실행 중 | 버튼 자리 "만드는 중… {단계}" + [취소](지금 단계가 끝나면 멈춤 — v3 마법사). 다른 쓰기 버튼은 잠김(v3 공통 잠금). ← · 탭 바꾸기는 된다 |
| 다 됨 | 선택 탭의 하위 화면을 첫 화면으로 되돌리고 상태 줄 "변수 {g}개 · 역할 {r}개 · {n}곳 연결"(하지 않은 단계의 부분은 뺌). 사용자가 다른 탭 · 설정에 있으면 탭은 바꾸지 않는다 |
| 일부 실패 · 건너뜀 | 만들기 화면에 남고(다른 탭에 있으면 상태 줄 "변수 만들기 일부 실패 · [보기]" → 이 화면) 버튼 위에 단계별 결과 줄(✓ / ⚠ / 건너뜀 + 사유: 다크 칠할 색 없음 · 연결 0곳 등, v3 마법사 요약 문구) + [닫기](→ 첫 화면) |
| 취소됨 | 화면에 남고 "취소했어요 · {끝낸 단계}까지 됐어요" |
| 추출 0개 | 종류 줄 자리 "이 선택에서 찾은 값이 없어요", 버튼 `aria-disabled` |

- **선택:** 선택이 없으면 이 화면에 들어올 수 없다. 들어와 있는 중 선택이 풀리면 "디자인에서 레이어를 선택하세요"와 [← 돌아가기].
- **포커스:** 들어오면 첫 종류 체크. 순서: ← → 종류 체크들 → 만든 뒤 체크 3 → [값을 직접 고르기 →] → [변수 만들기].
- **[값을 직접 고르기 →]:** v3 만들기 4단계(색 · 토큰 · 테마 · 타이포 — 레일 칩 · 내용 그대로)를 하위 화면으로 연다. 머리만 "← 값을 직접 고르기". **선택이 없어도 들어갈 수 있다**(v3처럼 단계마다 "레이어를 선택하면 그 안의 값으로 만들어요"). 안의 v3 링크는 이렇게 바꾼다:

| v3 링크 | v4 도착 |
|---|---|
| "← 돌아가기"(변수 탭 첫 화면) | ← (만들기 화면, 들어온 곳이 ＋ 메뉴 · 준비 현황이면 변수 탭) |
| 타이포 "변수 탭으로" | 변수 탭 |
| 타이포 "레이어에 연결하기 →" · 안내 "화면 연결은 레이어 › 연결에서" | 선택 탭 연결 화면 · 문구 "화면 연결은 선택 탭에서" |
| 테마 "토큰 만들기로 →" | 같은 하위 화면의 토큰 단계 |
| "라이선스 →" | ⚙ 설정 › 라이선스 |
| 마법사 요약 "레이어 › 연결에서 확인하고 연결하기 →"(B.1~B.3 동안 남는 v3 마법사) | "선택 탭에서 확인하고 연결하기 →" → 선택 탭 연결 화면. 연결 단계를 껐을 때만 보이고, 그때 요약 끝에 " · 연결은 아직 안 했어요" |

**B.1 ~ B.3 동안의 v3 마법사("한 번에 정리") — 연결 단계를 당겨 넣는다** (2026-11-09 사용자 결정 "한 번에 정리는 연결까지")
- §2.3-2 "바로 연결"을 B.4보다 먼저 v3 마법사에 넣는다. 단계 순서: 추출 → 변수 만들기 → 역할 매핑 → 다크 → 텍스트 스타일 → **연결** → 이름 정리.
- 연결 단계는 선택 단계(체크 "연결", 기본 켬), **무료**(무료 마법사도 연결 + 이름 정리로 완주). 기준 `nodeIds`로 `APPLY`(preview 아님) — 연결 화면 [연결]과 같은 규칙(v3 §2.11 · §2.12 · §2.13: 같은 값만 · 이미 붙은 곳은 그대로 · 레이어에는 Semantic · 인스턴스 안쪽 제외), 텍스트 스타일은 붙이지 않는다.
- **기준은 실행을 시작할 때 한 번 정한다:** 시작할 때의 목록 기준 nodeIds를 저장해 추출(`EXTRACT`) · 연결(`APPLY`) · 이름 정리(`RENAME`)에 모두 쓴다. 실행 중에 선택이 바뀌어도 기준은 그대로다. (텍스트 스타일 스캔 · 컴포넌트 등록은 지금 선택을 읽는다 — B.4에서 이 화면에서 빠진다.)
- **겹침 막기:** 마법사가 도는 동안 찾기 · [읽기] · 연결 화면의 [찾기] · [다시 찾기]는 공통 잠금(`op.wizard`)이고 자동 찾기는 미룬다(§7). 코드에서도 preview 찾기는 preview 아닌 연결(`APPLY` · `APPLY_SELECTED`)을 취소하지 않고 끝나길 기다린다. 마법사의 연결 요청에는 reqId를 붙여 마법사가 그 reqId로만 받고, 메인 처리기는 그 결과로 연결 화면을 다시 그리지 않는다. 마법사 연결 중의 진행 메시지(`PROGRESS{op:'bind'}`)는 연결 화면 진행 줄에 띄우지 않고, 코드의 `CANCEL`은 실제 연결 중이면 무시한다. 코드 쪽 찾기 · 연결은 요청을 한 줄로 세워 차례로 돈다(겹쳐 깨어나지 않게).
- 요약에 "연결 {n}곳"(새 역할이 있으면 단계 칩에 " · 새 역할 {k}개"). 연결이 0곳이면 단계 칩에 사유: 계층으로 쓸 변수가 없음(noTier · 변수 0개) / 이미 모두 연결됨(`already-bound`만) / 변수와 값이 같은 곳이 없음(그 밖).
- **무료:** 실행 버튼 "연결 · 이름 정리 실행", 설명 "무료 버전에서는 기존 변수 연결과 레이어 이름 정리만 해요. 변수 만들기는 유료예요", 요약 "연결 {b}곳 · 레이어 이름 {n}개 정리 · 변수는 만들지 않았어요"(연결 단계가 끝나지 않았으면 "연결" 부분을 빼고 끝에 " · 연결은 아직 안 했어요").
- "선택 탭에서 확인하고 연결하기 →"와 요약 끝 " · 연결은 아직 안 했어요"는 **연결 단계가 실제로 끝나지 않았을 때**(껐음 · 연결 전에 취소 · 앞 단계 실패로 멈춤) 보인다.
- 연결 단계가 끝나면 작업 직후 다시 읽기(§7)로 카드가 갱신된다. B.4에서 이 마법사는 §4.3 만들기 화면으로 바뀐다(순서는 그대로 "연결 → 이름 정리", 무료 범위도 같다 — §4.3 "무료").

### 4.4 이름 정리 (⑨)

- 머리: "← 이름 정리" + 오른쪽 "{선택 이름} · 바꿀 이름 {n}개".
- 들어올 때와 기준이 바뀔 때(250ms 뒤) · 창에 다시 들어올 때 미리보기(`RENAME` preview, 기준 `nodeIds`)를 다시 한다(조용한 읽기 · 300개 규칙 — §2.6). 끈 체크는 같은 레이어면 이어받는다.
- 줄: 체크 + 옛 이름(취소선, `--text-2`) → 새 이름(굵게). 기본 모두 켬. **바꿀 줄만** 보인다(트리 순서). 보존 줄(최상위 · 인스턴스 · 컴포넌트 · 글자 · 잠긴 레이어)은 보이지 않으므로 v3 `rename.hideKeep` 토글도 없앤다. 규칙은 v3 이름 정리 그대로.
- 빈 상태: 바꿀 이름 0개 "바꿀 이름이 없어요", 선택이 풀리면 "디자인에서 레이어를 선택하세요"와 [← 돌아가기].
- 아래 고정: [{k}개 이름 바꾸기](k = 켠 수, 0이면 `aria-disabled`). 끝나면 첫 화면 + 상태 줄 "이름 {k}개 바꿈 · ⌘Z로 되돌리기".
- **포커스:** 들어오면 첫 체크. 순서: ← → 목록(`grid`, Space = 체크) → [k개 이름 바꾸기].

### 4.5 컴포넌트 (베타)

- 머리: "← 컴포넌트 베타". 내용은 v3 레이어 › 컴포넌트 그대로(후보 등록 · 닮은 프레임 묶기 · 분류 · 빠진 변형, 유료 잠금 그대로, 선택이 없을 때 v3 문구 그대로). 포커스는 v3 화면 순서.

### 4.6 변수 탭

**머리 줄**(고정): [🔍 변수 검색](남는 폭) · [모드 ▾](보이는 모드가 1개면 숨김) · [＋] · [⋯].
- 검색: 입력하면 모든 로컬 컬렉션에서 전체 경로 부분 일치(대소문자 무시). 결과는 오른쪽에 경로 머리로 묶고 사이드바 고른 표시는 흐리게. 검색 중 사이드바 컬렉션을 고르면 검색을 지우고 그 컬렉션을 보인다. 결과 없음 "'{q}'와 맞는 변수가 없어요 · [검색 지우기]". 라이브러리 변수는 찾지 않는다.
- [＋] 메뉴(⑥): 새 변수(§4.9) · (구분선) · 선택에서 변수 만들기… · 다크 모드 만들기… · 텍스트 스타일 만들기….
  - "선택에서 변수 만들기…" → 선택 탭으로 바꾸고 §4.3. 선택이 없으면 `aria-disabled`("선택이 없어요").
  - "다크 모드 만들기…" · "텍스트 스타일 만들기…" → 선택 탭으로 바꾸고 값을 직접 고르기의 테마 · 타이포 단계. 선택이 없어도 된다(v3 기능 그대로).
- [⋯] 메뉴: 준비 현황 {k}/7…(팝오버, 줄 → 도착은 아래 표) · 코드로 내보내기…(팝업 — v3 그대로) · (구분선) · 색 격자로 보기 / 색 목록으로 보기(전환, 기억) · 그룹 모두 펼치기 · 그룹 모두 접기.

**준비 현황 줄 → 도착** (v3 §3.1 표를 바꾼다. 이동 뒤 포커스는 그 화면의 첫 컨트롤)

| 줄 | 도착 |
|---|---|
| 색 | 값을 직접 고르기 › 색 |
| 토큰 | 값을 직접 고르기 › 토큰 |
| 역할 매핑 | 값을 직접 고르기 › 토큰 + 상태 줄 "역할 매핑은 토큰을 만들 때 함께 만들어져요" |
| 다크 | 값을 직접 고르기 › 테마 |
| 텍스트 스타일 | 값을 직접 고르기 › 타이포 |
| 연결 | 선택 탭 첫 화면(선택이 없으면 그 안내가 보인다) |
| 이름 | 선택 탭 › 이름 정리(선택이 없으면 첫 화면) |

**사이드바**(128px, `listbox`, 정지점 1개, ↑↓ · Home/End, Enter · Space · 클릭 = 고르기): 로컬 컬렉션만(변수가 0개인 컬렉션도). 계층 배지(G · S · C · –, 배지 툴팁은 v3 §4.4 그대로) + 이름(말줄임) + 전체 변수 수. 순서 Component → Semantic → Global → 계층 없음, 같은 계층은 피그마 순서. 처음에는 첫 컬렉션, 그 뒤 마지막으로 고른 컬렉션을 기억. 고른 컬렉션이 사라지면 첫 컬렉션. 그룹 · ★ Inspect · LIB · 삭제된 변수 항목은 없다.

**오른쪽 목록**
- 그룹 머리(24px, [▾/▸] + 경로 = 이름의 마지막 "/" 앞, 접기 기억)만 있다. "/"가 없는 변수는 맨 위에 머리 없이.
- 그룹 순서는 **종류 순서**(간격 → 반경 → 크기 → 선 두께 → 투명도 → 색 → 글자 → 기타), 같은 종류 안에서는 피그마 순서. 그룹 안 변수도 피그마 순서. 그룹의 종류는 그 그룹 첫 변수의 종류.
- **종류 판정** (위에서부터 처음 맞는 것):
  1. 타입: COLOR → 색. BOOLEAN → 기타.
  2. 이름 첫 마디(소문자로 비교): FLOAT이고 `spacing` → 간격, `radius` → 반경, `size` → 크기, `stroke-width` → 선 두께, `opacity` → 투명도, `font-size` · `line-height` · `letter-spacing` → 글자; STRING이고 `font-family` → 글자.
  3. 이름 끝 마디(소문자): FLOAT이고 `gap` · `row-gap` · `column-gap` · `spacing` · `padding` · `padding-x` · `padding-y` · `padding-{방향}` → 간격, `radius` · `radius-{모서리}` → 반경, `size` · `width` · `height` → 크기, `stroke-width` · `stroke-width-{방향}` → 선 두께, `opacity` → 투명도, `font-size` · `line-height` · `letter-spacing` → 글자; STRING이고 `font-family` → 글자. (사용자 Component 컬렉션의 `button/padding-x` · `button/font-size` · `avatar/size` 같은 이름)
  4. 용도(scopes, FLOAT · STRING)가 한 종류만 가리키면 그 종류: GAP → 간격, CORNER_RADIUS → 반경, WIDTH_HEIGHT → 크기, STROKE_FLOAT → 선 두께, OPACITY → 투명도, FONT_SIZE · LINE_HEIGHT · LETTER_SPACING · FONT_FAMILY → 글자.
  5. 그 밖은 기타.
- **Global 계층 컬렉션:**
  - 숫자 · 글자 · 참거짓 변수 → 값 알약(높이 24, 좌우 8, 줄바꿈, 간격 4). 글자는 고른 모드의 값(숫자 소수 둘째 자리, 글자 120px 말줄임, 참거짓 "true" · "false"). 그 모드의 값이 별칭이면 "→ {대상 끝 이름}".
  - 색 변수 → 동그라미. 목록 보기(기본): 18px 동그라미 + 끝 이름(높이 28). 격자 보기: 24px 동그라미만(간격 7).
  - 툴팁(마우스 · 키보드 포커스 모두): 전체 이름 / 값.
  - 사용 표시는 없다(사용은 선택 탭에서 본다).
- **Semantic · Component · 계층 아님 컬렉션:** 줄(이름 = 끝 이름 · 값 알약). 열 폭: 이름 남는 폭, 값 180px. 사용 수 칸 없음.
- **빈 상태:** 로컬 변수가 0개면(컬렉션이 있어도) 오른쪽 전체에 "아직 변수가 없어요 · [선택에서 변수 만들기]"(선택이 없으면 버튼 `aria-disabled`). 고른 컬렉션만 비었으면 "이 컬렉션엔 변수가 없어요".

**조작** (알약 · 동그라미 · 줄 공통)

| 조작 | 결과 |
|---|---|
| 클릭 | 지금 캔버스 선택에 **연결**(§4.7). 선택이 없으면 연결하지 않고 상태 줄 `status.noSelection`("선택이 없어요 — 캔버스에서 레이어를 선택하세요") |
| 더블클릭 | 클릭과 같다. 두 번째 click(`event.detail > 1`)은 버린다 — 연결은 한 번 |
| Enter | 상세…(§4.8) |
| Space | 연결(클릭과 같음) |
| 우클릭 · Shift+F10 · 컨텍스트 메뉴 키 | 메뉴: 다른 곳에 연결 ▸ · 상세… · 복제 · (구분선) 삭제. 라이브러리 변수는 상세…만 |

- **쓰기 잠금:** 쓰기 작업(v3 OPS 표의 write — 이번에 더하는 `APPLY_VARIABLE` · `CREATE_VARIABLE` · `DUPLICATE_VARIABLE` · `DELETE_VARIABLE` 포함, 연결 화면의 연결 · 만들기 실행 · 고치기 저장 등)이 진행 중이면 클릭 · Space · 메뉴의 쓰기 항목은 하지 않고 상태 줄에 v3 공통 잠금 사유를 띄운다. 반대로 클릭 연결이 진행 중이면 다른 쓰기 버튼이 잠긴다.
- 줄 안의 별칭 알약도 클릭 = 연결이다. 가리키는 변수로 가기는 상세의 [→]로.
- 줄 고르기(파란 바탕) 상태는 없다. 키보드 포커스 표시만.

**키보드** (사이드바 `listbox` · 오른쪽 `grid`, 각각 정지점 1개)
- 오른쪽: ↑ ↓ = 줄(그룹 머리 · 줄 · 알약 줄 · 동그라미 줄) 사이, 알약 · 동그라미 줄로 들어가면 같은 열에 가까운 것. ← → = 알약 · 동그라미 줄 안. 그룹 머리에서 Enter · Space = 접기 · 펼치기. Home / End · PageUp / PageDown = v3 그대로. Esc = 메뉴 · 팝업 닫기, 검색 지우기.
- 알약 · 동그라미에 포커스가 오면 툴팁 내용을 띄운다. 접근성 이름 "{전체 이름}, {값}".
- 포커스 순서: 탭 → ⚙ → — → 머리 줄(검색 · 모드 · ＋ · ⋯) → 사이드바 → 오른쪽 → 공통 상태 줄 버튼(있을 때).

### 4.7 클릭 연결 규칙

- **대상:** 지금 캔버스 선택의 레이어 각각(선택한 레이어만, 자식은 아님). 숨긴 · 잠긴 레이어도 선택돼 있으면 한다.
- **속성 고르기:** 그 종류의 속성 목록(아래 표, 앞이 기본) 가운데 ① 변수 용도(scopes)가 허용하고 ② 그 레이어에 있는 첫 속성. 기본 속성이 용도에 없으면 같은 종류의 다음 속성으로 간다. 하나도 없으면 그 레이어는 건너뜀(사유 "용도에 맞는 속성이 없음" 또는 "그 속성이 없는 레이어").
- "있다"는 기본 속성이면 필드가 있다는 뜻(없는 단색 채움 · 선은 아래 세부대로 만든다), **다음 속성으로 넘어갈 때는 보이는 그 페인트 · 선 · 그림자가 이미 있다는 뜻**이다 — 넘어간 속성에는 새로 만들지 않는다. 새로 만드는 것은 기본 속성과 "다른 곳에 연결"로 직접 고른 속성뿐이다.
- 채움 용도는 레이어 종류를 따른다(v3 A.9): 글자 → TEXT_FILL, 프레임 · 컴포넌트 · 인스턴스 → FRAME_FILL, 도형 → SHAPE_FILL. ALL_FILLS · ALL_SCOPES는 셋 다 허용.

| 종류 | 속성 목록 (앞이 기본) |
|---|---|
| 색 | 글자 레이어: 글자 색 → 선 색 → 그림자 색. 그 밖: 채움 → 선 색 → 그림자 색 |
| 간격 | 이름 끝 마디(v3 §2.12 12.3 이름 표의 역): `gap` → 간격(`itemSpacing`), `row-gap` → 줄바꿈이면 `counterAxisSpacing`, 아니면 `itemSpacing`, `column-gap` → `itemSpacing`, `padding` → 안쪽 여백 4방향, `padding-x` → 좌 · 우, `padding-y` → 위 · 아래, `padding-top · -right · -bottom · -left` → 그 방향. 그 밖(예 `spacing/16`) → 간격 |
| 반경 | 끝 마디가 `-top-left` 등이면 그 모서리, 그 밖은 모서리 4곳(`topLeftRadius` … 필드가 있는 레이어만) |
| 크기 | 끝 마디가 `width`면 가로만, `height`면 세로만, 그 밖은 가로 · 세로 |
| 선 두께 | 끝 마디가 `-top` 등이면 그 방향, 그 밖은 `strokeWeight` |
| 투명도 | 레이어 투명도(`opacity`) |
| 글자 | 그 글자 속성(fontSize · lineHeight · letterSpacing · fontFamily) |
| 기타 | 붙이지 않는다 — 상태 줄 "이 변수는 붙일 속성을 정할 수 없어요" |

- **색 세부:**
  - 채움 · 글자 색: 보이는 단색 채움 중 **맨 위**(fills 배열의 마지막)에 붙인다. 단색 채움이 없으면(그라디언트 · 이미지만, 또는 없음) 맨 위에 단색 채움을 새로 만들어 붙인다. 채움이 없는 노드(그룹 · 슬라이스)는 건너뜀.
  - 글자 색이 구간마다 다르면 글자 전체를 단색 하나로 바꾼다.
  - 색 스타일이 붙어 있으면 스타일 연결이 끊긴다(사용자가 직접 고른 것 — 받아들임).
  - 투명도가 있는 색 변수도 붙인다(페인트 불투명도가 변수 값을 따른다).
  - 선 색: 보이는 선이 없으면 1px 안쪽 단색 선을 만든다. 그림자 색: 그림자가 없으면 건너뜀.
- **숫자 세부:**
  - 간격 · 여백은 오토 레이아웃(가로 · 세로)인 레이어만. GRID 레이아웃 · 오토 레이아웃 아님은 건너뜀. "공간 분배(Space between)"인 레이어에 간격을 붙이면 피그마가 정렬을 바꾼다 — 받아들인다.
  - 크기: HUG · FILL 축은 FIXED가 된다 — 받아들인다. 글자 · 그룹은 건너뜀.
  - 반경: `topLeftRadius` 필드가 없는 레이어(원 · 다각형 · 별 · 벡터 · 글자)는 건너뜀.
  - 선 두께: 보이는 선이 없으면 건너뜀.
- **글자 세부:** 글자의 모든 구간 글꼴을 불러온 뒤 붙인다. 글꼴 이름(font-family)을 바꿀 때 같은 스타일이 그 글꼴에 없으면 그 레이어는 건너뜀. 줄 높이 · 자간은 px 값이 된다. 텍스트 스타일이 붙어 있으면 스타일 연결이 끊긴다(받아들임). 빈 글자는 건너뜀.
- **결과**(상태 줄, ⌘Z 한 번): "레이어 {applied}개에 {이름} 연결" + 건너뛴 것이 있으면 " · {skipped}개는 맞지 않아 건너뜀"(툴팁에 사유별 수) + " · ⌘Z로 되돌리기". 하나도 못 붙였으면 "선택한 레이어에 {이름}을 붙일 곳이 없어요"(툴팁에 사유별 수). applied · skipped는 **레이어 수**다.
- 연결 뒤 다시 읽는다(§7).
- **다른 곳에 연결 ▸**(하위 메뉴, `aria-haspopup`, → 로 열고 ← · Esc로 닫고 포커스는 그 항목으로): 색 — 채움 · 선 색 · 글자 색 · 그림자 색 / 간격 — 간격 · 안쪽 여백(4방향) · 위 · 아래 · 왼쪽 · 오른쪽 / 반경 — 모서리 4곳 · 왼쪽 위 · 오른쪽 위 · 왼쪽 아래 · 오른쪽 아래. 그 밖의 종류는 항목을 보이지 않는다. 변수 용도가 막은 항목은 `aria-disabled`(사유 "이 변수의 용도에 없어요"). 선택이 없으면 "다른 곳에 연결" 자체가 `aria-disabled`. 고른 속성이 레이어에 없으면 그 레이어는 건너뜀(다른 속성으로 가지 않는다).
- 메시지: `APPLY_VARIABLE{reqId, id, target?}` → `VARIABLE_APPLIED{reqId, applied, skipped, skipReasons, name}` / `ERROR{op:'APPLY_VARIABLE', reqId}`. target 값: `fill · stroke · text · shadow · gap · padding · padding-top · padding-right · padding-bottom · padding-left · radius · radius-tl · radius-tr · radius-bl · radius-br`(없으면 위 속성 고르기).

### 4.8 상세 팝업 (합침)

- "상세"와 "고치기…"를 하나로. 열자마자 고칠 수 있다(v3 고치기 그대로). 처음 포커스 [닫기](복제 직후에만 이름 칸).
- 어디서 열든(변수 탭 · 선택 탭 카드 2) 같은 팝업이다. 닫으면 포커스는 연 줄 · 알약으로 돌아간다. 저장으로 이름 · 그룹이 바뀌었으면 새 자리의 그 항목으로. 그 항목이 보이지 않으면(검색 · 접힘 · 카드 2 목록에서 빠짐) 같은 그룹의 첫 항목, 그것도 없으면 오른쪽 목록 첫 항목(카드 2면 [보기 ▾])으로 가고 상태 줄 "{새 이름}은 지금 목록에 보이지 않아요"(v3 닫을 때 규칙).
- 더하는 것:
  - 제목 줄 오른쪽 [⧉ 이름 복사]. CSS 줄 `--{css 이름}` + [⧉]. 누르면 단추 글자가 1.5초 "복사됨"으로 바뀌고 포커스는 그 단추에 남는다(상태 줄은 팝업 뒤라 쓰지 않음).
  - 모드 값이 별칭이면 값 칸 오른쪽 [→](툴팁 "가리키는 변수로"). 대상이 삭제된 별칭이면 숨긴다. 고친 내용이 있으면 v3 "닫기 전 확인"을 거친 뒤 이동: 팝업을 닫고 변수 탭으로 바꾸고, 대상의 컬렉션을 고르고(검색은 지움), 그 그룹을 펼쳐 그 알약 · 줄로 포커스. 상태 줄 "{이름}(으)로 옮겼어요 · [← 되돌리기]". [← 되돌리기]는 연 곳으로 돌아간다 — 변수 탭이면 고른 컬렉션 · 접힘 · 검색 · 스크롤, 선택 탭이면 그 탭 · 카드 2 펼침 · 그 줄 포커스. 라이브러리 대상이면 이동하지 않고 "라이브러리 변수예요 · 원본 파일에서 관리해요".
  - 쓰인 곳 머리 "{n}곳 · [모두 선택]"(최대 200 — v3 그대로, 목록 기준 안에서, **직접 연결만** — `FIND_VAR_USERS`에 그 변수 id 하나만 보낸다). "{n}곳"의 툴팁 "인스턴스 안쪽 포함". n = 0이면 "0곳"이고 [모두 선택]은 `aria-disabled`. 목록 기준이 없으면 "레이어를 선택하면 그 안에서 찾아요"(버튼 없음).
- 값 복사 단추는 두지 않는다(값 칸을 골라 ⌘C).
- 포커스 순서: [⧉ 이름 복사] → 이름 칸 → 모드마다 값 칸 · [▾] · [→] → CSS [⧉] → 쓰인 곳([모두 선택] · 레이어 단추들) → (확인 줄) → [닫기]/[취소] → [저장]. 라이브러리 상세: [⧉ 이름 복사] → CSS [⧉] → 쓰인 곳 → [닫기].

### 4.9 새 변수 · 복제 · 삭제

**새 변수** (변수 탭 ＋ › 새 변수)
- 팝업(상세와 같은 틀): 컬렉션(읽기, 지금 고른 컬렉션) · 이름 · 타입(색 · 숫자 · 글자 · 참거짓) · 모드별 값(값 ↔ 별칭, 고치기의 칸 · [▾] 그대로) · [취소] [만들기].
- 타입 기본값: 지금 보이는 첫 그룹의 첫 변수 타입. 그룹이 없으면 숫자.
- 로컬 컬렉션이 0개면 사용자 컬렉션 `Variables`를 새로 만들어 넣는다(플러그인 표시 없음 — 플러그인 자동 쓰기가 건드리지 않는 곳). 컬렉션 칸에 "Variables (새로 만듦)".
- **직접 만든 변수 지키기:** 새 변수 · 복제로 만든 변수에는 플러그인 데이터 `dsl.manual = 1`을 단다. 플러그인 컬렉션 안에 있어도 자동 쓰기가 덮어쓰거나 지우지 않는다 — 빼는 곳(이름이 같으면 덮어쓰거나 지우는 경로): `createTokens` · `prunePaletteColors` · 역할 매핑 `createSemanticAliases`의 `upsertVariable` · 다크 `themeApply`(manual Semantic 변수의 Dark 값을 다시 걸지 않고, 쓸 `dark/{이름}` Global이 manual 변수면 그 값을 덮어쓰지도, 다른 이름으로 새로 만들지도 않고 그 역할의 Dark 값을 지금대로 둔다 — 건너뜀으로 센다. 다시 돌려도 같은 결과라 변수가 늘지 않는다). `createUsageRoles`는 지금도 같은 이름이면 `-n`으로 새로 만들어 덮어쓰지 않는다(같은 이름 · 같은 값 재사용 판정에는 manual 변수도 들어간다).
  - `createTokens`가 같은 이름의 manual 변수를 만나면: 값이 같으면 그 변수를 그 토큰의 Global로 쓴다(`globalOf`가 가리킴 — 지금의 재사용과 같음). 값이 다르면 그 토큰과 그 토큰을 가리킬 역할을 만들지 않는다. 응답 `CREATE_RESULT`에 `skippedManual`(수)을 더하고 결과 문구 끝에 " · 직접 만든 변수라 건너뜀 {n}".
  - 역할 매핑 · 다크가 manual 변수를 건너뛰면 결과의 건너뜀 수에 더한다.
  - 사용자가 상세에서 고치는 것은 그대로 된다.
- 이름은 비워 둔다. 이름 검사 · 값 검사는 고치기와 같다(새 변수용 가상 self로 `nameError` · `aliasCandidates`를 부른다). 기본 모드 값은 필수, 다른 모드는 비우면 기본 모드 값.
- 용도(scopes)는 **최종 이름**의 종류(§4.6 판정 1~3)로: 간격 GAP, 반경 CORNER_RADIUS, 크기 WIDTH_HEIGHT, 선 두께 STROKE_FLOAT, 투명도 OPACITY, 색 ALL_FILLS · STROKE_COLOR · EFFECT_COLOR, 글자는 그 속성(FONT_SIZE · LINE_HEIGHT · LETTER_SPACING · FONT_FAMILY). 기타 · 참거짓은 용도를 설정하지 않는다(피그마 기본값).
- 만든 뒤 팝업을 닫고 변수 표를 다시 읽어, 그 그룹을 펼치고 새 변수로 포커스 · 스크롤. ⌘Z 한 번. 사용자 컬렉션에도 된다(v3 §2.13 13.1 — 사용자가 직접 하는 일).
- 메시지 `CREATE_VARIABLE{reqId, collectionId?, name, type, values, scopes?}` → `VARIABLE_CREATED{reqId, id}` / `ERROR{op, reqId}`(이름 거절은 팝업 오류 줄).

**복제** (우클릭 › 복제)
- 같은 컬렉션에: 모든 모드 값(별칭 포함) · 용도 · 설명 · 게시 숨김 · 코드 문법(codeSyntax)을 복사. 플러그인 표시(`dsl.autoRole`)는 복사하지 않고 `dsl.manual`을 단다.
- 이름 `{이름}-copy`, 있으면 `-copy-2` · `-copy-3`(겹침 판단은 `nameError`와 같게 대소문자까지 같을 때).
- 새 변수는 피그마가 컬렉션 끝에 만든다 — 목록은 피그마 순서라 그룹 끝에 보인다(받아들임). 만든 뒤 상세를 열고 이름 칸에 포커스.
- 메시지 `DUPLICATE_VARIABLE{reqId, id}` → `VARIABLE_DUPLICATED{reqId, newId}` / `ERROR{op, reqId}`.

**새 변수 · 복제의 무료 개수 제한** — 무료는 사용자가 직접 만든 수(새 변수 + 복제)만 센다. 만들기 · 연결이 자동으로 만드는 Global · 역할은 세지 않는다(유료 [변수 만들기], 무료 연결의 역할 만들기 — v3 그대로). 한도에 닿으면 ＋ › 새 변수 · 복제가 잠금(사유 "무료로는 {n}개까지 만들 수 있어요 · [라이선스 →]"). 숫자 · 기준은 §9.

**삭제** (우클릭 › 삭제, 무료)
- 확인 팝업(늘): 제목 "{이름} 변수를 지울까요?". 이 변수를 가리키는 로컬 변수가 있으면 "이 변수를 가리키는 변수 {m}개는 '삭제된 변수'를 가리키게 돼요". 늘 "연결된 레이어 · 스타일은 '삭제된 변수'가 돼요". [취소] [삭제](`--danger`). 처음 포커스 [취소], Esc = 취소. 라이브러리 게시 경고는 넣지 않는다.
- 지운 뒤 다시 읽고, 포커스는 같은 그룹의 다음 항목(알약 · 동그라미 · 줄), 없으면 이전, 그것도 없으면 그룹 머리.
- ⌘Z로 되돌린다(§2.3-3). 사용자 컬렉션도 지울 수 있다.
- 메시지 `DELETE_VARIABLE{reqId, id}` → `VARIABLE_DELETED{reqId, id}` / `ERROR{op, reqId}`. {m}은 UI가 변수 표에서 센다(모든 모드의 별칭 대상).

### 4.10 ⚙ 설정

## 7. 다시 읽기 (v3 §4.1에서 바뀌는 점)

| 언제 | 읽는 것 |
|---|---|
| 목록 기준이 바뀜(사용자의 캔버스 선택 · [기준 바꾸기]) | 250ms 뒤 선택 탭: 찾기(preview) + 텍스트 스타일 미리보기 + 쓰는 변수 + 삭제된 변수(300개 규칙). 지금 하위 화면이 만들기 · 이름 정리면 그 미리보기도. 변수 탭 · 설정에 있으면 미뤘다가 선택 탭에 들어올 때 |
| 선택 탭에 들어옴 | 기준이 바뀌었거나 플러그인 작업 뒤면 위와 같이 |
| 변수 탭에 들어옴 | 변수 표(조용히) |
| 창에 다시 들어옴(v3 400ms · 2초 규칙) | 준비 상태 + 지금 탭의 표: 변수 탭이면 변수 표, 선택 탭이면 찾기 · 텍스트 스타일 미리보기 · 쓰는 변수 · 삭제된 변수, 하위 화면이 만들기 · 이름 정리면 그 미리보기도(조용히, 300개 규칙, 끈 스위치 · 체크 이어받음). 피그마 오른쪽 패널에서 바꾼 연결이 반영된다(v3 흐름 D) |
| 플러그인 작업 직후(연결 · 클릭 연결 · 삭제된 변수 연결 풀기 · 만들기 · 이름 정리 · 컴포넌트 · 새 변수 · 복제 · 삭제 · 고치기 · 다크 · 텍스트 스타일) | 준비 상태(`GET_PREREQ`) + 변수 표 + 선택 탭 데이터(선택 탭에 있으면 바로, 아니면 들어올 때) |

- [↻] 버튼은 없다. 큰 선택의 [읽기]만 사용자가 누른다.
- **찾기는 한 번에 하나:** 앞 찾기가 진행 중일 때 새 요청이 오면 앞 것을 취소하고, 그것이 끝난 뒤 마지막 요청 하나만 돌린다(사이 요청은 버림). 버리는 판단은 찾기 요청끼리만 한다 — 연결이 끼어들어도 UI가 보낸 마지막 찾기는 버리지 않아 응답이 늘 온다. 코드 쪽도 겹쳐 돌지 않게 막는다 — `bind.ts liveVarIds` · `code.ts bindCancel`이 모듈 전역이라서다(B.1).
- 쓰기 작업(연결 · 만들기 실행 · 클릭 연결 등)이 진행 중이면 자동 찾기 · 자동 추출 · 자동 미리보기를 미루고, 끝난 뒤 1번 한다(v3 "진행 테두리 대상 작업 중에는 미룬다", 마법사 중 자동 요청 안 함).
- 찾기(`APPLY_RESULT`)와 쓰는 변수(`USAGE_RESULT`)는 따로 오고, 온 카드부터 그린다(§4.1 상태 4).
